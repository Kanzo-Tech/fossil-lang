# @fossil-lang/prompt

The Fossil surface language as a system prompt, for a model that writes
programs.

```ts
import { FOSSIL_PROMPT } from '@fossil-lang/prompt';

const system = `${FOSSIL_PROMPT}\n\n${hostRules}`;
```

`FOSSIL_PROMPT` is the language and nothing else. What a host appends is its
own: which connections exist and how a model should name them (`"@name/path"`
inside a string reaches a connection the host defines), what the model is
given, and what shape the answer takes.

## Why a package, and why this one

It is a string with **no dependencies**. The call that uses it is usually a
server-side LLM route, and putting it in `@fossil-lang/wasm` would make that
route import a wasm module to read a constant. It is not in `@fossil-lang/types`
either: that package is the host contract, and a prompt is not one.

## Why it cannot drift

A host used to keep this prose itself, written against one release and edited
by hand; by the time it moved here it named two namespaces, `validate` and
`anon`, that no catalogue row declares. Every part is now held to something:

| part | held to | by |
|---|---|---|
| `LIBRARY`, `NAMES` — every `io.` reader and stdlib function with its signature | `catalogue.bnf` | generated by `cargo xtask catalogue`; `--check` fails when stale |
| `EXAMPLE` | `apps/docs/programs/shop/shop.fossil`, a conformance program | `tests/prompt.test.ts` compares it verbatim |
| every other fossil line in the prose | the conformance programs under `apps/docs/programs/` | the test fails on a line no program writes |
| `FORBIDDEN` — the forms that are gone | the real checker | each carries a program the wasm checker must refuse, beside a control that checks clean |
| the rest of the prose | `grammar.bnf` | `GRAMMAR_DIGEST`: any change to the grammar turns the test red until a person re-reads `src/surface.ts` and moves the digest |

The last row is a review gate rather than a derivation, on purpose: the grammar
is ahead of the parser and changes in prose as often as in productions, so no
extraction can tell which change matters to a model.
