Every decision has a shadow: the thing that was not done. A shadow recorded without what would
reverse it is a graveyard, so every row here carries four fields, and an entry that cannot state the
last one does not go on the page. That is the admission rule, and it is what stops this becoming a
list of things somebody once disliked.

This is the one page here you are expected to search rather than read. Where the evidence is a
paragraph rather than a number it sits in an accordion under the table, titled with its row.

## The algebra and the checker

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Rewriting the operator tree before it is lowered — filters pushed down, redundant projections eliminated, constants folded | It is what a compiler middle-end is *for*, and each rule is individually correct | It optimises twice, in the layer with less information: the engine underneath sees the whole plan plus statistics the middle does not have | A transformation that depends on something only the type layer knows and the engine cannot recover from the SQL it is handed |
| Admitting a computed join key — `on = str.lower(A.k) == B.k` | Every SQL engine plans one, and refusing it sends the author back to the source file to prepare a column | There is nowhere in the language to compute it first: `map` takes no function (`grammar.bnf` lists `LambdaExpr` under what is not in the MVP) and there is no `extend`. So admitting it means admitting an arbitrary expression on each side, which is the theta join wearing an `==` — and the engine plans that as a filter over the product of the two relations | A verb that computes a column. With one, the key is prepared upstream and the equality stays between two columns: the rule does not widen at all |
| Refusing a chained join in the checker, so that `check` never accepts what `run` cannot plan | The checker would stop promising something the engine breaks a stage later | `Both.join(Third, on = Right.k == Third.k)` is a join by the language's own rule. The engine refused it because `fossil_mir::JoinSide` carried ONE relation name — the pipeline's, after the first join — where the checker's scope carries every binding a body may address. And that name was not a narrower truth but a false one: a join re-qualifies neither side, so `Both` qualified no column of the relation, and the refusal demanded the one spelling that could not resolve while refusing the only one that could. Writing that into the checker would have turned an inverted engine rule into a rule of the language | Nothing, and the other side moved: `relations` is a set and the two layers admit the same conditions |
| `distinct(on = …)` — `DISTINCT ON`, keeping one row per group of key columns | It is what the catalogue row already declared, `DuckDB` and DataFusion both have it, and it is the only form of the verb that is more than a de-duplicate | Which row survives a group is arbitrary without an `ORDER BY`, and `sort` has no lowering to write one with. Every conformance artefact is compared byte for byte and the graph is written from these rows, so the same program would pass and fail across two runs of itself | `sort`, lowered. The order is the whole of what is missing: with it the pick stops being arbitrary and the row can be declared |
| Width subtyping on records | What most structural type systems do, and projections compose without ceremony | None was needed: no program required it, and the invariant rule is simpler to explain and to check. A decision to stay narrow, not a rejected argument | Partial-row projections flowing through the standard library, where a caller legitimately holds a wider row than the signature asks for |

## Type providers

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Declaring the source's schema outside the program — a flag, an attached file, a host setting | A schema feels operational, and one program can be pointed at several environments | The documented damage in that family is liveness, not location, and the systems that moved the declaration out did not come out better: one needs a live database at build time and fixes it by committing an anchor, another keeps a generated schema file in the repository and pays for two sources of truth. Decisive on its own: a program whose meaning changes with an external flag is not self-contained | A host that must compile one unmodified program against two schema revisions and legitimately cannot express that as two programs |
| Disambiguating a derived name automatically — a numeric suffix, a singular/plural heuristic | The build never breaks on a naming accident | The most mature implementation of derived names published the criterion that condemns it: avoid anything that lets a small change in the sample cause a large change in the provided types. Its own collision scheme was a numeric suffix, so a member's name depended on which other members existed; its singulariser produced `Purchasis` and `Sourcis`; and a minor version bump renamed members and broke a production application | A real vocabulary where collisions are the norm rather than the exception — at which point the short name has stopped being the name, and the scheme needs rethinking rather than patching |
| Choosing the row that reads a document by the document's extension — a bare `schema = "x.shex"`, or `io.` inferred | A path already says what it is, and the program writes one word less | `.ttl` is claimed by `io.rdf` (rows) and `io.shacl` (types), so the answer would depend on which question was asked and on table order; dispatch by name has no question to ask. One rule — where there is a document, there is a row that names it — and a bare string is a diagnostic, not a fallback (`crates/fossil-base/src/providers.rs, one_extension_two_rows_and_the_name_is_the_only_thing_that_separates_them`) | A catalogue in which no two rows claim one extension, and a reason to keep it that way |
| Taking every shape document from a `type { … }` binding and dropping `schema =` | One way to name a document instead of two | They are not the same document: `schema =` shapes the INPUT rows and `type { … }` is the OUTPUT contract, and nothing says a program's two ends read one file | A corpus of real programs in which the input and output documents are always the same file |
| Resolving an unknown namespace prefix over the network at compile time | The public registry exists for exactly that, and it removes a declaration | That registry served an expired certificate for seven months while every IRI it abbreviates continued to answer. IRIs are durable; the abbreviation layer over them rots, and a compile that depends on it inherits its uptime | Nothing, at compile time. As an editor suggestion — offered, ignorable, never load-bearing — it is a different thing and was never rejected |

## Inference from shapes

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Making SHACL the language the contract is written in | SHACL is a W3C Recommendation with an active working group; ShEx's standardisation moved elsewhere. On standards-body health alone it is the safer bet | The axis is expressiveness, not prestige: the available SHACL path carries neither the one-versus-one-or-more distinction nor closure's three states — see below | Three conditions, none of them an argument — see below |
| Deriving the shape document from the mapping | It is free, it never disagrees with the mapping, and it produces a document where there was none | It never disagrees *because it was computed from the mapping*: an after-the-fact description of whatever the mapping happened to do, typos included. A contract that cannot contradict you is not checking anything | A workflow where nobody has a shape and the produced graph really is the specification — where the generated document is documentation rather than a contract, and is labelled as such |
| Binding an imported document's shapes by position — the Nth name to the Nth declared shape | The local name is free, so two documents that both declare `Person` coexist, and nothing has to match | Reordering a document rebinds every program that reads it, silently ([Inference from shapes](/docs/design/shapes)); and with declared types binding by name, the language would have two rules for one idea | A document imported as it is whose shapes' local names collide often enough that declaring the type each time costs more than the positional rule did |
| Putting shapes in the order the document declares them | It is the order an author sees, a person can predict it, and the ShEx parser and Turtle's first appearance both keep it | A shapes graph is an RDF graph, and an RDF graph is a set: no standard gives the order a meaning, so a rule that read it would make the node types of the output, and the shapes an import is told about, depend on how a file was laid out. ([The order of shapes](/docs/design/shapes#the-order-of-shapes)) | A standard giving node shapes an order that validation or construction may rely on |
| `@rename(T, "iri" as name)` to repair two predicates whose last segments coincide | The vocabulary stays somebody else's, and the repair is one line in the program | It is a second way to name a property, spelled differently from every other, and a declared type makes it unnecessary: the field's name is what the program writes and the IRI sits beside it ([Types declared in the program](/docs/design/declared)) | A document that must be imported unchanged, with collisions, where declaring the type is not an option |
| A base IRI the compiler falls back to when a declared type or field has no `@iri` | A type of ten fields is ten lines shorter, and a host could supply the base | A name nobody wrote becomes an IRI that ends up in a graph, and the grammar has no `PrefixDecl` for it to expand through. A host that proposes types computes the IRIs and writes them | Programs where the `@iri` lines are most of the text — then an explicit `@base` on the type, never an implicit one |
| Declaring a type as `type A = { … }`, an F# record's punctuation | It is F#'s, and F# is this language's reference | `=` assigns a value and a declaration assigns nothing — the rule the grammar already states for `:=` — and every other block in Fossil is opened by indentation, not braces | A declaration that must nest a field's type inline, which indentation alone would make ambiguous |
| ShEx's `?`, `*` and `+` beside a field's type | The four cardinalities of the document a type used to come from, with tokens the grammar already has | The language already has types for them — `Option<T>` and `Seq<T>` are what the checker prints — and a marker beside a type is a second notation for the same thing. `+` is `Seq<T, 1>` and `{n,m}` is `Seq<T, n, m>` | A count two bounds cannot say |
| Checking a count against the candidate keys a profile measured, at compile time | The profile already knows whether a column is unique, so `sh:maxCount 1` could be decided before a run | The keys are facts about what the data holds, not about what the source is: the editor asks a source for `Options::TYPES` alone and has none, so one program would compile one way in the editor and another in the run. The checker reads the program and its documents and nothing else ([Types declared in the program](/docs/design/declared#what-a-type-does-not-say-is-an-assert)); the keys stay an optimisation, tied to the etag they were measured at | A key that is part of what a source IS — a declared primary key a source format carries — read as an input like its columns |
| `NonEmpty<T>`, a fourth constructor for ShEx's `+` | The one count `Option` and `Seq` could not say | `Seq<T, 1>` says it, and a constructor for one bound is a second spelling of the bounds | A count two bounds cannot say |
| `closed` on a shape — `ShEx` `CLOSED`, SHACL `sh:closed` — read by the checker to decide whether an unlisted predicate is an error | Both languages state it, and dropping it loses what the document says | A property key is a bare name resolved against the shape's predicates, so a key no predicate declares is already an error, with a did-you-mean, for every shape. Openness cannot be expressed from the writing side, which is the only side a mapping has, and a flag that can only select the behaviour that already happens is not a flag (`crates/fossil-graph-schema/src/shapes.rs`) | A reading side — a validator of a graph against its document — where a predicate the mapping never wrote can arrive |
| `&T` or another sugar for `Ref<T>` | Shorter, and familiar from languages with references | `&` was a token once, the intersection of two shapes, and went; a sugar is a second spelling of one type | A measurement that `Ref<…>` is the bulk of a real program's text |
| A mapping that adds only edges to a type — `Friends : Person.knows from KnowsRow` | `docs/programs/relationship` writes `isLocatedIn` three times to add two edges | Syntax ahead of the programs that need it: two mappings of one type already work, and the repetition is the price of each mapping reading whole | A real program that repeats the same properties across more than two mappings of one type |
| `into()`, choosing a conversion by the field's type, as the language's spelling | The bidirectional checker knows the target, so `Row.year.into()` needs no `parse.integer` | It would be a second way to convert beside `parse.*`. `From`/`Into` belong in the implementation, onto rudof's RDF types, not in the surface | A conversion `parse.*` cannot name, or a family of them that grows faster than the catalogue |

<Accordions>
<Accordion title="Making SHACL the language the contract is written in">
A contract that does not distinguish **one** from **one or more** is not the contract being asked
for, and closure has three states rather than two. The available SHACL path could carry neither,
while the ShEx path already is a contract end to end: it types the input side, it is read by the
checker, and the same document describes the output.

What brings it back, in three:

1. A client arriving with a shape document that already exists and that nobody is going to rewrite.
2. SHACL reaching Recommendation with the triple-term node kind in it **at the same time as** a real
   RDF 1.2 producer in the graph — both, because the node kind without the producer checks nothing.
3. A shape that needs a disjunction, where the current advice to split it into several mappings is
   going to sound absurd the day the shape was written by somebody else.
</Accordion>
</Accordions>

## The standard library

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Growing the catalogue ahead of the programs | Cheaper to design the general case once than to generalise later | One error repeated at nine scales in this project's own history: the abstraction was written before the second implementation existed — extension points with one implementation and no dispatch, operators defined and mostly unreachable, catalogue entries no program could call. The aggravating factor is that it was documented as finished, so intent stopped being distinguishable from state | The second implementation. That is the whole rule, and it is a condition rather than a judgement |
| Plugins, as wasm modules or dynamic libraries | The standard answer to extensibility, and it scales past the maintainers | Measured in three projects that did it: one editor maintains ten simultaneous ABI versions; one database maintains a signed matrix of six platforms per release; one compiler paid for openness with `Unknown` variants in every enum of its syntax tree, permanently. An in-tree registration list delivers the entire benefit at zero ABI cost | A consumer who genuinely cannot merge into the tree. It is a door that opens later, and opening it later costs nothing that opening it now would have saved |
| A uniform `HirSourceOp { op, args }` instead of typed variants | Twelve declared verbs against six constructible variants is an asymmetry, and the uniform shape makes `lower_source_stage` end without a `match` at all | It trades a compile-time guarantee for a runtime unwrap: `args[0]` expecting a predicate is checked by nobody, where `Where(HirExpr)` cannot hold a column list (`crates/fossil-hir/src/lower.rs, HirSourceOp`). It is the fork rustc and rust-analyzer took opposite ways over the same table — rustc's `[Option<DefId>; N]` costs it a discriminant coupling, a `from_u32` its own comment calls *"clumsy"* and a `panic!`-enforced bijection, where rust-analyzer's one typed field per row has none of the three. The surviving `match` is construction rather than dispatch: six arms, exhaustive | Enough lowered verbs that the typed variants stop being writable by hand — the constructible set overtaking the declared one, which is the opposite of today's six declared and not lowered |
| `seq.map`, `flatten`, `take`, `drop`, `sort` and `count` in the catalogue, with no operator in `fossil-mir` to run them | They are what a reader expects of a relation, and the checker already typed them | The checker accepted a program no engine could run: the verb typed, and the run refused it as `pipeline/unimplemented-verb`. No conformance program used one | Each one, when it has a variant in `fossil-mir` and a test that runs it |
| A third lowering kind naming a native function registered on the engine's connection — a Rust UDF | What SQL cannot say — an HMAC, Unicode normalisation beyond NFC — could still be a catalogue row | The language runs entirely in the browser, on an engine no native function reaches. Of the eight rows that used one, six are templates whose delta against the native function was measured, and two cannot be done honestly without native code, so they are not in the language (`crates/fossil-hir/src/stdlib/tests.rs, the_deleted_names_are_gone`) | A host that can register native code with its engine and a program that needs a function no template expresses |
| `str.concat(a, b)` beside interpolation | A function is easier to generate than a template | Both lowered to the same `Expr::Concat`: two spellings of one idea | A concatenation interpolation cannot write |
| `parse.decimal` beside `parse.float` | `xsd:decimal` is the datatype a shape names | It returned `Float`, as `parse.float` does: the lattice has no decimal, so the name promised a precision it did not keep | A `Decimal` type that keeps its precision through to the graph |

## The surface

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Borrowing the comprehension binder for the source binding | Instantly familiar, and it reads as "drawn from" | In the languages it would be borrowed from, the specification defines the left side as an element and the right side as the collection. Here the left side names the relation, so the borrowed glyph would say the opposite of what it means. It already means assignment in one widely-read language and channel receive in another, no language was found in which it means "produced once per element of", and it flows right-to-left in a program whose pipelines flow the other way | A form where the left-hand side really does denote one element rather than the relation — an iteration construct, if one is ever needed |
| The anonymous row: drop the receiver's name and write bare `.field` against an implicit current row | The shortest possible spelling of the most common expression in the language, and several query languages start there | A table with no counterexamples, and a failure mode that is silent and triggered by data rather than by code — see below | A source model with genuine hierarchy to descend, where the context item earns its cost. An implicit context item optimises for hierarchical navigation rather than for joins, and tabular sources are all joins |
| Renaming silently when a join collides — suffix the shared column, as the mainstream data frame libraries do | The join always succeeds and nobody has to think about it | The same failure mode as the anonymous row — triggered by the data, invisible in the code — and the libraries that do it by default only raise when the suffixes are turned off by hand | The other defensible option was never rejected on merit: flatten and require qualification, which is what SQL does. It becomes the answer the day a row carrying two `id` columns is what readers expect to see rather than something to be protected from |
| Letting a program omit its shape document and checking only the source side | The gentler on-ramp, and for a while it was the rule — a program with no shape was explicitly not an error | It stopped being coherent the moment a property key became a bare name. A bare key takes its name from a predicate a shape declares, so with no shape there is no name for a property to have: `TypeckOutput.predicates` is empty (`crates/fossil-hir/src/check.rs, TypeckOutput`), every property fails to lower, and the program reports success having written nothing | The second source of predicate names now exists — [types declared in the program](/docs/design/declared) — and it did not bring this back: every type is declared or imported, so a property still has a name. What would is a graph with no types at all, which `fossil/1` has no place for |
| The outer join, and the rest of the variants | The ordinary set, and their absence looks like an omission | An outer join fabricates nulls, and a graph whose contract asserts that a property is present is a graph into which a fabricated null must not be written | Its nullability story, and it arrives with one or it does not arrive: a rule that lets a fabricated null land only where `Occurs` does not demand one or more (`crates/fossil-hir/src/check.rs, check_required_properties`), so the graph never asserts a property it invented |
| A backtick-quoted member, ``Row.`Person.id` ``, for a column whose header is not an identifier | Kotlin, Scala, Swift, Spark SQL, MySQL and BigQuery all spell a delimited identifier so, and it cannot be mistaken for a value | The backtick was a second spelling of the string and is retired (`grammar.bnf`, the TEMPLATE tombstone); bringing the byte back for a third meaning costs a token and a lexer rule, where `"…"` already means «the text between the quotes», which is what a delimited identifier is. The SQL standard, `DataFusion` and `DuckDB` — the engines under fossil — write `t."Person.id"`. `Row."Person.id"` it is (`grammar.bnf`, `Member`) | A string literal acquiring a meaning after a dot other than «this name» — at which point the two readings would compete and the member needs a delimiter of its own |
| Sanitising a header into an identifier — `Person.id` becomes `Person_id` — so no quoting is needed | Every column is reachable with the bare spelling, and the program never shows the data's punctuation | A name nobody wrote, minted by the compiler: two headers that sanitise alike (`Person.id`, `Person_id`) need a tie-break, and the tie-break is the numeric-suffix scheme FSharp.Data paid for (see [the naming rule](/docs/design/type-providers)). The one suffix fossil keeps is the data's own duplicate (`Person.id\|Person.id` → `Person.id_1`), named by `DuckDB`'s rule because `DuckDB` describes the source | A source format whose column names cannot be written in a string at all |
| Resolving a relative reference against the working directory, or falling back to it when the file is not beside the program | A program run from where its data is just works | A program's meaning would depend on where it was invoked from: `check` and a run could disagree about where one file is, and a missing file would report a path the program never named. The program's directory wins, and the working directory is not consulted at all (`crates/fossil-base/src/location.rs, a_missing_file_resolves_where_the_program_said_it_would`) | A host whose programs have no location of their own and whose data is addressed from where the user stands — a REPL |
| Accepting both spellings of an identifier, `Row.name` and `Row."name"` | SQL does, and a generator can quote everything without asking | Two spellings of one name, and SQL keeps both only because they differ in case-folding, which fossil does not do. The parser refuses the quoted form of an identifier and names the bare one; every suggestion and completion prints the one spelling (`crates/fossil-syntax/src/name.rs, spell`) | Case-folding, or any other rule under which the two spellings would stop meaning the same name |
| The RDF 1.2 triple term — `<< s p o >>` as a value, with a reifier as an ordinary mapping | The standards-track answer to annotating a statement, and the graph already writes the edge row a triple term would have to name | Nothing in RDF 1.2 is a Recommendation: Concepts and Semantics are Candidate Recommendations, every concrete syntax is still a Working Draft, Turtle 1.2 in its fourth. The surface did not fail to arrive, it left — `<<` is not a token and `grammar.bnf` carries the retired rule's tombstone rather than a pending one. `rdfs:Proposition` appears nowhere under `crates/`, and the one place a triple term is handled reduces it to its surface form because it has no identity to key a row by (`crates/fossil-exec/src/rdf.rs, term_value`). That the Turtle parser accepts one on the way in was never decided either: `oxttl`'s `rdf-12` arrived by feature unification, and the Turtle parser is now `rudof_rdf`'s, which declares it itself; the two RDF 1.2 tests in `crates/fossil-exec/src/rdf.rs` fail at parse time if it stops, and a literal carrying a base direction is refused at the pivot rather than flattened into text a host lays out backwards. Both are guards over what arrives; neither is a step towards a surface | Turtle 1.2 reaching Recommendation, and a program that wants to annotate an edge and cannot. The second half arrived first, on 2026-10-09: a timeline over Nobel prizes and LDBC's `knows` wanted a date on the relation. It is answered with RDF 1.1's own pattern — the relation as a vertex (the W3C's n-ary relations note, schema.org's `Role`) — because a shape has no way to declare a property of an edge until SHACL 1.2's reifier shapes are a Recommendation too. The design is [planned](/docs/design/later/edge-properties) |

**Retired, not rejected.** *A join whose two keys have different names* sat here with the criterion
*"the first real mapping whose two keys do not share a name — not an argument, a program somebody
wants to write and cannot."* It was met. The MIR carries the binding, so a column reference says
which side it is, and two differently-named keys plan as an ordinary equi-join
(`crates/fossil-exec/tests/pipeline.rs, a_join_whose_two_keys_are_named_differently_plans`). Measuring it also turned up what nobody had seen: under
the algebra as declared, two ordinary tables could not be joined **even with a qualified condition**,
because they share a primary-key column name and any shared name was an error — an unmeasured
consequence prohibiting the join of any two tables with primary keys.

<Accordions>
<Accordion title="The anonymous row">
Every system that started with an implicit receiver had to add a naming mechanism the moment two
rows were in scope — a context function, an explicit binding form, a variable binder, a pair of role
keywords, a marker annotation, named bindings replacing positional ones — and **not one went the
other way**.

Worse, the failure is silent and triggered by data rather than by code: a path degrades quietly when
the implicit receiver is shadowed, and one language's implicit-scope construct is documented as
having changed the meaning of surrounding code because a record *gained a field*. In a language
whose job is surviving schema drift, that is the worst available failure mode.
</Accordion>
</Accordions>

## Annotations and language-tagged strings

What a type, a field or a relation is called, and a string's language, are
[Annotations and language-tagged strings](/docs/design/labels). `core.lang(value, tag)` sat in the
standard library table above, waiting for «a graph column for a literal's language»; that page
decides the column, and the call is `str.lang`.

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Primitives named for their RDF datatype — `GYear`, `AnyUri`, `LangString`, and `Date`, `DateTime`, `Time` beside them | Each name says which datatype it writes, and a reader of ShEx or SHACL meets the word they already know | Three of the ten existed only because RDF has them, so a type system meant to be neutral named one of its outputs; four types for points in time had no relation the checker could use, and `AnyUri` was both an IRI node and an `xsd:anyURI` literal depending on the shape. The families say what a value is — a text with or without a language, a time at a precision, an identifier — and the datatype is the RDF border's table (`crates/fossil-graph-schema/src/xsd.rs`) | A second output format that needs a value type the families cannot parameterise, rather than a new parameter |
| A dedicated `@label("…")` attribute | The commonest annotation in one word, with no IRI to write | A label is one predicate among several a reader wants — `rdfs:label`, `skos:prefLabel`, `sh:name`, `rdfs:comment`, `dcterms:description` — and neither ShEx nor SHACL has a label field: ShEx 2.1 §5.9 has an annotation, a predicate and an object. An attribute per predicate grows the language with every vocabulary | A measurement over real programs that nearly every annotation is one predicate |
| Comments as annotations — ShExC's `//`, or a doc comment `///` | ShExC already spells an annotation `//`, and Rust lowers `///` to a `#[doc]` attribute | `//` is Fossil's COMMENT, discarded by the lexer, and the conformance programs' `// #region` markers are ordinary comments that would start to mean something. A doc comment would be a second spelling of `@annotation` with `rdfs:comment` | Descriptions becoming the bulk of the annotations programs write — then `///` as sugar for that one `@annotation`, as Rust's is for `#[doc]` |
| The predicate as the attribute's name — `@rdfs:label("…")` | It reads as Turtle does | `AT_ATTR` is `'@' IDENT`, which no CURIE or IRI lexes as, and the CURIE left the grammar with `PrefixDecl`; the attribute namespace would become every vocabulary's | The CURIE coming back as a whole, with a `PrefixDecl` |
| Expanding a predicate's CURIE through the RDFa Core Initial Context — `@annotation("rdfs:label", …)` | A shorter spelling; a W3C list of prefixes, so nothing is invented, and JSON-LD publishes the same list as a context | The context maps `schema:` to `http://schema.org/` and every program here writes `https://schema.org/`, so an expansion would mint a different IRI from the one meant; and `"rdfs:label"` is already a well-formed IRI with scheme `rdfs`, so the expansion would be a rule about strings that look like something else. It is refused naming the expansion instead | Programs where annotation predicates are most of the text — and then a `PrefixDecl`, explicit and in the program, never an implicit context |
| Keeping SHACL's `sh:name` and `sh:description` as themselves in the graph, rather than reading them as `rdfs:label` and `rdfs:comment` | It is what the document wrote, and the Shapes WG's ISSUE-112 invented `sh:name` precisely because `rdfs:label` on a property shape labels the *shape* by RDFS's own definition, not the property in its context — normalising undoes that resolution | Inside a graph the distinction has nothing to hold on to: an annotation sits on the column it labels and makes no triple about the predicate, so `rdfs:label` there already is the local name ISSUE-112 asked for, and the shape it would label is not in the graph. Keeping both words makes every reader carry the same preference list between two predicates for one thing | A consumer that reads the annotations back as a shapes graph — a SHACL engine, or the ShEx round trip carried to SHACL — where `rdfs:label` again means the shape's label. Then the document's predicate is kept and the one-word reading moves into the reader that wants it |
| Writing annotations into the mapping's triples, as triples about the class and predicate IRIs | A reader of RDF gets them with no fossil code | An annotation on a field is a *local* label; stated about the predicate IRI it becomes a global one — ISSUE-112 in the other direction. They are written as plain triples *about the IRIs* in `mapping.ttl` and make no triple of the data: the relation `rml::sql` computes is the data's meaning, not the schema's | A consumer that needs the shapes graph back as RDF — then a document of its own about the shapes, beside the data's |
| An IRI, or a typed literal, as an annotation's object in Fossil | ShExC admits both, and `rdfs:seeAlso` wants an IRI | Fossil writes an IRI as a string, so `"https://…"` as an object would be a literal or an IRI depending on nothing written; no program needs either | A program that needs `rdfs:seeAlso` or `skos:exactMatch` on a field — then the spelling is decided with it. | A tag written after an expression — `Row.name@en` | The literal's spelling, applied to a column | `@` after an expression would be a third reading of the sigil, `@en-US` would need the lexer to know it is after an expression, and a per-row tag (`rml:languageMap`) has no spelling in it at all | Nothing: `str.lang` covers both a constant and a column tag |
| A `String<Lang>` value in its vertex table, as two columns or a struct | No join for a single-valued label | Two columns need a name for the tag minted from the property's, which is the compiler naming what nobody wrote; a struct is SQL's `ROW` type, no more Core SQL than the array the property table was chosen over | A reader measuring the property table's join as its cost — then the struct, as one cell holding one term |
| `fossil/2` for a graph that has a language column, `fossil/1` unchanged for one that has none — Delta Lake's table features, a version raised only for the tables that use the feature | A reader that does not know `lang` would write an `rdf:langString` literal with no tag, which RDF 1.1 Concepts §3.3 forbids, and a version string is the one field a reader checks before reading Parquet | Every reader of a graph ships from the release that ships its writer, or is GraphAr's own, and the mapping is written beside the data, so the reader that would misread the column does not exist to be protected; a version string of fossil's own is a branch in every reader for a reader nobody runs | A reader outside the release train — a third party's, or a graph kept and read by a reader older than its writer — that must keep reading every graph; the rule is on [the graph](/docs/design/graph#one-format-changed-in-place) |
| RML's fallback for a per-row tag that is not valid — the literal written with no language | It is the standard's precedence rule, §6.5 | It writes an untagged string into a column whose datatype is `rdf:langString`, and the graph's `declared-term` guard holds every value to its declared term | A host that needs the graph written with bad rows counted and left out, the way a dropped edge is counted |

## Identity

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Identity as an argument to an attribute above the mapping | It is metadata, and attributes are where metadata goes | Seven languages, no exception: none admits a per-instance expression in an attribute argument, and one specification calls the restriction a deliberate syntactic device. The control experiment is the language that does evaluate expressions in attributes — the per-row form compiles, produces one frozen value for every row, and costs its documentation a paragraph warning about a mistake the other languages cannot express | The rule that decides it: if the attribute can be omitted it is forbidden, because omission implies a derived fallback; if it cannot be omitted it is not an attribute but syntax with brackets, and the spelling is then irrelevant. Make it mandatory in every declaration and this becomes a spelling question |
| Letting each mapping mint its own identity, so two mappings producing one type declare different templates | What every mapping language does, and the one federation system that checked it removed the check and published its reasons | The federation case does not transfer: its two keys are alternative ways to locate one entity rather than two identities, and its subgraphs deploy separately so nobody ever holds the whole set — the check here is available precisely because the topology is the opposite. The same property is silently assumed by the academic work, detected but wired only to an optimiser by the one engine that computes it, and guaranteed by construction in the one W3C mapping that derives identity from the table's key rather than from a free template | In order: (1) a legitimate case of disagreement — disjoint populations of one type with no common identity scheme, where one real instance demotes the error to a warning; (2) a topology where fossil composes mappings from independent authorities, at which point the federation argument becomes ours; (3) invertibility, since virtual access over a live source needs the inverse expression and one template per type is not enough for it |

## Streaming, memory and scale

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Distributing the writer across machines | The reflexive answer to "no ceiling" | One machine is not exhausted: the one writer runs in wasm32 under a 2 GiB budget ([three hosts](/docs/design/three-hosts#what-the-wasm-writer-holds-and-how-it-says-no)), and the two mechanisms that extend a single machine — a native host, and spill — are not built. Distributing first trades a measured problem for a larger unmeasured one | A graph that exhausts one machine's **disk** rather than its memory |
| Unifying the two execution engines | Two engines mean two SQL dialects, two configuration surfaces and two sets of behaviour to keep in step | The margin does not pay: the read path is a few views `attachGraph` creates and then the host's own SQL, and unifying means turning that into plan construction, adding a wasm build of several megabytes to a path that loads none, and losing the range-request file system that makes reading a graph over HTTP work at all | The read path no longer needing range requests over plain HTTP — which would be a different product |
| Preassigned `dense_id` ranges per partition, so the writer stops collecting every batch before it can number them | It removes the one `collect()` in the write path whose cost is proportional to N, and the imbalance looks affordable: fourteen hash partitions come out within 0.526% of each other at ten million, and a quantum sized to the largest leaves 35,200 holes — 0.35% of V | Three numbers, in order of how badly each hurts. That quantum is only knowable **after** the run; the one a writer can pick beforehand is source rows over partitions, and the dedup collapses 8.1 rows into one — 71,027,072 holes, **710% of V**. Compacting them back costs 9.6 s and 3.72 GiB against a whole write of 404.4 s and 20.72 GiB, so the exit that keeps the published convention is 2.4% of the wall clock and the exit that changes it is the expensive one. **And the premise is refuted**: level by level at ten million the sort is 13.72 GiB and the aggregate beneath it 13.85, so deleting the collect leaves ≈13.9 GiB — that term is the dedup, which no range scheme touches, and the `Vec` that escapes the pool is 1.64 GiB, not fourteen | A partitioning whose sizes are known before the run — a range partition on a key with published bounds rather than a hash — which makes the preassigned quantum exact and the holes zero. At that point it stops being a trade against [gaplessness](/docs/format/conventions/identity) and becomes a scheme with no downside, and the harnesses to price it again are `ac1801d4:crates/fossil-df/examples/dense_id_ranges.rs` and `ac1801d4:crates/fossil-layout/examples/compaction_pass.rs`. Since the layout pass went the executor numbers each type as one contiguous range as it lands (`crates/fossil-exec/src/lib.rs, prepend_dense_id`), and the collect is still the one that numbers |


## Privacy

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Privacy inside fossil — a read-time gate on the door, or a bound sealed at write time: a `policy :=` document in the program, k-anonymity derived and verified by the writer and declared in the manifest | A graph is files with no read path to put a control on, so write time looks like the only place a bound can be enforced, and a declared bound a recipient can re-derive is stronger than a promise | **At read time there is no chokepoint**: a recipient holds the Parquet, and the systems that genuinely gate reads — Snowflake's masking and row access policies, BigQuery's column ACLs and row-level security, Databricks' equivalent — all apply it inside the query planner, a position a file format does not have. **At write time it was removed whole on 2026-09-30** — the `fossil-policy` and `fossil-kanon` crates, the `policy :=` syntax and the manifest field — because only one of the two write hosts of the time enforced it: the browser never read the program's `policy :=`, so the same program sealed `privacy: undeclared` there. A bound one host enforces and another ignores is not a property of the program | For reads, a **served** graph: the operator keeps the files and the only access is through their engine — a different product. For writes, a bound the one write host enforces and `packages/corpus/guards/` re-derives from the bytes, so a recipient checks it rather than trusts it |

**A second writer** is not a rejection but a standing reversal condition, recorded because it flips a
decision rather than adjusting one. If anybody produces this graph without using this
implementation, the priority inverts: the specification becomes the contract and the implementation
becomes one implementation among several. One writer is what makes the library half safe; two
writers is what turned a widely-used columnar format into a reference implementation that became
normative by accident. And the clock runs one way — if the graph reaches third parties before the
arithmetic is published, the option is gone.

What the information files' relations carry and what the writer counts are [the graph's own facts](/docs/design/facts).

| The idea | Its attraction | The evidence against | What brings it back |

| The idea | Its attraction | The evidence against | What brings it back |

The only thing an interior node could contain that a leaf cannot is the crossing edge, and it is

### The camera

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Keeping the published tile-code anchor beside the footers — `codes.json`, two `u32` per tile, and a Z-order descent over them | It prunes tighter than a footer's box, because the box is the hull of an arc that snakes and the arc is what the vertices are on. Measured over the million-vertex bench graph, both ways at three windows: at 10% the footers open **17 tiles in 6 requests, 1,466 kB** and the anchor opens the **15 that hold a matching vertex, in 4 requests, 1,294 kB** — 1.13× over-read against 1.00×; at 2%, 7/5/602 kB against 4/4/344 kB; at 30%, 96/21/8,283 kB against 90/17/7,772 kB | **A 13% over-read is cheaper than a second index.** The two answer the SAME question — which tiles a rectangle touches — and the field `addressed: 'anchor' | 'footer'` was the admission that a reader had to be told which one answered. What the anchor cost was a document per graph, a request to fetch it, a parser, a guard, a code path, a fallback path for graphs written before it, and a second thing to keep true of every writer. The footers are already there, already guarded by `footer-is-the-index`, and cost nothing to keep correct because Parquet writes them | A read where the over-read is the difference between fitting a budget and not — **and that read arrived**: at a window of about 5,000 vertices under the Z-curve, the boxes opened 7 tiles at the median where 5 held a vertex, 1.4×, and it was what pushed a view with a 20,000-row budget onto a coarser rung. Two things are **not** reasons to revisit that row, and are recorded so they are not re-argued.

**`points` at 4.85× `marks` is not a renderer's problem.** The anchors come from
the playground's `src/tiles.ts` (deleted after `2fa5f22`) and from the `Slice` contract — real vertices at real coordinates, so
that an edge leaving the window has an honest far end. Dropping them gives 15,625 points and a
sparse cloud with holes rather than a cheaper version of the same picture. No engine changes that
number.

**Nor is the 3.29× tile ratio, and it is not residency's either.**
`@fossil-lang/draw`'s `residency.ts` (deleted after `2fa5f22`) existed and was wired, and the reads it would have avoided were issued from
inside DuckDB's Worker where this thread never sees them. Residency buys latency, not fetches — so
*swap after residency lands and re-measure* is the wrong option twice over: the re-measurement does
not move the column an engine choice operates on, and the licence is exactly as prohibitive then.

<Accordion title="Lifting `fossil-base`'s `test_support` feature into a crate of its own">
Cargo permits a dev-dependency cycle, and half of it works: an **integration** test in `tests/`
links the plain rlib, so it sees the same `fossil-base` the helper crate saw. A **unit** test does
not. `#[cfg(test)]` compiles a second `fossil-base`, and rustc says so exactly:

```text
note: there are multiple different versions of crate `base` in the dependency graph
   |
15 |     use crate::System;
   |         ------------- `System` imported here doesn't correspond to the right version of crate `base`
```

Measured 2026-08-26 on a two-crate spike outside the workspace, reduced to one trait and one impl.
It is not a quirk of the reduction: every `SourceFile`, `Provider`, `System` and Salsa input that
`test_support` hands out is a `fossil-base` type, so every one of them crosses that seam.

The bill, then: sixteen of `fossil-base`'s thirty-two unit tests move out of `src/` into `tests/`
and lose their module's private scope; `test_support`'s own three go with the module; 112 call sites
in 58 files across eight crates change import path; nine manifests change a dev-dependency line.

Against which `fossil-base` sheds 339 lines, one feature — and **no dependency**. Its two path
dependencies are both held by production code: `fossil-graph-schema` by `shape_documents.rs`,
`providers.rs` and `diagnostic.rs`, and `fossil-descriptors-input` by `system.rs` until it became `fossil_base::sources`. No arrow moves on the
architecture diagram either, because that page reads `[dependencies]` and this is a dev edge.

The rule being applied here indicts what a `base` decides **about a program**. The location decided
where a written path points, which is a decision about a program, so it left. `test_support` decides
nothing about one, and its own header already said so before this was measured: *"This is not
compiler logic … a format that exists nowhere else and that no program will ever be written in."*
It is a reference implementation of a seam `fossil-base` itself defines, behind a feature no shipped
binary carries.
</Accordion>
<Accordion title="Removing the incremental core from the batch path">
The borrowed 52% does not transfer, and measuring locally says why: that project is a library whose
entire work is compilation, so its percentage of compilation *is* its percentage of the process.
Here compilation is two thousandths of a command dominated by process start-up and opening a
database connection. The ceiling on the saving is under four percent of that two thousandths,
falling to under half a percent as the program grows — and the same measurement found the real cost,
quadratic behaviour in one lowering step, entirely unrelated.

Two structural blocks came with it: the memoised core is the type through which the whole internal
API passes, so replacing it is a rewrite of thousands of signatures; and the browser artifact
reaches it through the executor regardless of whether the database is built.

What would bring it back is a file with hundreds of mappings, or a check called in a loop inside a
long-lived process. The first is measured and points the wrong way. What is **not** measured is the
cost in bytes of the browser artifact, which would be a different argument from the one about time.
</Accordion>
<Accordion title="A subprocess as the embedding surface">
Measured on 2026-08-16: the product this surface was built for spawns no fossil binary anywhere, and
both of its images declare that they contain none — `run`, `refs`, `providers` and `check` all
execute in the browser. The verbs and their wire types outlived their only consumer, and while they
lived a second implementation of each grew beside them, which is how the serializer divergence got
in.

The subprocess is not wrong as a *transport*; it is wrong as the definition of what fossil offers.
</Accordion>
<Accordion title="A linked Rust type as the contract between fossil and a host">
The crate accumulates contracts that have nothing to do with each other — the run result, the
provider registry and the typed lineage arrived in one crate named for the first of them — and it
accumulates build machinery belonging to the consumer, which is how an optional schema-derive
feature whose own comment read "Host-only" came to live in a compiler crate.

Measured: of the three contracts, only the run result is referenced from the host's Rust at all; the
other two are consumed from TypeScript through the wasm package, so the linked crate carries two
contracts for a language that never links it. A linked type also pins the host to a tag — dropping
the feature means the host cannot bump past its pinned tag until it stops asking for it.
</Accordion>
