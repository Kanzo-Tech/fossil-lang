fossil has an incremental core so that [editing one mapping re-runs work for that mapping and not
for its neighbours](/docs/design/tooling-for-humans). That promise only holds if Salsa sees
everything a check reads. A fact read beside it — from a table the host fills, a map passed as an
argument, a second copy of a decode — is memoised with the answer and never invalidated, and the
editor shows a result for an input that is gone.

The rule is the one [ty](https://github.com/astral-sh/ruff/tree/main/crates/ruff_db),
[rust-analyzer](https://github.com/rust-lang/rust-analyzer/tree/master/crates/base-db) and
[Cairo](https://github.com/starkware-libs/cairo/tree/main/crates/cairo-lang-filesystem) follow: **the
host writes inputs, and everything else is a query.**

## What a host writes

Three things change a compile's answer, and each is a Salsa input.

- **The text of a file** — the program, and every shape document it names
  (`crates/fossil-base/src/files.rs, SourceFile`).
- **Which files exist** — the registry a path resolves through, so that a document registered after
  a check that missed it re-runs that check (`crates/fossil-base/src/files.rs, FileRegistry`).
- **What each source is** — the columns a host's profile found for it, or the problem that stopped
  the host from finding any (`crates/fossil-base/src/sources.rs, Described`).

The third was not an input. The descriptors lived in a `Mutex<HashMap>` on the host's `System`, read
from inside the checker with no dependency, so a source described *after* the first check left that
check memoised against no columns: the squiggles of an open row, for a file whose columns the host had
since read. The sources whose description failed lived in a second map on the wasm workspace, read
beside the queries. Both are one input now, keyed by the source's location as the program writes it.

Its granularity is the whole map, for the reason the file registry's is: a check that asked for a
source nobody had described yet must re-run when one is, and a per-key input cannot express a miss.
A host describes sources after a profile, not per keystroke, so invalidating every reader of the map
costs a re-check of a program whose sources just changed.

**What would reverse it:** a host that describes sources as often as it edits text. Then one input per
source, with the registry holding only which keys exist.

## The run reads what the check read

The executor decoded a program's output document with a copy of the checker's decode: the same
provider lookup, the same extension check, the same registry key, read off a static provider table
rather than the installed one, and run again on every execute. Two copies of a decode are two places
a run and a check can disagree about the document. It calls the checker's now
(`crates/fossil-hir/src/shapes.rs, decoded_document`), whose read of the document's text is tracked.

It reads the third input too: a run is given the profile the editor was given, so it checks a
program against the columns the editor checked it against — [the last section](#one-database-and-the-run-checks-what-the-editor-checked)
says how.

## Diagnostics are returned by value

A query that can find a mistake returns what it found in its output, as ty and rust-analyzer do.
Diagnostics were a Salsa accumulator, and an accumulator can only be pushed from inside a query —
which is why the tests carried tracked wrapper functions whose only job was to be a query, and why a
helper that found a mistake needed a database to report it to.

- **A query that can find a mistake carries its diagnostics in its output** — the parse, the
  lowering, a mapping's body, the check of one mapping, the identity check, the lowering to MIR. A
  check that refuses still returns an output, with the refusal among its diagnostics and the poison
  beside it (`crates/fossil-hir/src/check.rs, TypeckOutput`).
- **A helper reports into a sink it is handed**, not into the database, and the sink is what mints the
  `ErrorGuaranteed` a poisoned result carries (`crates/fossil-base/src/error.rs, Diagnostics`). The
  rule that a refusal cannot be silent stays a type: the only way to get the token is to push a
  diagnostic.
- **The program's diagnostics are the union of those outputs**, collected by one function every host
  calls (`crates/fossil-mir/src/diagnostics.rs, program_diagnostics`).
- **A test builds a database with what it needs** — files, documents, described sources — and calls
  the real query, or hands a helper a sink of its own. No tracked function exists to be a test's
  frame.

**What would reverse it:** a diagnostic whose producer is not the query whose output carries it —
reported from deep inside a query on behalf of another. An accumulator is the tool for that, and
fossil has no such case: every diagnostic belongs to the query that found it.

## One database, and the run checks what the editor checked

The editor's workspace and the executor build the same database type, `FossilDb`, and write the same
inputs into it. Nothing else is shared state:

- **The connections are an input**, beside the files and the sources
  (`crates/fossil-base/src/connections.rs, Connections`). A location expands through them, so a
  document the program names, the list of what it reads and the run's routing read the connections
  from the database rather than from a map handed beside it — and changing a connection re-runs the
  queries that read them.
- **The run is given the profile the editor was given.** `run` takes the same answer of the host's
  profile `describe` answered, and writes it into the run's database before the check. A
  run then refuses exactly what the editor refused, against the same columns.
- **The executor stays its own wasm module**, so the editor does not load DataFusion. It compiles the
  same queries over the same database type, so the two cannot answer differently about one program
  and one set of inputs.

**What would reverse it:** a host that needs a run and an edit to disagree on purpose — a run against
inputs the editor must not see. None does: the run's inputs are the program, its documents, its
connections and its sources, which are the editor's.

## The crates, as the references cut them

ty, rust-analyzer and Cairo put the Salsa substrate in one small crate at the bottom — the database,
its inputs, the file abstraction — the parser in a crate of its own, the semantic analysis in one or
a few, the editor functions in one with no protocol in it, and each transport in a thin crate over
those. fossil's crates are cut that way, and a crate that is none of those folds into the one whose
subject it is. Seven are modules of those crates now:

| module | because |
| --- | --- |
| `fossil_base::location` | where a written reference points is the file abstraction, which ty keeps in `ruff_db` beside the inputs |
| `fossil_base::sources` | the columns a host found for a source are the value of an input, so the type is the input's; the trait beside it, its schema and its stub had no caller |
| `fossil_hir::lineage` | what a program reads is a question about its def map, asked by every host |
| `fossil_shapes::shex`, `fossil_shapes::shacl` | a shape document becomes a type — the decoders, in their own crate, and the `providers` rows of `fossil_hir` that install them; what the executor was handed beside them, an enum whose one live method returned a `GraphSchema`, is a `GraphSchema` |
| `fossil_sinks::graphar::layout` | the graph's layout is the writer's: nothing else lays out a GraphAr graph, and the module exports nothing |
| `fossil_mir::describe` | the graph's mapping is a function of the types, so the editor's module links it and a host asks before a run ([the graph as Apache GraphAr](/docs/design/graphar)) |

One is still a crate of its own:

| crate | folds into | because |
| --- | --- | --- |
| `fossil-graph-schema` | `fossil-base`, `fossil-hir` | the errors are the substrate's and a primitive is the type system's |

The ShEx decode still resolves references and labels by hand; reading `shex_ast`'s compiled schema,
`SchemaIR`, through a `TryFrom` is [the declared types' direction](/docs/design/declared).

**SHACL is read by rudof's `ShaclParser`.** The graph is parsed by `rudof_rdf`'s in-memory store, the
parser `io.rdf` reads with, and `shacl`'s AST is projected onto the shape vocabulary in
`fossil_shapes::shacl`. They are the fork's, Kanzo-Tech's rudof at the commit of its PR #33, which is on
`shex_ast`'s line and shares its `IriS`, and whose `rudof_iri` `fetch` and `rudof_rdf` `sparql` features,
the ones that bring `reqwest` and `tokio`, are off by default: the wasm closure has neither, and
`cargo xtask wasm-check` fails the day it does. The fork adds what the walk read by hand: the
non-`sh:` triples of a shape (`extra`), `sh:order`, `sh:name` and `sh:description`, and shapes held in an
ordered map so that iterating them is the same on every run. The module editors load, `fossil_wasm_bg.wasm`,
grew from 5,459,661 to 6,758,681 bytes (+1,299,020, +23.8%; 1,555,565 to 1,929,451 gzipped, +24.0%), and the
executor's, `fossil_df_wasm_bg.wasm`, from 28,840,262 to 29,564,170 (+2.5%; 6,659,933 to 6,864,600 gzipped). Both are
`wasm-bindgen --target web` output of `cargo build --release` and `--profile wasm-release`, before `wasm-opt`, on 2026-10-14.
Of the editor's growth, 746,732 bytes were the graph (`rudof_rdf`'s in-memory store parsed every RDF syntax it knows,
while fossil asks for Turtle) and 552,288 are `shacl`'s parser, measured by building the decode with the parser stubbed out.

**`rudof_rdf` now has one cargo feature per syntax** (the fork's PR #37), and fossil asks for `turtle` alone. The same two
modules at the fork's `889cb741`, built the same way (`wasm-bindgen --target web`, `cargo build --release` and
`--profile wasm-release`, before `wasm-opt`, on 2026-10-15), are 6,218,133 bytes (1,775,441 gzipped) for the editor's and
29,546,971 (6,859,811 gzipped) for the executor's: the editor's module is 540,548 bytes (8.0%) smaller than at the
measurement above, with the graph's own growth still +758,472 (+13.9%) over the module before the fork, and the executor's
is 17,199 bytes smaller than before while carrying the GraphAr writer, `graphar-parquet` and `rml`. 

**The editor's module is built with `wasm-release`, like the other two.** `packages/wasm`'s `build-wasm.sh` used
`cargo build --release` and `wasm-opt -O3`; it now builds with the profile the executor and the storage module
already used (`opt-level = "z"`, fat LTO, `strip`, `panic = "abort"`) and runs `wasm-opt -Oz`, so there is one
size profile and not two. Nothing here catches an unwind (`grep -rn catch_unwind crates/` is empty), so `panic = "abort"`
gives up nothing on `wasm32-unknown-unknown`. At the fork's `889cb741`, on 2026-10-15, the editor's module is
5,013,996 bytes (1,622,233 gzipped) as shipped before, and 3,549,130 (1,245,546 gzipped) as shipped now: 29.2% fewer
bytes and 23.2% fewer gzipped. The price is speed the module has no benchmark for: `update` plus `diagnostics` on
`examples/hello.fossil` measured 0.3 to 0.7 ms an edit on a loaded machine for the old and the new build alike, which
is inside the noise, so what that costs a large program is not known. `wasm-opt` is not free either: on the
size-tuned build it saves raw bytes and adds gzipped ones (the module before `wasm-opt`: 4,164,703, 1,185,693 gzipped),
and the executor's does the same (with the change below: 29,541,340 and 6,857,455 gzipped before `-Oz`, 24,909,829 and 7,248,203 after, and 25,807,990
and 7,240,564 after `-Os`). The scripts keep it because the module is parsed and compiled raw, and a host that serves
Brotli was not measured.

**One thing in the editor's module is `regex`, and one function keeps it there.** Of the editor's 6,218,133 bytes before `wasm-opt`, 1,114,518
(17.9%) are `regex`, `regex-automata`, `regex-syntax`, `aho-corasick` and the Unicode tables they carry, and the only
call that reaches them from fossil is `shex_ast`'s `ShapeExprLabel::try_from(&str)`, which compiles `<(.*)>` and `_:(.*)`
to strip two delimiters (`twiggy paths` from `Regex::new` ends at it through `FromStr` and `Deserialize`, and nowhere else). Written as string searches,
with a test that holds both against the regexes they replace, the module is 5,103,615 bytes (1,412,754 gzipped) before
`wasm-opt` and 2,761,994 (966,691 gzipped) as shipped with the profile above. That is a change in the fork, not here, and
the rev moves to it when it is merged. The executor does not gain: DataFusion links `regex` itself, and its module is
5,631 bytes smaller. `oxrdfxml` and `quick-xml`, which `deny.toml` ignores two advisories for, are compiled and
linked into nothing: no symbol of either is in the editor's module.

**What would reverse it:** a measurement of the editor's `update` on a program of a real size that shows the
`opt-level = "z"` cost in a keystroke, in which case the editor takes `opt-level = "s"` in a profile of its own: with the change above, 3,448,192 bytes
(1,098,275 gzipped) after `wasm-opt -O3`, against 2,884,232 (971,688) for `"z"` after the same.

**The editor's module links the mapping.** `describe` moved to `fossil-mir` ([the graph as Apache
GraphAr](/docs/design/graphar), D6) so that `program.mapping()` can answer before a run, which puts `rml`'s AST and its
Turtle writer in the editor's module, beside `vocabularyOf` and `subjectOf`. Built with `--profile wasm-release` and
`wasm-bindgen --target web`, before `wasm-opt`, at the fork's `889cb741` on 2026-10-15, it is 4,360,297 bytes (1,244,285
gzipped) against the 4,164,703 (1,185,693 gzipped) above, which was not measured again: 195,594 bytes more (+4.7%) and
58,592 more gzipped (+4.9%). `wasm-opt` was not run. The module is still under the 2 MB compressed ceiling `build-wasm.sh` asserts.

**What would reverse it:** that growth showing in first paint. Then `mapping()` is the executor's module's and the
editor's is what it was, at the price of a host loading the larger module to ask for a shape before a run.

**What would reverse it:** a growth of that module that shows in first paint and that the fork
cannot trim (a parser the fork's features cannot drop, say), or its additions not reaching an upstream
release; the decode is then fossil's again, over a Turtle reader.

**What would reverse it:** a module whose consumers are not the crate it sits in — a second reader
of the graph layout in Rust, say, which would want `fossil_sinks::graphar::layout` without DataFusion.

## Held by

the check re-runs against the new columns; `crates/fossil-exec/tests/documents.rs` runs a program whose
output document the checker decoded; `crates/fossil-base/src/connections.rs` sets the connections
after a query read them and asserts it re-runs, and that setting the same map again does not.
