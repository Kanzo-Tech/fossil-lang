The rest of this section argues in the abstract on purpose: *seven languages, no exception*; *the
most-downloaded candidate*; *one editor maintains ten simultaneous ABI versions*. That reads better
and it is unfalsifiable, which is the failure this whole site is built to avoid. So the names live
here, once, with the single claim each one settles and where that claim is used.

This page is a bibliography, not an argument. It carries no opinion the other pages do not already
carry, and if a source is named here and used nowhere, it should be deleted rather than kept for
completeness.

## The algebra

| source | what it settles |
| --- | --- |
| **Min Oo & Hartig**, *An Algebraic Foundation for Knowledge Graph Construction* ([arXiv:2503.10385](https://arxiv.org/abs/2503.10385)), ESWC 2025 Best Research Award | The set fossil's middle elaborates. Nine operators plus the refinements the typed sink needs; the claim that erasing fossil's type annotations yields an expression in *their* algebra is what lets their soundness results carry over rather than be re-derived. [The mapping algebra](/docs/design/algebra) is the argument. |
| **Milner (1978)**, *A theory of type polymorphism in programming* | The form of the soundness commitment: well-typed programs do not fail for the reasons the types are about. |
| **Pierce (2002)**, *Types and Programming Languages* | The bidirectional presentation — synthesis and checking as two modes with named switch points — used in [the typing rules](/docs/design/typing). |

## Types from data

| source | what it settles |
| --- | --- |
| **F# type providers**, and **Petricek et al., PLDI 2016 §6.5** (*Types from data*) | Both halves of the naming rule. Their published criterion is that a provider must avoid anything that lets *a small change in the sample cause a large change in the provided types* — and their own collision scheme broke it: a numeric suffix made a member's name depend on which other members existed, their singulariser produced `Purchasis` and `Sourcis`, and a minor version bump renamed members and broke a program in production. So fossil takes only the last segment of the predicate IRI, never a plural heuristic, and a collision is an **error** rather than a suffix. |
| **F#'s `CsvProvider<…>` plus `.Load(…)`** | The one place fossil departs, and why: F# separates the type from the file because a type is reused across files. Here a binding *is* one concrete source, so `User := io.csv(…)` binds both and the separation would be ceremony. |
| **Prisma `@map`** | The shape of the repair when a derived name is wrong: an attribute above the declaration, all constants, in the program rather than in the vocabulary — which is `@rename`. |

## Identity

The claim on [identity](/docs/design/identity) is that no reviewed language admits a per-instance
expression in an attribute argument. These are the languages, and the control experiment.

| source | what it settles |
| --- | --- |
| **Java — JLS §9.7.1** | An annotation argument must be a constant expression. The specification calls the restriction a deliberate syntactic device, so this is a decision rather than an accident of the grammar. |
| **Jakarta Persistence `@Id`** | The annotation is *literally empty*: identity is expressed by **where it is placed**, not by an argument. |
| **Prisma** | No expression language at all in this position — nine closed names implemented in the engine. |
| **Django** | The criterion for keeping a language-owned namespace separate from user-declared names, which is what the `@` sigil does against the bare keys a shape declares. |
| **JSON-LD** | The solution shape for the same problem: a reserved, sigil-marked keyword space beside arbitrary vocabulary terms. |
| **Ecto (Elixir)** — the control experiment | Elixir *does* evaluate expressions in attribute arguments. `default: DateTime.utc_now` compiles, and it is wrong: it freezes **one value for every row**. Ecto documents it as a trap. The experiment matters because it shows the restriction elsewhere is not an accident of parsing. |
| **R2RML, RML and their mappers** | No precedent anywhere in the mapping world for *one identity per type* as a check; the community closed the request as out of scope. |
| **Ontop** | Computes the property and wires it only to the optimiser — detected, never diagnosed. |
| **Apollo Federation** | The counterexample, answered rather than ignored: it shipped this check in v1 and **removed it in v2**. It does not transfer, because its `@key`s are alternative ways to locate the *same* entity and its subgraphs deploy separately, so nobody ever holds the whole set. Here the compiler sees the whole program. |

## Shapes, and the surface around them

| source | what it settles |
| --- | --- |
| **ShEx** — Staworko & Boneva (ICDT 2015); Boneva, Labra Gayo & Prud'hommeaux (ISWC 2017) | The semantics of the constraint table fossil reads as a target type. |
| **[`rudof`](https://github.com/rudof-project/rudof)** — the WESO group's Rust ShEx implementation (Universidad de Oviedo, José Emilio Labra Gayo) | The implementation the checker reads shape documents through. It is also where our RDF 1.2 support came from without anyone deciding it — see the `oxttl` row below. |
| **SHACL 1.2 Core**, and its `sh:TripleTerm` node kind | The cost of the choice, stated plainly: SHACL is the W3C Recommendation with the active working group. What decides against it is expressiveness in this one job — it cannot distinguish "one" from "one or more", and closure has three states rather than two. [What was discarded](/docs/design/discarded) carries the three conditions that would reverse it. |
| **shexTest** | The termination criterion for the checker's shape support is a percentage of a published suite, not "round-trips textually", which nobody achieves. |
| **CUE** | The model for import soundness — what it means for a document to be accepted without silently losing what it declared. |
| **RDFC-1.0** | Canonicalisation, and therefore what "a fixed point modulo canonical form" means as an acceptance test. |
| **LinkML** and **TypeSpec** | Both put closure and cardinality in an emitter flag rather than in the type, and both demonstrate that round-tripping is then impossible **by construction**. That is why those live in the type here and never in a flag. |
| **schema.org** | The measured cost of a vocabulary you do not control: 82 terms carrying `supersededBy`, 24 morphological renames, and a typo frozen forever as a global identifier. It is the argument for `@rename` living in the program. |
| **Haskell §3.11** and **Scala §6.19** | Both define the left of `<-` as the **element** and the right as the collection. Borrowing that arrow for a source binding, where the left names the relation, would say the opposite of what it means. |
| **Rust — `s.len()` ≡ `str::len(&s)`** | One catalogue entry reachable by two paths, which is the model for member-call dispatch by receiver type. |
| **17 mapping languages and 12 schema-as-code systems** surveyed | 15 of the 17 treat a class IRI as an opaque string, and every one of them **derives** the shape from the mapping. Checking the mapping *against* the shape is the inversion, and it is the thesis. |

## RDF 1.2

| source | what it settles |
| --- | --- |
| **RDF 1.2 Concepts §3.1**, and the Turtle 1.2 drafts | A triple term appears in object position only; a triple term has no identity of its own; `rdf:reifies` mediates. The concrete syntaxes are Working Drafts, which is why the design is written against the abstract model. |
| **Oxigraph / `oxttl`** | The dependency trap: RDF 1.2 support sits behind a feature that was enabled here by a transitive dependency and never by us. Its changelog is also where the name change is recorded — *"RDF-star support is now dropped in favor of RDF 1.2."* |
| **MillenniumDB** | The reference for a discriminator in the identifier space: 8-byte identifiers whose first byte declares the class, with edge ids dense and consecutive by row position. |
| **The Wikidata singleton-property study** | A distinct predicate per statement broke four of five engines. It is the first-principles argument against singleton property in a dictionary-encoded column. |
| **StarBench** | Double nesting alone broke two of four engines, which is the evidence for an explicit nesting cap with a number rather than unbounded recursion. |
| **ISO GQL and openCypher** | `N ∩ E = ∅` — an edge cannot be the endpoint of another edge *by definition*, which is why the corpus question is ours and not a lookup. |

## The corpus, and how a format ships

| source | what it settles |
| --- | --- |
| **Iceberg** | The model for publishing arithmetic: the formula, the widths, the sign, **and a table of vectors** — `34 → 2017239379` turns up in the tests of independent implementations that copied it. |
| **PMTiles** | The counterexample: a Hilbert curve dispatched with a link to an encyclopedia, and every port re-deriving it. |
| **H3 against S2** | One compiled oracle almost nobody reimplements, against four oracles in a chain with no shared vectors and divergences open for years. H3 also settles the 64-bit boundary by decree, typing its index as a string before anyone could get it wrong. |
| **`node-s2`** | A *binding* — not a port — that returned wrong cell ids anyway, because JavaScript's `number` holds 53 bits and a cell id holds 64. It is why `BigInt` at the TypeScript boundary is a rule and not a precaution. |
| **Arrow, Parquet, Delta, Zarr, MVT, GraphAr** | The nine-format survey behind [the corpus](/docs/design/corpus). GraphAr is the one this corpus borrows *from*, and the borrowing has a measured edge: its specification defines **no count and no data-file path**, and its reference implementation supplies both — a count as raw native-endian bytes in a file the specification never names. So the rule is that fossil follows GraphAr as far as GraphAr specifies and no further, argued with the eight divergences it produces in [what is borrowed from GraphAr, and where borrowing stops](/docs/design/corpus#what-is-borrowed-from-graphar-and-where-borrowing-stops). |
| **Parquet's `LogicalType` against its deprecated `ConvertedType`** | What settles that an unsigned address is expressible at all, and what it costs to read one back. Unsignedness is an *annotation* on a signed physical `INT32`, so `uint32` is not an exotic type — but the format's original `min`/`max` statistics were defined by **signed** byte comparison and are therefore meaningless for it. A writer that gets this right leaves them empty and fills `min_value`/`max_value`; a reader that only knows the deprecated pair concludes the footer carries no box for exactly the column the whole address is built on. That is not hypothetical here: four checks in this repository passed over NULL for that reason before the fallback was written. |
| **dbt, Delta, Lance, Malloy** | Five projects that have already been through "does the specification get its own repository". None of them separates the implementation. Delta shows co-location does not prevent drift and that what fixes it is a **process** (`protocol_rfcs/`, specification PR before implementation PR); Malloy is the counterexample, with twenty-five satellite repositories and one frozen 159 releases behind. |

## The backend

[The backend](/docs/design/backend) takes its reading path from one system and its addressing from
two standards, and departs from each in named places. These are the sources that page is held
against.

| source | what it settles |
| --- | --- |
| **Apache Iceberg's read path** — PyIceberg's `Table.scan(row_filter, selected_fields, case_sensitive, snapshot_id, options, limit)`, `DataScan.plan_files()` and `to_arrow()` (`pyiceberg/table/__init__.py`); iceberg-rust's `TableScanBuilder`, `TableScan::plan_files` and `to_arrow` (`crates/iceberg/src/scan/mod.rs`) | The shape of the reader: a table loaded from its metadata, a scan that is a filter plus a projection, planning into tasks, and a task read on its own. PyIceberg's `FileScanTask` is `{ file, delete_files, residual }` and never splits a file; iceberg-rust's carries `start`, `length` and `record_count`, which is the split fossil takes, one row group per task. |
| **Iceberg's expressions and metrics evaluators** — `EqualTo`, `In`, `IsNull`, `And`, `Or`, `Not`, `UnboundPredicate.bind(schema)`; `_InclusiveMetricsEvaluator` and `_StrictMetricsEvaluator` (`pyiceberg/expressions/`), `InclusiveMetricsEvaluator` and `StrictMetricsEvaluator` in iceberg-rust | The filter vocabulary, bound before planning, and the two pruning answers — *rows might match* over `lower_bounds`, `upper_bounds` and `null_value_counts`, and *rows must match*, which PyIceberg's planner does not use and fossil uses to drop a residual. |
| **The Iceberg table spec**, manifests and scan planning ([iceberg.apache.org/spec](https://iceberg.apache.org/spec/)) | Statistics are written by the writer, per data file, into a manifest a reader plans from without opening the data — the argument for the tile manifest. |
| **How Iceberg's writers fill a manifest** — Java's `ParquetUtil.footerMetrics`, and iceberg-rust's Parquet writer building its `DataFile` from the `ParquetMetaData` the Arrow writer returns on close (`crates/iceberg/src/writer/file_writer/parquet_writer.rs`) | The numbers are read off the footer the writer has just closed, not computed a second time over the rows — which is how `fossil-layout` fills the tile manifest (`crates/fossil-layout/src/layout/statistics.rs`), and why the guard holds the published figures against the footers rather than against a recount. |
| **OGC Two Dimensional Tile Matrix Set 2.0** (17-083r4) | Declared, never derived, and its own reason for it: each tile matrix publishes its width and height in tiles *so that the range of relevant tile indexes does not have to be calculated by the client application*. That is the argument for `projections:` carrying `scale` itself rather than a level number a reader would raise to a power, and against re-deriving the writer's plan from `vertex_count`. |
| **OGC API – Tiles – Part 1: Core** (20-057) and its WebMercatorQuad | The address: `{tileMatrix}/{tileRow}/{tileCol}` with the matrix a string id, matrix `z` of WebMercatorQuad being `2^z × 2^z` with four children per tile, and an out-of-range tile being an error rather than an empty answer. |
| **FlatGeobuf's packed Hilbert R-tree**, and **PMTiles' `TileID`** | Two formats that order spatial data on a Hilbert curve so that a run of it has a tight box — FlatGeobuf sorts features by Hilbert value and indexes the boxes of consecutive runs, PMTiles numbers its tiles along one. The reference for [the ruling](/docs/design/backend#the-id-is-a-hilbert-rank) that ranks `dense_id` on the same curve — in Wikipedia's `xy2d` spelling at `n = 2^16`, and published with vectors where PMTiles publishes a link. |
| **deck.gl's `Tileset2D`** | Named and not used here: it is the view's reference for loading, caching and cancelling tiles, and kanzo-ui argues it. It is on this page because the backend's refusal to cache is stated against it. |

## Multiscale readers

The corpus already had the three parts every multiscale reader has — a declared list of what each
scale holds, an address that is arithmetic, and a client that picks the scale — before the backend
named its references; these are the systems the list and the container were read against.

| source | what it settles |
| --- | --- |
| **OME-NGFF / OME-Zarr `multiscales`** | **The two field names, not an analogy.** A `multiscales` object lists `datasets`, each carrying a `path` to its array and a `coordinateTransformations` entry of `{"type": "scale", …}`, ordered by a rule the specification fixes — the paths *MUST be ordered from largest (i.e. highest resolution) to smallest*. `projections:` is that block flattened onto the one axis a sequence has: `path`, `scale`, finest first. The spelling is theirs because the point of borrowing is recognition. The coarse entries it held — a subset of one array rather than a resampling of it — were the retired level files; every projection is at `scale: 1` now, and the coarse scales are the cell tree's rungs, which carry a count and not a `scale`. |
| **Zarr v3's `sharding_indexed` codec** | Many addressable chunks inside one object with an index at its end, so that an address stays arithmetic while a request stays one request. It is the same trade `container: rowgroups` makes with row groups and a Parquet footer, arrived at independently. |
| **Cloud Optimized GeoTIFF** | The other container answer: the whole pyramid inside one file as reduced-resolution directories, read by range request. Named because it is the alternative to a directory per rung, and the reason it is not needed here is that a run of tiles is one range request either way, and the coarse rungs are a handful of tiles. |
| **ASK-GraphView** — Abello, van Ham & Krishnan, *IEEE TVCG* 12(5):669–676, 2006 | The alternative, at the largest scale anyone has published it: a clustering hierarchy over the graph, navigated by expanding one cluster into its children. That expansion is the meta-node that moves every point on screen, which is why the retired levels here were a decimation, and why the cells that replaced them nest by the partition rather than by a clustering — the refusal it is cited to size. **This entry said it was also the design [cells](/docs/design/cells) follows, and that is retracted**: that page publishes a pyramid of cells cut on `dense_id`, and a clustering hierarchy navigated by expanding one cluster into its children is the holarchy [what was discarded](/docs/design/discarded) rejects. So it is refused in both readers, for two different reasons — the meta-node in one, a measured extent a reader would have to fetch in the other — and it is the exact shape of reader that would bring the holarchy back. |

## The partition, and where its levels come from

[Cells](/docs/design/cells) decides that a corpus carries one multiscale structure and that it is
the cell pyramid, and the decision turns on what a community hierarchy's levels *are*: measured
stopping points of a greedy optimisation rather than a declared sequence. Three sources carry the
weight of that sentence, and the third carries the name the block is still called by.

| source | what it settles |
| --- | --- |
| **Louvain** — Blondel, Guillaume, Lambiotte & Lefebvre, *Fast unfolding of communities in large networks*, *J. Stat. Mech.* (2008) P10008 ([arXiv:0803.0476](https://arxiv.org/abs/0803.0476)) | **That a community hierarchy's levels are where the passes stopped, not a schedule anyone chose.** The method alternates local moving with contraction and repeats until no move improves the objective, so the number of levels and the contraction between them are outputs. That is the whole of why a holarchy's extents cannot be declared ahead of the bytes the way `ceil(V / 4^k)` can, and why com-DBLP yields five levels of which the declared cut admits three. `crates/fossil-layout/src/layout/community.rs, community_hierarchy` is the implementation the measurements here were taken from. |
| **Modularity** — Newman & Girvan, *Finding and evaluating community structure in networks*, *Phys. Rev. E* 69, 026113 (2004) ([arXiv:cond-mat/0308217](https://arxiv.org/abs/cond-mat/0308217)) | **The objective the numbers on [cells](/docs/design/cells) are of** — 0.6356 climbing to 0.8092 across com-DBLP's five levels, and the 0.0001 that the discarded fifth level buys. It is also what makes the retraction on that page precise: a merge that maximises modularity absorbs edges *on purpose*, which is a property of the objective and not of the algorithm, and it is the one thing a fixed-count cut genuinely does not do. |
| **Koestler**, *The Ghost in the Machine* (1967) | **The word this tree used, and the promise it made.** A *holon* is a thing that is simultaneously a whole and a part — semantic nesting, a level of organisation that is *about* something. The pyramid on [cells](/docs/design/cells) carried the name for months and gives the promise up in its own first section: its partition is cut on `dense_id` and means nothing. The source stays cited because the rename is argued against it rather than against taste — what a reader would find on looking the word up is the thing the artefact is not. |

## Coordinates, and where they come from

The claim on [where x and y come from](/docs/design/position) is that a corpus has to record the
*provenance* of its positions, and that the field carrying it is a list rather than a value. Neither
half is invented here.

| source | what it settles |
| --- | --- |
| **SpatialData** — Marconato et al., *Nature Methods* (2024), [10.1038/s41592-024-02212-x](https://doi.org/10.1038/s41592-024-02212-x) | **That more than one coordinate system over one dataset is a shipped design rather than a hypothetical.** Built on OME-NGFF and Zarr, its elements are aligned *into* named common coordinate systems, with the transformation that placed them there recorded alongside — so one array legitimately sits in several spaces at once and a reader chooses. That is the shape `coordinates:` takes, and the reason it is a list: the alternative is a writer picking on a reader's behalf. |
| **OME-NGFF `coordinateTransformations`** (also cited above, for `projections:`) | The same list shape one field over, and the precedent for borrowing the spelling rather than inventing one. What it does *not* carry is provenance — a `scale` says how an array maps into a space, never where the space came from — so the borrowing stops before the field this page is about. |
| **napari**, with `napari-ome-zarr` | That an exact multiscale raster needs no bespoke reader: the 183 kB eleven-level density pyramid measured over com-DBLP opens without a line of napari being written. Named with its measured limit, because a source cited without one is decoration — the plugin honours `scale` and ignores `translation`, so a raster whose origin is not zero lands displaced unless the offset is applied by hand. |

## A catalogue of names, and how one is kept honest

Two decisions rest on these. That the stdlib stays a Rust table rather than moving into
`catalogue.bnf` is [a discarded alternative](/docs/design/discarded); that a row declares every
parameter it takes is argued in [the dot](/docs/design/the-dot).

| source | what it settles |
| --- | --- |
| **rustc's `symbols!`** (`compiler/rustc_span/src/symbol.rs`) | The shape of a generated name table, and its two admitted costs, both in its own source: *"There is currently no checking that all symbols are used; that would be nice to have"*, and an ordinal that is semantically load-bearing — keyword classification is a range comparison over generated indices, so reordering the list changes the language. fossil takes the generation and refuses the ordinal: a provider's identity is its own address, never its position. |
| **rustc PR #110437**, *Add unused pre-interned symbols tidy check* (closed unmerged) | The reason there is no "declared but not lowered" guard. The author measured **35** unused symbols and closed it — *"I personally don't think it's worth having this extra maintenance burden"*; the reviewer agreed. The mechanism that replaced it is a periodic manual audit, and that is the mechanism here. |
| **rustc's `Providers`** | The DATA/BEHAVIOUR split `catalogue.bnf`'s header names: the data says what exists, the code registers what it can do. Cited as lineage and not as implementation — its own detection of a missing registration is an ICE whose message says *"likely never assigned"*, because it cannot tell that apart from a genuine absence. |
| **rust-analyzer's `language_item_table!`** (`crates/hir-def/src/lang_item.rs`) | Three choices fossil copies: **typed slots** rather than an untyped array indexed by discriminant; **no `require`** anywhere, so every accessor is `Option` and every consumer degrades, which is what an IDE that must answer over an incomplete program needs; and one table holding several *kinds* of row rather than several tables. The fourth thing it settles is the tier split — *the declaration is compile-time, the binding is a query, neither is an input* — against which `Registry` is the one input fossil genuinely has, because it models what a **host** installs. |
| **rust-analyzer's `builtin_type.rs`** | The floor of the argument. Nineteen builtin types, a hand-written array, a linear scan reconstructing it on every lookup, and **not in the database at all** — because nineteen is small and the alternative buys nothing. Forty-one is nearer nineteen than it is to anything that needs a file. |
| **Swift's `.def` files; Clang's move off them** | The measurement that sizes the question: `.def` carried **1,364** rows with no generator before TableGen was considered, and Clang left the format at around **6,000**. |
| **Swift's `GenBuiltin.cpp`** | The exhaustive switch with no `default:` and the unimplemented cases listed by name, forty lines from its own counter-example. It is the fix `lower_source_stage` copies, and the ten unlowered relation verbs are the same list. |
| **PostgreSQL's catalogue** (`pg_proc` and its `.dat` files) | The strongest form of the design in the survey: a data file, a generator, and **a reference the linker has to resolve** — ~3,300 rows paying one file per addition for a link error as the guarantee. `catalogue.bnf`'s `decodes decode_shex` gets the identical property at six rows. |
| **rust-analyzer's `xtask codegen --check`** | The ergonomics of a drift guard: rewrite in place locally with a red note on stderr, hard-fail only under CI, and name the exact command to re-run in the failure text. |
