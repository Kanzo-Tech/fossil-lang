title: Its RDF meaning, as triples
description: What a corpus means as RDF, stated once as one relation of triples that attach() attaches beside the tables, so a SHACL engine, a triplestore loader or any reader of triples reads the corpus with plain SQL and no fossil code.
---

A corpus is a property graph in Parquet, and its meaning as RDF is in the manifest already: a vertex
table's `iri` is a class and its `identity` column the subject, a column's `iri` is a predicate, and
an edge table's `iri` is a predicate between the subjects its two ends reference. **`attach` states
that meaning once, as the relation `"<name>".triples`** — one row per RDF triple, a view over the
tables beside them — so that a reader who wants triples selects them instead of re-deriving the
interpretation.

```ts
await using corpus = await attach(job, { engine, host });
await engine.query(`SELECT * FROM "${job}".triples`);   // what a SHACL engine validates
```

| column | what it holds |
| --- | --- |
| `s_type`, `s_value` | the subject's type, always `I`, and its IRI |
| `p` | the predicate IRI |
| `o_type` | the object's type: `I` for an IRI, `L` for a literal |
| `o_value` | the object's IRI, or its lexical form |
| `o_datatype` | a literal's datatype IRI, and `''` for an IRI |
| `o_lang` | a literal's language tag, and `''`: a corpus states none |

The suffixes are SPARQL 1.1 Query Results JSON's names for a term's parts (§3.2.2): `type`,
`value`, `datatype` and the language.

Every column is `VARCHAR` and none is null, so a reader compares terms with `=` and never with
`IS NOT DISTINCT FROM`. `packages/corpus/src/triples.ts, triplesOf` is a pure function of
`fossil.json`: the same manifest answers the same view, and it reads no Parquet until the view is
read. The relation is not a file of the corpus and `fossil.json` does not name one: the corpus carries
the IRIs, and the triples are what they mean. `triples` is therefore a name no table may have, as
`fossil_tables` and `fossil_columns` are, and `attach` refuses a manifest that uses it with
`corpus/duplicate-table`.

## What each part means

**A vertex type is its subjects' class, and its columns' values.** Each row's `identity` is the
subject, as an IRI, and has `rdf:type` the table's `iri`. Each column with an `iri` is a predicate,
and each non-null value of it an object, with the term its shape declared.

**A relation is the edge table, joined at each end.** `src` is joined to the source's `dense_id` and
`dst` to the destination's, and the triple is the source's subject, the relation's `iri`, and the
destination's subject as an IRI. `dense_id` is an
[address and never an identity](/docs/format/conventions/identity), so it is joined through and never
emitted.

**A multi-valued property is the same join over its own table**, a row per value: `src` joined to the
vertex it belongs to, and the value an object with the term the column declares, as a vertex
column's is.

## The rules

- **What has no IRI is not mapped.** A column without an `iri` makes no triple; a relation without
  one makes none; a vertex type without one has subjects with no `rdf:type`. A relation or property
  whose end names a type with no table has no subject there, and makes none either. Nothing is
  invented: there is no default namespace a missing IRI falls back to.
- **The term is the shape's, verbatim.** `fossil.json` carries the term each column's shape declared
  — `term_type`, R2RML's `rr:IRI` or `rr:Literal`, and `datatype`, the IRI the document wrote — and
  the view writes both. Nothing is derived from the column's `type` then: a shape that says
  `xsd:gYear` over an `int32` column makes `xsd:gYear` literals. The `declared-term` guard holds every
  stored value to the term its column declares, so the literal is always well-typed.
- **Where the shape declared no term, the literal is the column's natural one** — the natural
  mapping of SQL types to XSD of [R2RML §10.2](https://www.w3.org/TR/r2rml/#natural-mapping), the W3C
  Recommendation for relational data as RDF:

  | `type` | datatype | lexical form |
  | --- | --- | --- |
  | `int8` … `int64`, `uint8` … `uint64` | `xsd:integer` | the digits |
  | `float`, `double` | `xsd:double` | the digits, and `INF`, `-INF`, `NaN` |
  | `decimal` | `xsd:decimal` | the digits |
  | `bool` | `xsd:boolean` | `true`, `false` |
  | `date`, `time` | `xsd:date`, `xsd:time` | ISO 8601 |
  | `timestamp` | `xsd:dateTime` | ISO 8601, with its `T` |
  | `binary` | `xsd:hexBinary` | the bytes in hex |
  | `string`, and anything else | `xsd:string` | the text |

  The lexical form is the one the `declared-term` guard checks, so a column declared `xsd:double`
  and one that falls back to it spell an infinity the same way.

## Why a relation

The reader once answered this meaning as an R2RML mapping in Turtle, for a processor to run over the
tables. Every consumer then needed an R2RML processor, and the one consumer there was — a SHACL
engine over SQL — needed only the triples. [`design/discarded`](/docs/design/discarded) keeps the
mapping and what would bring it back.

## How it is held

`packages/corpus/tests/triples.test.ts` reads the view of the checked-in corpus and compares it with
`packages/corpus/tests/rdf.ts, held`: the triples a second query, written by the test against the
manifest and the tables, says the corpus holds. Over tables of every type word it holds each natural
literal to the spelling XSD gives it, and a declared IRI to an IRI. `integration/round-trip.test.ts`
does the same over a corpus the executor writes, with an edge between two types.
