A corpus is a property graph in Parquet, and its meaning as RDF is in the manifest already: a vertex
table's `iri` is a class and its `identity` column the subject, a column's `iri` is a predicate, and
an edge table's `iri` is a predicate between the subjects its two ends reference. **`mapping` states
that meaning once, as an [R2RML](https://www.w3.org/TR/r2rml/) mapping** — the W3C Recommendation
for relational data as RDF — so that a reader who wants triples runs an R2RML processor over the
tables instead of re-deriving the interpretation.

```ts
import { mapping } from '@fossil-lang/corpus';
const turtle = mapping(manifest);   // manifest: the text of the corpus's fossil.json
```

`packages/corpus/src/mapping.ts, mapping` is a pure function of `fossil.json`'s text: it reads no
Parquet and the same manifest answers the same Turtle. It refuses what `open` refuses —
`corpus/not-json`, and `corpus/unsupported-format` for a format other than `fossil/1`. The mapping is
not a file of the corpus and `fossil.json` does not name one: the corpus carries the IRIs, and
the mapping is what they mean.

## What each part means

**A vertex type is a `rr:TriplesMap` over its table.** The subject is the `identity` column, as an
IRI, of class `iri`. Each column with an `iri` is a predicate-object map whose object is the column,
with the term its shape declared — `term_type` and `datatype`, copied as `rr:termType` and
`rr:datatype`.

```turtle
<#map/Person> a rr:TriplesMap ;
  rr:logicalTable [ rr:tableName "\"Person\"" ] ;
  rr:subjectMap [ rr:column "\"subject\"" ; rr:termType rr:IRI ; rr:class <https://example.org/Person> ] ;
  rr:predicateObjectMap [ rr:predicate <https://example.org/birthYear> ; rr:objectMap [
    rr:column "\"birth_year\"" ; rr:termType rr:Literal ; rr:datatype xsd:gYear ] ] .
```

**A relation is a `rr:TriplesMap` over an `rr:sqlQuery`.** The query is the edge table, inner-joined
at each end to the vertex table its key `references`: `src` to the source's `dense_id`, `dst` to the
destination's, answering each one's `subject` as `source` and `destination`. The subject of a triple
is the source's subject, the predicate is the relation's `iri`, and the object is the destination's
subject as an IRI. `dense_id` is an [address and never an identity](/docs/format/conventions/identity),
so it is joined through and never emitted.

```turtle
<#map/Order_placedBy_Person> a rr:TriplesMap ;
  rr:logicalTable [ rr:sqlQuery """SELECT s."subject" AS "source", d."subject" AS "destination"
FROM "Order_placedBy_Person" AS e
JOIN "Order" AS s ON e."src" = s."dense_id"
JOIN "Person" AS d ON e."dst" = d."dense_id\"""" ; rr:sqlVersion rr:SQL2008 ] ;
  rr:subjectMap [ rr:column "\"source\"" ; rr:termType rr:IRI ] ;
  rr:predicateObjectMap [ rr:predicate <https://example.org/placedBy> ;
    rr:objectMap [ rr:column "\"destination\"" ; rr:termType rr:IRI ] ] .
```

**A multi-valued property is the same query over its own table**, a row per value: joined at `src`
to the vertex table it references, answering the vertex's `subject` as `source` and the value as
`value`. The object is the value, with the term the column declares, as a vertex column's is.

```turtle
<#map/Person_nickname> a rr:TriplesMap ;
  rr:logicalTable [ rr:sqlQuery """SELECT s."subject" AS "source", e."nickname" AS "value"
FROM "Person_nickname" AS e
JOIN "Person" AS s ON e."src" = s."dense_id\"""" ; rr:sqlVersion rr:SQL2008 ] ;
  rr:subjectMap [ rr:column "\"source\"" ; rr:termType rr:IRI ] ;
  rr:predicateObjectMap [ rr:predicate <https://example.org/nickname> ;
    rr:objectMap [ rr:column "\"value\"" ] ] .
```

Each query is declared `rr:SQL2008`, R2RML's identifier for Core SQL 2008 (ISO/IEC 9075): it is
standard SQL and no engine's dialect, and it is always one of these two forms — inner joins of
delimited identifiers. R2RML §5.2 makes it a derived table, so a processor runs it as it stands.

## The rules

- **What has no IRI is not mapped.** A column without an `iri` has no predicate map; a relation
  without one has no triples map; a vertex type without one has subjects with no `rr:class`, and a
  type with neither an IRI nor a column that has one has no triples map at all. Nothing is invented:
  there is no default namespace a missing IRI falls back to.
- **The term is the shape's, verbatim.** `fossil.json` carries the term each column's shape declared
  — `term_type`, R2RML's `rr:IRI` or `rr:Literal`, and `datatype`, the IRI the document wrote — and
  the mapping copies both. Nothing is derived from the column's `type`: a shape that says `xsd:gYear`
  over an `int32` column is mapped `xsd:gYear`. Where the shape declared no term the mapping states
  none, and R2RML's default holds: a literal of the column's natural datatype (§10.2), which the
  processor derives from the SQL type. The `declared-term` guard holds every stored value to the term its column
  declares, so the override of §10.3 makes a well-typed literal and never the data error of §11.
- **Every name is a delimited identifier, unqualified.** `rr:tableName`, `rr:column` and every name
  in a query is written `"Person"`, case kept, a `"` doubled — so every processor reads it the same
  way and none folds `birthYear` to upper case. No catalog or schema is in front of a table: R2RML
  leaves the connection to the processor, and each consumer resolves the names against wherever it
  attached the corpus.
- **The mapping's own nodes are relative IRIs** — `<#map/…>` — resolved against wherever the document
  is kept. They are never subjects of the triples it produces.

## How it is held

`packages/corpus/tests/mapping.test.ts` parses the Turtle as a graph and holds it against the
manifest — every type, column and relation with an IRI mapped, nothing without one, each column's
declared term copied and none invented, each relation's and property's query joining the right keys
of the right tables. Then it runs the mapping:
`packages/corpus/tests/r2rml.ts, materialise` is an R2RML processor for the constructs the mapping
uses, natural datatypes included, over DuckDB, and the triples it makes of the checked-in corpus are
compared with the triples a second query, written against the manifest, says the corpus holds. `integration/round-trip.test.ts`
does the same over a corpus the executor writes, with an edge between two types.
