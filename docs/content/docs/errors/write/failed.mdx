---
title: A graph file could not be written
description: "`write/failed` — the store refused one file of the graph, so the write stopped and `fossil.graph.yml` was never written."
---

The run executed, laid the graph out, and was writing it when the store refused a file:

```text
`vertex/Person/` could not be written
```

`data.path` is what was being written, relative to the destination — a vertex type's directory
`vertex/<Type>/`, an edge type's `edge/<Src>_<label>_<Dst>/`, or `fossil.graph.yml`. The cause is the store's refusal, kept as a
nested problem with a code of its own — usually
[`storage/unreachable`](/docs/errors/storage/unreachable), the store having answered with an error,
which in turn carries the store's own message.

```ts
if (isFossilError(e, 'write/failed')) console.error(e.data.path, e.cause);
```

## Why fossil refuses it

A graph is an Apache GraphAr graph: the chunks of each vertex type and each relation, the information
file of each, and `fossil.graph.yml`, written **last**. The graph document's presence is the commit: a
reader that finds it can trust every file it names, and a directory without it is a write that did not
finish, which no reader opens. So when one file fails, the write stops at once — nothing after it is
written, and the graph document never is. What is left under the destination is chunks with nothing
over them, not a graph that looks whole and is missing a table. The layout of the files is on
[the format](/docs/format).

## How to repair it

- **Read the cause.** It is the store's answer — a permission refused, a network error, a quota.
- **Check the write credential.** The host vends `write` for the job's prefix; a credential that has
  expired, or that grants read only, is refused by the store at the first `put`.
- **Run again.** The files a failed run left behind are not a graph, and a new run to the same
  destination writes every file again, `fossil.graph.yml` last.
