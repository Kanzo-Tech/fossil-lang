---
title: The table has no position
description: "`corpus/no-position` — a scan filtered by `bbox` over a table that declares no position."
---

A `bbox` filter keeps the rows inside a box over the two columns a table is drawn at. Those columns
come from the table's `position` in `fossil.json`, and this table has none:

```ts
corpus.scan({ table: 'Person_knows_Person', filter: { bbox: [0, 0, 10, 10] } });
```

```text
Person_knows_Person declares no position, so it has no box to filter by
```

A host sees `data: { table }`. It is thrown synchronously by the filter binder when the scan is built,
wherever the `bbox` sits in the filter — under an `and`, an `or` or a `not`.

## Why fossil refuses it

A box is not over any two columns; it is over the pair the manifest names as where the table is drawn,
the writer's layout `x`/`y` or the program's own columns ([where x and y come from](/docs/design/position)).
An edge table carries no position, and a vertex table without one is not drawn, so there is nothing a
box could mean for it. Choosing columns that happen to be called `x` and `y` would be a guess; matching
no rows would make an empty answer look like an empty region.

## How to repair it

- **Scan a vertex table that is drawn** — its manifest entry has `position`.
- **Filter on the columns directly** when they exist under other names: `and` of `>=` and `<=` leaves
  on the two columns does what `bbox` does, closed on every edge.
- **Write the corpus with a position** for the table if it should be drawn.
