---
title: Not a table of this corpus
description: "`corpus/unknown-table` — `scan` was asked for a table the corpus's manifest does not declare."
---

`corpus.scan({ table })` names one table of the corpus, and the name is not among the vertex and edge
tables `fossil.json` declares. The message lists the ones it does:

```ts
corpus.scan({ table: 'Nobody' });
```

```text
Nobody is not a table of this corpus — its tables are Person, Organisation, Person_worksAt_Organisation
```

A host sees `data: { table, tables }` — the name it asked for, and every table name the manifest
declares, vertex tables first. It is thrown synchronously by `scan`, when the scan is built, before
any statement reaches the engine.

## Why fossil refuses it

The manifest was read once, at `open`, and it is the whole catalogue of the corpus: one view was
created per table it names, and nothing else exists to read ([one door](/docs/design/one-door)). A
name that is not in it would become a query against a view that was never created, and fail later as
the engine's own error about a relation it cannot find. Checking against the manifest gives the
mistake a code, before any statement, and the list of names that would have worked.

## How to repair it

- **Use a name from `data.tables`**, or from `corpus.manifest.vertex_tables` and `edge_tables`.
- **An edge table is scanned by its `name`, not its `label`.** A label like `knows` repeats across
  relations; the table's `name` is the one that is unique.
- Names are matched exactly, case included.
