---
title: The projection selects nothing
description: "`corpus/empty-projection` — a scan was given `select: []`, a projection of no columns."
---

`select` on a scan names the columns to read, and leaving it out reads every column. An empty array is
neither: it asks for no columns at all.

```ts
corpus.scan({ table: 'Person', select: [] });
```

```text
the projection names no column of Person
```

A host sees `data: { table }`. It is thrown synchronously by `scan`, when the scan is built, before
the columns in `select` are checked and before any statement reaches the engine.

## Why fossil refuses it

A scan answers rows in columns — one Arrow batch per task — and a projection of nothing has no
columns to carry them in: whatever the engine made of it, the answer would hold no values. Reading
every column instead would quietly turn the narrowest request into the widest one, which is exactly
the cost `select` exists to avoid. The two meanings stay apart: no `select` is
*everything*, an empty one is a mistake.

## How to repair it

- **Leave `select` out** to read every column.
- **Name at least one column.** If the list is built from a user's choice, skip the scan when nothing
  is chosen rather than passing an empty list.
