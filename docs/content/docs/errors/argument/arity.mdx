---
title: The wrong number of arguments
description: "`argument/arity` — a call gives a function fewer arguments than it requires or more than it takes."
---

Every function in [the standard library](/docs/book/stdlib) has a signature, and a call has to fill
its required parameters and no more than all of them. `str.concat` takes exactly two strings:

```fossil
    label = str.concat(Row.label)
```

```text
`str.concat` takes 2 arguments, and 1 was given
```

On the value path the receiver counts: `Row.label.concat()` is the same call with the same one
argument, because `x.concat(y)` is `str.concat(x, y)`. When a row has optional trailing parameters,
the message gives the range, `takes 1 to 2 arguments`.

This code is for calls to catalogue functions in an expression. A relation verb given the wrong
arguments is [`pipeline/stage-arity`](/docs/errors/pipeline/stage-arity), and an edge given the wrong
number of values for its identity is [`identity/edge-arity`](/docs/errors/identity/edge-arity).

## Why fossil refuses it

[Calls are checked against the catalogue entry](/docs/design/typing#calls) — arity and types both — so
that nothing is written from a value nobody checked: the property line is poisoned and not written.
The comparison is between two lengths, and it is sound because of two rules that hold elsewhere:
named arguments are placed into their declared slots and a gap between two filled positions is
refused on its own ([`argument/skipped-parameter`](/docs/errors/argument/skipped-parameter)), and
every optional parameter of a row comes after every required one, which the catalogue asserts of
itself. So a short argument list is always missing its trailing parameters, never one in the middle.

## How to repair it

- **An argument is missing.** Read the row in the standard library and supply it. Remember that on
  the value path the receiver is the first argument already.
- **There is one too many.** Some rows take fewer arguments than their counterparts elsewhere:
  `str.slice` has a `start` and no `end`, `math.round` takes no `digits`, `str.concat` takes exactly
  two. Nest calls to combine more: `str.concat(a, str.concat(b, c))`.
