---
title: No credential was vended
description: "`storage/no-credential` — the host answered a request for credentials with an empty list, so there is nothing to reach the scope with."
---

fossil asked the host for `read` or `write` access on a scope — a job or a connection — and the
host's `credentials(scope, access)` resolved to an empty array. It did not refuse; it vended
nothing. The message names both halves of the request:

```text
the host vended no write credential for job job-2
```

A host sees it as a `FossilError` whose `data` is `{ scope, access }`. `scope` is written the way
fossil names it, `job <id>` or `connection <name>`, and `access` is `read` or `write`. It is thrown by
`mount` in `@fossil-lang/storage`, so by `attach(job, { engine, host })` in `@fossil-lang/corpus`, and
by a run in `@fossil-lang/executor`, which asks for `write` on its job before it reads a source or
writes a byte. A document read through a connection answers it as that file's `problem` rather than
throwing it, and introspection reports it through `onWarn` and skips the source.

## Why fossil refuses it

fossil never reaches storage on its own authority. The one capability a host gives it is
`Host.credentials`, and the answer is a list of Iceberg REST `StorageCredential`s, each scoped to one
prefix — see [storage is reached by a vended credential](/docs/design/three-hosts). An empty list
leaves no prefix to install a secret for and no store to route through, and reading anyway would
mean reading anonymously, which is not what the host authorised. So `mount` stops before it touches
the engine, and a run stops before it writes a byte: the executor's test for this case asserts that
the job fails and nothing was put.

A credential that stops being vended later is not this error at the moment it happens: a renewal that
no longer finds its prefix keeps retrying while the old credential still works, and only logs once it
has expired.

## How to repair it

- **Check the access asked for.** A corpus is opened with `read` on its job; a run asks `write` on
  its job; documents and sources ask `read` on the connection they lie under. A host that vends only
  `read` for jobs answers a run with an empty list.
- **Check the scope.** `data.scope` is the job id or connection name fossil was given. A typo in the
  job id, or a connection the host's `connections()` lists but `credentials` does not know, ends here.
- **Vend at least one credential** for that scope and access, with a `prefix` ending in `/`.
