---
title: A retired spelling
description: "`syntax/retired-spelling` — a form fossil once had and has removed, recognised on purpose so the message can say what replaces it."
---

The program uses a spelling the language had and retired. The parser still recognises each of these
forms, consumes the whole of it, and names the replacement instead of reporting an unexpected token:

```text
User : Person from Users
    @subject = "https://example.org/user/{Users.id}"
    email = .email
```

```text
syntax/retired-spelling
  × `.name` is retired: write `Row.name`
  help: a leading `.` names a column of a row with no name, and the row has a name now. Every
        reference is qualified: write `User.name`, naming the row this mapping draws `from`.
```

There are six, and each message pairs the form with what to write:

| retired | write instead | why it went |
| --- | --- | --- |
| `prefix ex: <…>` | a full IRI in a string, `"http://…"` | there is no vocabulary left to declare: the CURIE is gone from every position |
| `ex:Person`, `ex:name` | the bare name, `Person`, `name` | a shape is a name a `type { … } := …` binding introduced; a property is the last segment of its predicate IRI |
| `<http://…>` | a string, `"http://…"` | `<` is the comparison operator and nothing else |
| `.name` | `Row.name` | every reference is qualified by the row it belongs to |
| a backtick string | `"…{expr}…"` | it was a second spelling of the quoted string |
| `a \|> f(…)` | `a.f(…)` | it was a second spelling of the member call |

The label covers the entire retired form, not one token of it. A retired `<http://…>` takes the rest
of its line: the `//` in its scheme opens a comment, so the `=` and the value after it are part of
what is refused.

## Why fossil refuses it

Each form left the grammar because it was a second way of saying something the language already
says, or because what it declared no longer exists ([what an expression is](/docs/design/expressions#what-leaves)).
The language keeps no two spellings for one idea, so the old one is an error rather than an alias.

They are recognised by name rather than left to fall through for a specific reason. Without it,
`ex:name = …` would be an `expected IDENT, found SHAPE_SEP`, which throws away both what the author
wrote and what to write instead. Worse, before the refusals existed a property the lowering could not
read was dropped without a word, so a program half-converted to the new spelling compiled and
silently lost the work. Consuming the form whole also keeps one dead line to one complaint, instead
of a cascade of recovery errors after it. No fenced fossil example on this site may spell one: a test
walks every `.fossil` file and every fenced block and fails on a retired form.

## How to repair it

Write the replacement the message names; the `help` carries the reason.

- **A CURIE or a `prefix` line**: delete the `prefix` line and write bare names. A constant IRI goes
  in a string, `"http://xmlns.com/foaf/0.1/name"`.
- **A leading dot**: qualify it with the row the mapping reads `from` — `User.email`.
- **A backtick string**: use double quotes. A hole is `{expr}`, not `${expr}`.
- **`|>`**: put the receiver to the left of the dot, `User.name.trim()`.

A retired key such as `ex:name = …` is also reported as
[`syntax/invalid-property-name`](/docs/errors/syntax/invalid-property-name); one fix clears both.
