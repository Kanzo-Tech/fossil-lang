# ADR 0007: Cap CSVW Metadata Vocabulary support at a literal-`@context` JSON-LD subset

**Date:** 2026-05-19
**Status:** accepted — §"Construction shape" (the `&'static str` name bridge) superseded by ADR-0047
**Decider:** Ángel Iglesias
**Cite:** `.planning/phases/03-bidirectional-type-checker-shex-target/03-RESEARCH.md` §"Standard Stack" + §"Code Examples — Example 3"; <https://www.w3.org/TR/tabular-metadata/>; `crates/fossil-descriptors-input/src/csvw.rs`

## Context

Phase 3 CORE-05 requires Fossil to read a CSV-source descriptor and propagate
the static type of each column forward into the mapping body, so that an
expression like `users |> filter(.age >= 18)` can type-check `.age` as
`Integer` and so that SC#1 ("typo on a column name surfaces a did-you-mean
diagnostic") can fire on the column-resolution path. The descriptor format
mandated by the design corpus and by `.planning/PROJECT.md` is the W3C
recommendation *Metadata Vocabulary for Tabular Data*
(<https://www.w3.org/TR/tabular-metadata/>), commonly abbreviated CSVW.

CSVW is a JSON-LD-based specification. A full CSVW implementation must follow
the JSON-LD 1.1 processing model — context resolution against remote IRIs,
term-alias maps, type-coercion contexts, scoped contexts, embedded vs.
external contexts — easily ~thousands of lines of code plus a
`reqwest`-style HTTP-fetching dependency, which would break the WASM gate
hard rule in `CLAUDE.md` (the playground and `fossil-wasm` must build for
`wasm32-unknown-unknown`). Beyond the gate, JSON-LD context resolution
introduces a runtime network-dependence that has no analogue in the rest of
the compiler.

A 2026-05-19 audit (RESEARCH.md §"Standard Stack") confirmed that no Rust
crate implements CSVW directly. The closest neighbours are JSON-LD parsers
in `sophia` / `oxigraph`, both of which are designed for general RDF graph
construction and are over-engineered for Fossil's use case: Fossil only
needs a column-name → datatype lookup table.

The forces in tension:

- **Spec fidelity.** Users with CSVW descriptors generated by third-party
  tools (Frictionless, CSVW-validator, custom JSON-LD-aware exporters) will
  send us inputs with array-form `@context`, nested term contexts, or
  type-coercion maps.
- **Compiler simplicity.** A thin descent parser over a documented subset
  is ~300-500 LOC and zero new transitive WASM hazards. A full JSON-LD
  context resolver is ~weeks of work plus a perpetual maintenance tax.
- **WASM gate.** Non-negotiable per `CLAUDE.md`; `reqwest` / `surf` /
  `ureq` / any HTTP client breaks it.
- **Diagnostic clarity.** Silent failures ("we ignored your custom context
  alias") are worse than loud rejections ("we don't support array-form
  @context; rewrite as the literal string").

## Decision

We will support a minimum-subset of the CSVW Metadata Vocabulary, hand-rolled
over `serde_json`, with explicit rejection of anything outside the subset.
The cutoff is the boundary at which a real JSON-LD context-resolution engine
would otherwise be required.

### What's IN the v0.1 subset

- **`@context`** MUST be exactly the literal JSON string
  `"http://www.w3.org/ns/csvw"`. Array form, object form, or any other IRI
  is rejected at parse time with the structured
  `DescriptorError::JsonLdContextNotSupported` variant carrying a fix-up
  hint in its message.
- **`url`** (optional). Recorded on the parsed descriptor for diagnostics
  but not validated against the filesystem at parse time (validation happens
  later, when the runtime opens the source).
- **`tableSchema.columns[]`** (optional, but the common case). Each column
  carries:
  - **`name`** (required) — the identifier the Fossil mapping references
    via field-projection (`users.age` resolves to the `age` column).
  - **`datatype`** (optional) in two forms:
    - String form: `"string"`, `"integer"`, ..., optionally with `xsd:`
      prefix (stripped at lookup time per W3C tabular-metadata §5.11.1).
    - Object form: `{"base": "..."}`. The `format` sub-field is recognised
      by the spec but IGNORED in v0.1 (facet checking is a Phase 4 concern,
      see CORE-09 / ROADMAP §Phase 4 SC#4).
  - **`titles`** (optional, string / array / language-keyed object). The
    field is deserialised but UNUSED for resolution per the W3C spec
    (display-only).
- **Allowed datatype names** map to the 9 xsd-aligned `Primitive` variants
  in `crates/fossil-hir/src/ty.rs` per `type-system.md` §2:

  | CSVW datatype                                                                                                                          | Primitive  |
  |----------------------------------------------------------------------------------------------------------------------------------------|------------|
  | `string`                                                                                                                               | `String`   |
  | `integer`, `long`, `int`, `short`, `byte`, `nonNegativeInteger`, `positiveInteger`, `nonPositiveInteger`, `negativeInteger`             | `Integer`  |
  | `decimal`, `float`, `double`, `number`                                                                                                 | `Float`    |
  | `boolean`                                                                                                                              | `Bool`     |
  | `date`                                                                                                                                 | `Date`     |
  | `dateTime`, `dateTimeStamp`                                                                                                            | `DateTime` |
  | `time`                                                                                                                                 | `Time`     |
  | `gYear`                                                                                                                                | `GYear`    |
  | `anyURI`                                                                                                                               | `AnyURI`   |

  Unrecognised names produce a structured `DescriptorError::UnknownDatatype
  { column, datatype }` diagnostic and the column is typed as `Ty::Error`.
  This is NOT a silent String fallback.

- **Unrecognised top-level fields** are tolerated (no
  `#[serde(deny_unknown_fields)]`) so future CSVW extensions parse rather
  than fail.

### What's OUT

The following forms are recognised by full CSVW implementations but are
explicitly NOT supported in v0.1. Each is either rejected with a structured
diagnostic or silently ignored as documented:

- **JSON-LD `@context` resolution.** No remote IRI fetch; the in-band IRI
  string is treated as an opaque literal that must match exactly.
- **Array-form `@context`** (e.g. `["http://www.w3.org/ns/csvw", {...}]`) —
  rejected with `JsonLdContextNotSupported`.
- **Object-form `@context`** with inline term definitions — rejected.
- **CSVW facet checking** (`length`, `minLength`, `maxLength`,
  `minInclusive`, `maxInclusive`, `minExclusive`, `maxExclusive`, `pattern`,
  `format`) — deferred to Phase 4 CORE-09 (lowered to runtime SQL assertions
  per ROADMAP §Phase 4 SC#4).
- **Foreign-key / primary-key declarations** (`foreignKey`, `primaryKey`)
  — deserialised silently as part of the tolerated-unknown-fields rule but
  ignored.
- **Multi-table CSVW** (`tables[]` at top level) — out of scope; Fossil v0.1
  consumes single-table descriptors.
- **Inheritance from parent metadata documents** (the `@id` / inherited
  schema chain in CSVW §5.4) — out of scope.

### Construction shape

`crates/fossil-descriptors-input/src/csvw.rs` provides:

- `CsvwMetadata`, `TableSchema`, `Column`, `DatatypeForm` —
  `serde::Deserialize` derives.
- `CsvwDescriptor::parse(&[u8]) -> Result<Self, DescriptorError>` —
  serde-driven parse + `validate_context`.
- `CsvwDescriptor::type_for_column(&str) -> Option<&'static str>` — returns
  the canonical `Primitive` variant name.
- `datatype_to_primitive_name(&str) -> Option<&'static str>` — the raw
  lookup function, exposed for unit tests and for the plan-03-05 checker's
  use when it has a column's datatype string in hand.

The string-name lookup (rather than returning a `Primitive` or `Ty<'db>`
directly) avoids a circular dependency `fossil-descriptors-input` ↔
`fossil-hir` and keeps the descriptor crate free of Salsa types. The
string→`Primitive` conversion lives in `fossil-hir/src/infer.rs` (plan
03-05).

## Consequences

**Positive**

- Parser is ~380 LOC of straight-line serde-derive code + 18 unit tests
  covering every datatype, both object/string forms, the `xsd:` prefix, the
  three rejection cases, and the four `type_for_column` edge cases.
- Zero new transitive WASM hazards. `serde` + `serde_json` are already
  declared at the workspace level and are WASM-compatible.
- Fast to implement (single Wave-1 plan). The bidirectional checker (plan
  03-05) can consume `CsvwDescriptor::type_for_column` on day one.
- Diagnostic shape is loud and structured. `DescriptorError` gained four
  new variants (`MalformedJson`, `JsonLdContextNotSupported`,
  `UnknownDatatype`, `MissingTableSchema`); each carries enough data to
  produce a precise miette diagnostic.

**Negative**

- A user with a vendor-generated CSVW descriptor that uses array-form
  `@context` must hand-edit it before Fossil will accept it. The
  `JsonLdContextNotSupported` message explicitly suggests this:
  "array/object-form @context not supported in v0.1; use exactly
  `"http://www.w3.org/ns/csvw"`".
- CSVW facets (`minInclusive`, `pattern`, ...) are parsed-and-discarded in
  v0.1; users who relied on facet declarations for runtime validation will
  not get them enforced until Phase 4 CORE-09. This is documented in the
  module-level doc-comment on `crates/fossil-descriptors-input/src/csvw.rs`.
- The `xsd` integer-family aliases (`long`, `int`, `short`, `byte`, ...) all
  collapse to `Primitive::Integer` and the numeric family
  (`decimal`/`float`/`double`/`number`) all collapse to `Primitive::Float`.
  Refinement (signed-vs-unsigned, fixed-width, precision/scale) is
  out-of-scope for Milestone 1 per RESEARCH.md §Q4.

**Future-extension path**

When JSON-LD context resolution becomes necessary — currently no signal that
it is — we have two options:

1. Depend on `oxiri` for IRI resolution + write a context resolver that runs
   only on native (`fossil-cli` / `fossil-runtime`). The playground would
   gate on a literal-context check at the WASM entry-point. Estimated cost:
   ~1-2 weeks.
2. Depend on a future Rust CSVW crate if one materialises. We will need to
   re-audit the dependency tree against the WASM gate at that point.

This ADR supersedes nothing. ADR-0002 (15-crate layout) implicitly assigned
CSVW handling to `fossil-descriptors-input`; this ADR fills in the
"how-much-CSVW" question for v0.1.
