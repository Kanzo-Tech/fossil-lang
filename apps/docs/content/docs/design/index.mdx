---
title: What fossil is
description: A statically typed language that turns tabular and RDF sources into a graph, where the types of the input and the types of the output are made to meet — and if it compiles, it is correct in its types.
---

fossil is a statically typed programming language, written in Rust, that turns tabular and RDF
sources into an RDF and property graph. Its thesis is one sentence:

> **If it compiles, it is correct in its types.**

That is a claim, not a slogan, and what makes it one is where the types come from. They arrive from
two ends and are made to meet.

## Two ends

**From the source.** A type provider reads the actual file — a CSV, a Parquet dataset, an RDF graph
— at compile time and generates the type its columns have. Nothing is declared by hand and nothing
is guessed from a filename, so `User.age` is a checked member of a type the compiler generated by
looking at the data, and `User.nmae` is a squiggle in your editor rather than a null in a graph.

**From the output.** An RDF shape document — ShEx or SHACL — declares, per class, which predicates a
node carries, with what kind of value and how many of them. That is a constraint table, and a
constraint table is a type. It is the target type of every mapping that claims to produce that
class.

**Where they meet is the property assignment.** Every line of a mapping body puts a value from the
left-hand end into a slot declared at the right-hand end. Checking runs in both directions at once:
information flows forward from the row type and backward from the constraint table, and the
compiler's job is that the two agree at every one of those lines. A mapping that could violate the
shape does not compile.

The consequences run in both directions too. There is nowhere in a fossil program to write a type,
because both ends of every type already exist as documents somebody else maintains. And **you
declare no functions**: the standard library is polymorphic and higher-order, and a program is a set
of declarations, not a script.

There is no build step and no artifact you handle. You point a program at its sources and its shape
document, and you get a graph.

## And one page underneath three of them

Three of those six are meaningless without the thing in the middle. A mapping is not a template
with holes in it; it is an expression in **an algebra of graph construction**, with fourteen
operators, each carrying a schema, and a schema is the thing a type can be attached to.
