title: Type providers
description: Compile-time metaprogramming that generates a source's type by reading the source. The lineage is F#, the registry is `io`, and the naming rule fossil takes from F#'s own published criterion is the one F# did not apply to itself.
---

A fossil program never declares the type of its input. It names the input, and the compiler goes and
reads it.

```
User := io.csv("data/users.csv")
```

That line does two things at compile time. It reads the file on disk and **generates a type** whose
members are the file's columns with the file's types; and it binds `User` to both that type and the
relation of the file's rows. From then on `User.age` is a checked member access, and the compiler can
say `User.nmae` does not exist because it has the real list.

## Provider, not loader

A loader runs when the program runs. It hands back rows, and whatever the program says about their
shape is an assertion checked — if at all — against the data at run time.

A type provider runs when the program is *compiled*. It is metaprogramming: a component the compiler
invokes during checking, whose output is types. There is no run-time step where the shape gets
confirmed, because there is no moment at which the compiler did not know it. That is what makes a
misspelled column a squiggle in the editor rather than a null in a graph.

The lineage is F#'s `ITypeProvider`, and every design in this space since is a variation on the same
question: what if the schema of the world could be a type, generated on demand, with no code
generation step the programmer maintains?

## `io` is the registry

`io` is the namespace where providers live — `io.csv` for delimited files, `io.shex` for a shape
document, one entry per family of source. **Adding a format is a row**: not a grammar production, not
a new binder, not a change to the checker. That is not a separate property from the verb catalogue
and the generic standard library; it is one property seen from three sides, and
[the dot](/docs/design/the-dot) is where it is argued.

## One binding, both the type and the relation

F# separates the two, and is right to: a `CsvProvider<…>` gives a type, `.Load(path)` gives data of
that type, because the type is meant to be reused across many files of one shape.

In fossil a binding **is** one concrete source. There is no population of other files sharing
`data/users.csv`'s type, so splitting would produce two names where one suffices. One name yields
both — `User` as a type whose members are the columns (`User.age`), and `User` as a relation whose
rows are the rows (`from User`) — and which one you get is decided by what you ask for, which is the
general rule [the dot](/docs/design/the-dot) states.

## The naming rule

A derived name depends on the label and nothing else: never on cardinality, never on the kind of
value, never on position, and with no plural-to-singular heuristic anywhere.

That is not first-principles reasoning. It is FSharp.Data's own published criterion — a provider must
avoid anything that lets **a small change in the sample cause a large change in the provided types**
— applied to the three places their implementation broke it.

| situation | fossil | F#, and what it cost |
| --- | --- | --- |
| two labels give one short name | an error naming both origins, repaired in the program | a numeric suffix, `PascalCase2`, so a member's name depended on which *other* members existed |
| a label looks plural | the last segment of the predicate IRI, verbatim | a singulariser over English morphology, which produced `Purchasis` and `Sourcis` |
| the source changes between releases | a name moves only when its label moves | a minor version bump renamed members and broke a production application |

The citation is the *Types from data* row in [prior art](/docs/design/prior-art); automatic
disambiguation is [discarded](/docs/design/discarded) with what would bring it back.

It lives in the program rather than in the document being read for one plain reason: **the vocabulary
may not be yours.** A local naming problem must not become an edit to a document other people share.

## Why the provider is named inside the program

F#'s documented damage is about liveness, not location. Schema drift is invisible until something
forces a re-read; the invalidation signal is respected by the IDE and ignored by the batch compiler;
a network outage becomes a compile failure. Every one of those asks *when the world is read*, not
*where the reading is declared*, and F#'s own answer moved the anchor into the program.

Outside does not come out better. `sqlx` needs a live database at build time and fixes it by
anchoring rather than relocating — a prepared artifact, committed. Diesel keeps a generated schema
file and pays two sources of truth. C# studied providers and shipped source generators instead:
additive only, over the compilation rather than over the world. The systems that get this right split
it the same way, name inside and location outside, from Cap'n Proto's include path to Go's module
path with a hash in a lock file.

Two rules fall out of that. **No network at compile time** — reading a file is a provider's job,
resolving a name over the network during a compile is not, and the registry that invites it is
[discarded](/docs/design/discarded) with the outage that settles it. As an editor suggestion, offered
and ignorable, it is a different thing.

**A provider needs a channel for warnings.** F# providers have none: every diagnostic is an
exception, so a provider's only two moods are "fine" and "the build stops". Anything that wants to
say *this file has a column I cannot type, and here is what I did about it* needs somewhere to say
it, decided at design time rather than discovered at the first partial success.

## What it costs

**The editor.** F#'s live pain is not the batch compiler, it is the IDE: providers re-running under
an editing loop, sustained high CPU, maintainers describing the mitigation as a band-aid over a more
fundamental architectural issue. A provider whose input is a file rather than a network call escapes
most of that — "most" is not "all", and the residue falls on
[the editor](/docs/design/tooling-for-humans), which is where the benefit falls too.

**Staleness.** A generated type is only as current as the last read. Every system in this family
answers that as a design decision about anchoring rather than as an optimisation. The answer belongs
next to the compiler; the obligation to have one belongs here.
