title: What was discarded
description: Every rejected alternative in one table — the idea, why it is attractive, the evidence against it, and the observation that would bring it back.
---

Every decision has a shadow: the thing that was not done. A shadow recorded without what would
reverse it is a graveyard, so every row here carries four fields, and an entry that cannot state the
last one does not go on the page. That is the admission rule, and it is what stops this becoming a
list of things somebody once disliked.

This is the one page here you are expected to search rather than read. Where the evidence is a
paragraph rather than a number it sits in an accordion under the table, titled with its row.

## The algebra and the checker

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Rewriting the operator tree before it is lowered — filters pushed down, redundant projections eliminated, constants folded | It is what a compiler middle-end is *for*, and each rule is individually correct | It optimises twice, in the layer with less information: the engine underneath sees the whole plan plus statistics the middle does not have | A transformation that depends on something only the type layer knows and the engine cannot recover from the SQL it is handed |
| Typing a join's `on` condition by running the body checker over it and requiring `Bool` | One rule rather than two, and it catches every malformed condition rather than only the equality | An ordering: the row algebra runs before the body checker and produces its input, so the synthesiser would need its own output as its input. Building it means a second expression typer, over a scope rather than a row. The plan builder already destructures the condition into `equality of two column references` and refuses everything else structurally | A join condition that is legitimately not a single equality — a range join, a conjunction of two keys, a function call on one side |
| `distinct(on = …)` — `DISTINCT ON`, keeping one row per group of key columns | It is what the catalogue row already declared, `DuckDB` and DataFusion both have it, and it is the only form of the verb that is more than a de-duplicate | Which row survives a group is arbitrary without an `ORDER BY`, and `sort` has no lowering to write one with. Every conformance artefact is compared byte for byte and the corpus is written from these rows, so the same program would pass and fail across two runs of itself | `sort`, lowered. The order is the whole of what is missing: with it the pick stops being arbitrary and the row can be declared |
| Width subtyping on records | What most structural type systems do, and projections compose without ceremony | None was needed: no program required it, and the invariant rule is simpler to explain and to check. A decision to stay narrow, not a rejected argument | Partial-row projections flowing through the standard library, where a caller legitimately holds a wider row than the signature asks for |

## Type providers

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Declaring the source's schema outside the program — a flag, an attached file, a host setting | A schema feels operational, and one program can be pointed at several environments | The documented damage in that family is liveness, not location, and the systems that moved the declaration out did not come out better: one needs a live database at build time and fixes it by committing an anchor, another keeps a generated schema file in the repository and pays for two sources of truth. Decisive on its own: a program whose meaning changes with an external flag is not self-contained | A host that must compile one unmodified program against two schema revisions and legitimately cannot express that as two programs |
| Disambiguating a derived name automatically — a numeric suffix, a singular/plural heuristic | The build never breaks on a naming accident | The most mature implementation of derived names published the criterion that condemns it: avoid anything that lets a small change in the sample cause a large change in the provided types. Its own collision scheme was a numeric suffix, so a member's name depended on which other members existed; its singulariser produced `Purchasis` and `Sourcis`; and a minor version bump renamed members and broke a production application | A real vocabulary where collisions are the norm rather than the exception — at which point the short name has stopped being the name, and the scheme needs rethinking rather than patching |
| Resolving an unknown namespace prefix over the network at compile time | The public registry exists for exactly that, and it removes a declaration | That registry served an expired certificate for seven months while every IRI it abbreviates continued to answer. IRIs are durable; the abbreviation layer over them rots, and a compile that depends on it inherits its uptime | Nothing, at compile time. As an editor suggestion — offered, ignorable, never load-bearing — it is a different thing and was never rejected |

## Inference from shapes

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Making SHACL the language the contract is written in | SHACL is a W3C Recommendation with an active working group; ShEx's standardisation moved elsewhere. On standards-body health alone it is the safer bet | The axis is expressiveness, not prestige: the available SHACL path carries neither the one-versus-one-or-more distinction nor closure's three states — see below | Three conditions, none of them an argument — see below |
| Deriving the shape document from the mapping | It is free, it never disagrees with the mapping, and it produces a document where there was none | It never disagrees *because it was computed from the mapping*: an after-the-fact description of whatever the mapping happened to do, typos included. A contract that cannot contradict you is not checking anything | A workflow where nobody has a shape and the produced graph really is the specification — where the generated document is documentation rather than a contract, and is labelled as such |

<Accordions>
<Accordion title="Making SHACL the language the contract is written in">
A contract that does not distinguish **one** from **one or more** is not the contract being asked
for, and closure has three states rather than two. The available SHACL path could carry neither,
while the ShEx path already is a contract end to end: it types the input side, it is read by the
checker, and the same document describes the output.

What brings it back, in three:

1. A client arriving with a shape document that already exists and that nobody is going to rewrite.
2. SHACL reaching Recommendation with the triple-term node kind in it **at the same time as** a real
   RDF 1.2 producer in the corpus — both, because the node kind without the producer checks nothing.
3. A shape that needs a disjunction, where the current advice to split it into several mappings is
   going to sound absurd the day the shape was written by somebody else.
</Accordion>
</Accordions>

## The standard library

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Growing the catalogue ahead of the programs | Cheaper to design the general case once than to generalise later | One error repeated at nine scales in this project's own history: the abstraction was written before the second implementation existed — extension points with one implementation and no dispatch, operators defined and mostly unreachable, catalogue entries no program could call. The aggravating factor is that it was documented as finished, so intent stopped being distinguishable from state | The second implementation. That is the whole rule, and it is a condition rather than a judgement |
| Plugins, as wasm modules or dynamic libraries | The standard answer to extensibility, and it scales past the maintainers | Measured in three projects that did it: one editor maintains ten simultaneous ABI versions; one database maintains a signed matrix of six platforms per release; one compiler paid for openness with `Unknown` variants in every enum of its syntax tree, permanently. An in-tree registration list delivers the entire benefit at zero ABI cost | A consumer who genuinely cannot merge into the tree. It is a door that opens later, and opening it later costs nothing that opening it now would have saved |
| Moving the standard library into `catalogue.bnf`, where the `io.` rows already live | The consistent answer, and the file already has a parser, five projections and a drift check waiting | Swift's `.def` files carried 1,364 rows with no generator at all before anyone reached for TableGen, and Clang left `.def` at around 6,000; the stdlib is fifty-one, two orders of magnitude below where a file starts paying (`crates/xtask/src/reference.rs:17`). That same file already generates a page from the Rust table with no `.bnf` in the path, which is the proof in the tree that generation does not need the file. And the one justification a data file has that a table does not is a second authoring audience: it is why `rust.ungram` exists, `catalogue.bnf` never claims one, and fossil has none | That second audience appearing. Not row count on its own, and not consistency with the `io.` half, which is in a file for a different reason: its BEHAVIOUR half is linked by a host that may not have it |
| A uniform `HirSourceOp { op, args }` instead of typed variants | Thirteen declared verbs against five constructible variants is an asymmetry, and the uniform shape makes `lower_source_stage` end without a `match` at all | It trades a compile-time guarantee for a runtime unwrap: `args[0]` expecting a predicate is checked by nobody, where `Where(HirExpr)` cannot hold a column list (`crates/fossil-hir/src/lower.rs:119`). It is the fork rustc and rust-analyzer took opposite ways over the same table — rustc's `[Option<DefId>; N]` costs it a discriminant coupling, a `from_u32` its own comment calls *"clumsy"* and a `panic!`-enforced bijection, where rust-analyzer's one typed field per row has none of the three. The surviving `match` is construction rather than dispatch: five arms, exhaustive | Enough lowered verbs that the typed variants stop being writable by hand — the constructible set overtaking the declared one, which is the opposite of today's eight declared and not lowered |

## The surface

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Borrowing the comprehension binder for the source binding | Instantly familiar, and it reads as "drawn from" | In the languages it would be borrowed from, the specification defines the left side as an element and the right side as the collection. Here the left side names the relation, so the borrowed glyph would say the opposite of what it means. It already means assignment in one widely-read language and channel receive in another, no language was found in which it means "produced once per element of", and it flows right-to-left in a program whose pipelines flow the other way | A form where the left-hand side really does denote one element rather than the relation — an iteration construct, if one is ever needed |
| The anonymous row: drop the receiver's name and write bare `.field` against an implicit current row | The shortest possible spelling of the most common expression in the language, and several query languages start there | A table with no counterexamples, and a failure mode that is silent and triggered by data rather than by code — see below | A source model with genuine hierarchy to descend, where the context item earns its cost. An implicit context item optimises for hierarchical navigation rather than for joins, and tabular sources are all joins |
| Renaming silently when a join collides — suffix the shared column, as the mainstream data frame libraries do | The join always succeeds and nobody has to think about it | The same failure mode as the anonymous row — triggered by the data, invisible in the code — and the libraries that do it by default only raise when the suffixes are turned off by hand | The other defensible option was never rejected on merit: flatten and require qualification, which is what SQL does. It becomes the answer the day a row carrying two `id` columns is what readers expect to see rather than something to be protected from |
| Letting a program omit its shape document and checking only the source side | The gentler on-ramp, and for a while it was the rule — a program with no shape was explicitly not an error | It stopped being coherent the moment a property key became a bare name. A bare key takes its name from a predicate a shape declares, so with no shape there is no name for a property to have: `TypeckOutput.predicates` is empty (`crates/fossil-hir/src/check.rs:94`), every property fails to lower, and the program reports success having written nothing | A second source of predicate names — a vocabulary the program names directly rather than through a shape. Until it exists, the permissive reading is not a relaxation but a program that silently produces nothing |
| The outer join, and the rest of the variants | The ordinary set, and their absence looks like an omission | An outer join fabricates nulls, and a corpus whose contract asserts that a property is present is a corpus into which a fabricated null must not be written | Its nullability story, and it arrives with one or it does not arrive: a rule that lets a fabricated null land only where `Occurs` does not demand one or more (`crates/fossil-hir/src/check.rs:609`), so the corpus never asserts a property it invented |
| The RDF 1.2 triple term — `<< s p o >>` as a value, with a reifier as an ordinary mapping | The standards-track answer to annotating a statement, and the corpus already writes the edge row a triple term would have to name | Nothing in RDF 1.2 is a Recommendation: Concepts and Semantics are Candidate Recommendations, every concrete syntax is still a Working Draft, Turtle 1.2 in its fourth. The surface did not fail to arrive, it left — `<<` is not a token and `grammar.bnf` carries the retired rule's tombstone rather than a pending one. `rdfs:Proposition` appears nowhere under `crates/`, and the one place a triple term is handled reduces it to its surface form because it has no identity to key a row by (`crates/fossil-df/src/rdf.rs:154`). That the Turtle parser accepts one on the way in was never decided either: `oxttl`'s `rdf-12` arrived by feature unification, and since 2026-08-07 it is declared instead of inherited, with a literal carrying a base direction refused at the pivot rather than flattened into text a host lays out backwards. Both are guards over what arrives; neither is a step towards a surface | Turtle 1.2 reaching Recommendation, and a program that wants to annotate an edge and cannot |

**Retired, not rejected.** *A join whose two keys have different names* sat here with the criterion
*"the first real mapping whose two keys do not share a name — not an argument, a program somebody
wants to write and cannot."* It was met. The MIR carries the binding, so a column reference says
which side it is, and two differently-named keys plan as an ordinary equi-join
(`crates/fossil-df/tests/pipeline.rs:272`). Measuring it also turned up what nobody had seen: under
the algebra as declared, two ordinary tables could not be joined **even with a qualified condition**,
because they share a primary-key column name and any shared name was an error — an unmeasured
consequence prohibiting the join of any two tables with primary keys.

<Accordions>
<Accordion title="The anonymous row">
Every system that started with an implicit receiver had to add a naming mechanism the moment two
rows were in scope — a context function, an explicit binding form, a variable binder, a pair of role
keywords, a marker annotation, named bindings replacing positional ones — and **not one went the
other way**.

Worse, the failure is silent and triggered by data rather than by code: a path degrades quietly when
the implicit receiver is shadowed, and one language's implicit-scope construct is documented as
having changed the meaning of surrounding code because a record *gained a field*. In a language
whose job is surviving schema drift, that is the worst available failure mode.
</Accordion>
</Accordions>

## Identity

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Identity as an argument to an attribute above the mapping | It is metadata, and attributes are where metadata goes | Seven languages, no exception: none admits a per-instance expression in an attribute argument, and one specification calls the restriction a deliberate syntactic device. The control experiment is the language that does evaluate expressions in attributes — the per-row form compiles, produces one frozen value for every row, and costs its documentation a paragraph warning about a mistake the other languages cannot express | The rule that decides it: if the attribute can be omitted it is forbidden, because omission implies a derived fallback; if it cannot be omitted it is not an attribute but syntax with brackets, and the spelling is then irrelevant. Make it mandatory in every declaration and this becomes a spelling question |
| Letting each mapping mint its own identity, so two mappings producing one type declare different templates | What every mapping language does, and the one federation system that checked it removed the check and published its reasons | The federation case does not transfer: its two keys are alternative ways to locate one entity rather than two identities, and its subgraphs deploy separately so nobody ever holds the whole set — the check here is available precisely because the topology is the opposite. The same property is silently assumed by the academic work, detected but wired only to an optimiser by the one engine that computes it, and guaranteed by construction in the one W3C mapping that derives identity from the table's key rather than from a free template | In order: (1) a legitimate case of disagreement — disjoint populations of one type with no common identity scheme, where one real instance demotes the error to a warning; (2) a topology where fossil composes mappings from independent authorities, at which point the federation argument becomes ours; (3) invertibility, since virtual access over a live source needs the inverse expression and one template per type is not enough for it |

## Streaming, memory and scale

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Distributing the writer across machines | The reflexive answer to "no ceiling" | At the measured density one machine reaches far past the scale that has been measured, and the two mechanisms that extend it — memory mapping and spill — are not exhausted. Distributing first trades a measured problem for a larger unmeasured one | A corpus that exhausts one machine's **disk** rather than its memory |
| Tuning the constants inside the layout — a tighter representation, a bitset instead of a map | The numbers are right there and the change is local | One such attempt regressed by seven gigabytes. And with *no ceiling* as the goal, fifty-three bytes per edge down to thirty does not change the category of the problem; it moves the point where it bursts | A goal that is a ceiling rather than the absence of one: a fixed target machine, where a constant factor is the difference between fitting and not |
| Adopting a community-detection library instead of the hand-written clustering | Nobody should hand-roll a graph algorithm, and one candidate is actively developed | Three independent reasons — flat partitions, 32-bit indices, and re-measurement against code carrying four measurements — see below | A layered-label-propagation implementation with 64-bit indices, a memory-mapped graph and spill to a working directory, written by the algorithm's own author. Its costs are equally specific — see below |
| Adopting a space-filling-curve library instead of writing twenty-one lines | The archetype of what should be a dependency | The most-downloaded candidate is a signature-for-signature copy of the local implementation capped at 16-bit two-dimensional coordinates — exactly the ceiling one would adopt it to escape, and the easy mistake precisely because it ranks first. Adopting is not a speed play either: the measured cost in this area is memory and network, not arithmetic | The day the interleaving stops being a detail of the writer and becomes the contract between two repositories — when a reader has to compute the same address the writer wrote. The well-made candidate for that day is generic in the number of dimensions with the output width as an associated type, which is the shape a flat identifier would need |
| Adopting a layout library | Layout is a solved problem with decades of literature | There is nothing to adopt, and that is the finding: no crate implements the placement used here, there is no port of the standard multilevel force layouts, and no layout crate publishes a benchmark above ten thousand nodes. There is a hard licence ceiling independent of technical merit — the best-known force implementation is licensed incompatibly with this workspace, and the only compatible one has a lifetime download count in the dozens | A maintained implementation with a compatible licence publishing a benchmark at the size where this work *starts* |
| Replacing the curve with a better-behaved one | The textbook improvement, and the best-maintained crate in the whole search implements it | Measured on this corpus the hypothesis is false: the improvement did not appear. Adopting anyway would be replacing measured code with code to be measured, against a hypothesis already refuted here | A corpus with a different shape, measured — the refutation is about this data, not about the curves |
| Unifying the two execution engines | Two engines mean two SQL dialects, two configuration surfaces and two sets of behaviour to keep in step | The margin does not pay: the SQL is a small fraction of the slice it sits in, and unifying means rewriting roughly nine hundred lines of query construction as plan construction, adding several megabytes to the read path, and losing the range-request file system that makes reading a corpus over HTTP work at all | The read path no longer needing range requests over plain HTTP — which would be a different product |
| Reusing one sparse accumulator in `local_moving` instead of a `HashMap` per vertex per sweep | A few hundred million transient allocations at ten million vertices, in the one step that bills +3.91 GiB while demonstrably *holding* 160 MB. It is the obvious reading of that gap, and the rewrite gives bit-identical output by construction | It goes the other way, measured twice and reproducing exactly: Louvain **225.7 s → 126.2 s** (1.78×, which the pass badly wants) and the process peak **8.82 → 9.20 GiB** against 90 MB of arrays added. It spends 0.38 GiB of the one quantity `--memory-gib` bounds to buy wall clock that was not the objective — and it leaves the residue unexplained, so it is not even the fix it looked like | The level-zero rewrite. Once Louvain stops holding the graph, the 90 MB is free and the 1.78× is unopposed. Or a run that declares a *time* budget, where the trade reverses on its face |
| Honouring the layout budget by degrading — fewer hierarchy levels, coarser tiles, a two-pass placement | It is what an engine does under pressure, and it turns a refusal into a slower success rather than no corpus at all | `fossil run` and the playground tab write the same tree byte for byte through one `LayoutIo`, and only one of them has a flag to declare a budget with — so a budget that changed the output would make the two paths disagree *exactly when* somebody declared one. There is also nothing to degrade into: the pass holds Rust `Vec`s and has no spill directory, so "coarser" means a different corpus and not a slower one | A declared budget on the browser side too. With both paths given the same number the degradation is the same degradation, the identity survives, and the choice becomes a real one |

<Callout title="The thread through the three adoption rows">
The ecosystem ends almost exactly where these sizes begin. No layout crate benchmarks above ten
thousand nodes; no maintained community-detection crate exceeds 32-bit indices; the most popular
curve crate stops at 16-bit coordinates. The small corpus here is ten million. That is not a
preference for local code — it is that the frontier of what can be bought falls below the starting
point, which is why what *is* bought is always small and verifiable and never large.
</Callout>

<Accordions>
<Accordion title="Adopting a community-detection library">
**Functionality.** Every level of the hierarchy is what earns this structure its place, and every
candidate returns a *flat* partition, which would leave the functions that consume it with nothing.

**Scale.** The maintained ones are capped at 32-bit indices, and one candidate's own published table
does not improve on what is already measured here; swapping one resident implementation for another
moves the point where it bursts rather than removing it.

**Re-measurement.** Adopting means trading measured code carrying four separate measurements for
something whose memory profile on this corpus is unknown — and the failure mode is on record, since
a correct rewrite in this exact area passed every parity test and regressed seven gigabytes.

The named candidate is a measurement to schedule rather than a dependency to add: it is label
propagation rather than modularity, so the compactness that justified keeping the hierarchy has to
be re-measured from zero; it requires a symmetric loopless graph; it still needs roughly twenty-five
bytes per node resident, which is twenty-five gigabytes at a billion; and it wants a second on-disk
format, which collides with "Parquet and nothing else".
</Accordion>
</Accordions>

## The privacy bound

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| A read-time gate: withhold `execute_sql`, or mask a column behind the query verbs | It is what a database does, and it is the shape every reviewer expects | There is no chokepoint to put it on. A recipient holds the Parquet, and `read`'s `where` is a raw SQL fragment evaluated by the same engine, so gating the escape hatch leaves the same surface with a second door. The systems that genuinely do this — Snowflake's masking and row access policies, BigQuery's column ACLs and row-level security, Databricks' equivalent — all apply it **inside the query planner**, below the query language, which is the position a file format does not have | A **served** corpus: the operator keeps the files and the only access is through their engine. That is a chokepoint and a different product, with a trusted operator and a budget that runs out as its price |
| Putting the classification in the shape document, as ShEx or SHACL annotations | The shape already enumerates every predicate, both languages have annotation mechanisms, and it is one document instead of two | It destroys the reuse of the shape. A shape says what a `Person` is — predicates, cardinality, datatype — and that holds in every jurisdiction; whether `birth_year` is a quasi-identifier depends on the release, the recipient and the regulator. The result is one shape per deployment differing only in annotations, which is how a vocabulary stops being shared | A deployment where the shape is genuinely not shared — written for one release, by the same people who wrote the policy, and never handed to anybody else. At that point the two documents have one author and one lifetime, and the second buys nothing |
| An anonymisation operator in the standard library — `anon.generalise`, `anon.mask` | It is the direct expression of the thing, it is easy to implement, and it puts the author in control of the trade-off | An obligation discharged by remembering to call a function is one that can be forgotten, and the failure is silent at every stage: the program compiles, the corpus writes, the manifest seals, and the recipient finds out. A mapping that does not call a function looks exactly like a mapping that had no need to | A generalisation *search* that the author has to steer — where the choice between recoding `postcode` and dropping `birth_year` is a judgement no solver can make, and the operator is how the judgement is written down. It comes back as an input to the search, never as the thing that discharges the obligation |
| A fractional null-contribution parameter, following sdcMicro's `alpha` in `[0, 1]` exactly | It is the field's own idiom, it is a continuum rather than three arbitrary points, and it subsumes all three | A fractional contribution produces a fractional `k`, and every number in this block exists to be re-derived from the bytes by a stranger. Three integers a `GROUP BY` can produce are checkable; `alpha = 0.4` is a number two implementations round differently | A recipient who needs the intermediate readings — at which point the manifest publishes `alpha` and the reached `k` as a rational, and the guard is rewritten to compare exactly rather than numerically |
| Recording the suppression as "records the writer chose not to emit" rather than as visible null cells | It is what suppression means in the literature, and it covers record suppression as well as local | A record that was never written leaves no trace, so no recipient can check it and no guard can be written for it — the same argument that keeps the dropped-edge count off the edge manifest. A budget a reader cannot check is not a budget | A corpus that carries its own input census — a declared count of what was read against what was written. That is a different field with its own argument, and it would make record suppression checkable for the first time |
| A registry of named hierarchies — `fossil:ukPostcode`, `fossil:age` — as the `rightOperand` of `fossil:generalization` | Short, readable, closed, and it validates at parse time against a list this profile controls | It undoes the reason `fossil-kanon` ships its hierarchies as files rather than constants. A postcode hierarchy is a fact about a country's postcode system, revised by statisticians and not by programmers, and a closed enumeration in a Rust module makes a **recompile** the unit of change for it again. Amnesia ships files; the directory is meant to be the interface | A hierarchy that is genuinely universal rather than jurisdictional — one where a name is a better key than a copy, because every deployment means the same thing by it and nobody should be editing the levels |
| An IRI naming a hierarchy document, fetched at compile time | It is what JSON-LD does everywhere else, it deduplicates a hierarchy shared by twenty policies, and it is one line in the document | It is the one thing the policy reader refuses on principle. A compile-time document whose meaning depends on a host being up is not a document, it is an outage — the same argument `/docs/design/discarded` already carries against resolving a namespace prefix over the network at compile time, and it does not weaken because the thing fetched is a hierarchy | A resolver the host supplies and the compiler never calls — the shape `@conn` already has. The objection is to the *fetch at compile time*, not to the indirection |
| A seventh profile term for a generalisation margin — "derive to `k` times this" — as a minimality mitigation | The minimality attack is real, and deriving to a larger `k` than is claimed is the cheap partial answer to it | `fossil:anonymityK` already expresses it. A producer who wants a table that is not minimal for `k` asks for a larger `k`, and then the number they chose is **published on the artifact** rather than hidden in a multiplier a reader cannot see. A term that duplicates an existing one and hides its effect is worse than no term | A margin that must NOT be visible to the recipient — which is a threat model where the recipient is the adversary and the producer is hiding the strength of their own control. That is a coherent position and it is not this format's |
| Letting the verifier read the deriver's report — the achieved `k`, the class sizes — instead of recomputing | It is already computed, it is exact, and recomputing the same aggregate twice on one corpus is visibly wasteful | The two measurements would then agree **by construction rather than by measurement**, which is what circular means. `fossil-kanon` re-reads its own output, so a deriver that also supplied the verdict would establish only that its code agrees with itself. Two implementations sharing no code is the entire value of the second pass, and the cost is one aggregate over a corpus already resident | Nothing at this seam. If the cost ever bites it is an argument for a cheaper *independent* check, never for reusing the derivation's own answer |
| Generalising some of a shape's quasi-identifiers and publishing the rest as they are | A quasi-identifier already coarse in the source has nothing to generalise, and forcing a hierarchy on it publishes a `*` where a usable value was safe | The deriver reaches `k` over the columns it was handed and the verifier measures the columns that were **published**; classes over more columns are never larger, so a partial derivation optimises for a tuple nobody checks. It fails safe — the verifier refuses — but for a reason neither message names, which is the worst kind of correct | An identity hierarchy: a declared level that publishes the value unchanged. Then "already coarse" is expressible *inside* the tuple and the all-or-none rule costs nothing |

## The corpus

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Conforming to an existing graph interchange specification instead of a bespoke layout | Interoperability, for free, with a specification somebody else maintains | It gave vocabulary and stopped giving contract, and conformance was not kept in practice either — see below | A second reader that is not ours, that already speaks it |
| One file per tile, so a request is a file | The addressing is trivial and every request is exactly one object | Measured against the alternative: four times the requests and not one byte saved. A request against a single file is a maximal run of consecutive row groups, and the tiles a window needs merge into a handful of runs — the file boundary is the only thing that prevents the merge | A store where opening a file is cheaper than a range request into a large one |
| A materialised tile tree, with each edge stored at the deepest tile containing both endpoints | The classical answer: it removes the cross-tile case, and interior nodes look like the natural home for it | An interior node earns its existence only by containing something a leaf cannot, and the only candidate costs more to lift than it saves — see below | Nothing declared, but the hole in the measurement is named — see below |
| Leaving *"a binding that gates `execute_sql` must gate `read`'s `where`"* as a doc comment on the type | It is where a binding author reads it, it costs nothing, and three bindings had in fact obeyed it | It is an obligation discharged by remembering, and the page rejects that shape one section down for the anonymisation operator. Nothing could notice a fourth binding wiring one door and not the other. What it would have cost to enforce is now measured and is zero: `RawSql` is `#[schemars(transparent)]`, so the published schemas changed in prose only — the two touched snapshots differ by a `description:` line | Nothing here. If the token ever obstructs a binding, the fix is a second constructor on `RawSqlAccess`, not a return to the comment |
| Parsing `read`'s `where` into a small filter language instead — columns, comparisons, conjunction | The coupling disappears at the root: `where` would stop being SQL, so it would stop carrying `execute_sql`'s authority, and the field could be exposed to callers the hatch is closed to | It is a second query language to specify, implement, document and keep at parity across two engines, and the escape hatch still exists beside it — so the surface gains a language and loses no door. And the thing it would buy is read-time policy, which [the privacy bound](/docs/design/privacy) shows this artifact has no chokepoint for | A **served** corpus, where policy is enforced inside the planner. There the parsed form is what the planner rewrites, and it stops being a second language competing with SQL and becomes the input to one |
| Keeping `Deserialize` on `Operation` and checking the permission afterwards — `fn permitted(&Operation, policy) -> bool` | Every binding keeps `serde_json::from_value::<Operation>()`, the change is additive, and nothing downstream breaks | A binding can forget to call it, which is the same failure class as the comment it would replace, one indirection further from the field. Refusing to *construct* the value is the only version a compiler enforces | Nothing. A check a caller may skip cannot enforce a rule about callers |
| Putting the refusal on the executor — `DuckExecutor` declining raw SQL — rather than on the params | It is the last layer before the engine, so it would catch every path at once, including any future verb | By then there is nothing to catch. `read` builds `SELECT … WHERE <fragment>` and hands over **one string**; the caller's fragment is no longer distinguishable from the SQL the verb generated around it. The seam that can still tell them apart is the params struct, which is where the distinction exists | A verb surface that hands the executor a structured plan rather than a string — the same rewrite [unifying the two execution engines](#streaming-memory-and-scale) is rejected for, and it would be a consequence of that decision rather than a reason for it |
| Capability negotiation for the artifact: a monotonic version plus an unordered set of named capabilities, split into read and write | The mechanism the mature table formats have, and retrofitting it is expensive | There is no problem to solve. Nothing is published and there are no older readers, so a negotiation mechanism answers a question nobody has asked — and then has to be maintained until somebody asks it | The day a corpus leaves this machine towards somebody who cannot regenerate it. The same boundary as publishing the arithmetic test vectors, for the same reason: the enduring cost in this space is files that can no longer be withdrawn |

**A second writer** is not a rejection but a standing reversal condition, recorded because it flips a
decision rather than adjusting one. If anybody produces this corpus without using this
implementation, the priority inverts: the specification becomes the contract and the implementation
becomes one implementation among several. One writer is what makes the library half safe; two
writers is what turned a widely-used columnar format into a reference implementation that became
normative by accident. And the clock runs one way — if the corpus reaches third parties before the
arithmetic is published, the option is gone.

<Accordions>
<Accordion title="Conforming to an existing graph interchange specification">
The specification defines no count and no data-file path, so derivability had to be invented anyway
— and two questions that were declared blocking existed *only* because of conformance. As an
interchange format it does not pay either: a recipient would have to learn an incubating
specification, where self-explaining file names are more interoperable than a specification nobody
has read.

Nor was conformance given up in principle and kept in practice. Every vertex manifest fossil writes
declares `dense_id` as `uint32` (`crates/fossil-df/src/lib.rs:1792`, `vertex_info`), and the
built-in list GraphAr's `types.cc` parses has no unsigned type at all — so its own C++ reader would
refuse the first property of the first vertex type.

What survives as an internal invariant is the good part: the manifest's field names, both adjacency
orientations, dense identifiers, and edges aligned to the source's chunk. The full enumeration —
eight divergences, each one the same rule applied once — is in [what is borrowed from GraphAr, and
where borrowing stops](/docs/design/corpus#what-is-borrowed-from-graphar-and-where-borrowing-stops).
</Accordion>
<Accordion title="A materialised tile tree, holding the edges that cross tiles">
The only thing an interior node could contain that a leaf cannot is the crossing edge, and it is
measured to cost more to lift than it saves. The reads diverge sharply: one placement stays flat as
the corpus grows fifty-fold and the other grows with it, and it loses on request count at the same
time.

The structural cause is that near the root there is no branching left to prune with, so every window
touches nearly every high tile — and every window pays the root whether or not anything in it is
drawn, because a reader cannot know what a tile holds without reading it. That is what addressing
*means*. With nothing to put in them the interior nodes are empty, and the addressing that replaces
the tree is arithmetic on identifiers.

The hole in the measurement: an edge with one endpoint off-screen has a visible segment, and
**neither placement brings it**. Measuring that needs the other adjacency orientation, and it
duplicates the addressing rather than the argument.
</Accordion>
</Accordions>

## Disclosure control

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Flash or Incognito — searching the full generalisation lattice for the optimal recoding | It is the *right* answer to the problem as posed: global recoding, every cell of a column at one declared hierarchy level, chosen by an explicit quality metric rather than by a greedy heuristic | The cost is not the search, it is everything the search needs: a lattice to build, a quality-metric framework to order it by, and predictive tagging to prune it. That is ARX's decade of work, and a port of it is a different project from a port of one algorithm | A caller who needs two releases of the same table to be comparable across *every* column rather than only the levelled ones — at which point the bucketed numeric presentation has stopped being enough and the lattice is what is actually being asked for |
| Datafly, instead of Mondrian | Small, well understood, and it produces hierarchy-level output — which is exactly the property local recoding gives up, and the one the incomparability warning is about | It generalises a whole column at a time, so one dense region of the table drags every other row up a level with it and the release comes out coarser, often far coarser, than multidimensional recoding needs for the same k. The narrower fix was taken instead: `NumericPresentation::EnclosingBucket` recovers declared, comparable values on numeric columns without giving up local partitioning | Evidence that the coarseness does not bite on the tables actually being released — measured on one, not assumed. Global recoding is genuinely simpler to explain to a data-protection officer, and that is worth something the utility numbers do not capture |
| Relaxed partitioning, offered beside strict as a flag | It is in the paper, it balances the partitions when the median value has many duplicates, and every published Mondrian benchmark reports its numbers | It emits equivalence classes below k, silently: dealing the tied records across both sides makes the two spans overlap, so the classes stop being determined by the published values while every row count still looks balanced. A weaker guarantee reachable by a parameter is one reachable by a typo, and the guarantee is the crate | Nothing, as a flag. As a *separate function* with its own return type that does not claim k — a different thing, which was never rejected |
| Treating a missing quasi-identifier as one more distinct value | It is what falls out of a group-by, and it needs no decision | Wrong in the unsafe direction: it collects the records with missing postcodes into a small class of their own and reports it as k-anonymous, when what it has built is a list of the people whose postcode nobody recorded. Disclosure-control semantics make a missing value compatible with *every* value, so it enlarges the classes it could belong to rather than forming one | Nothing. The two readings that remain — publish `*`, or withhold the record — are both offered, with no default, because they give different numbers about the same file |
| `[min, max]` as the only numeric presentation | It is Mondrian's own output and what the literature reports utility against, so an alternative makes this crate's numbers incomparable with every published benchmark | Both endpoints are values a specific record holds. A published `[29, 61]` releases two attributes in full, in the column whose whole purpose was to be generalised, and it is worst where the class is small — which is where k-anonymity puts its attention | It is not gone: `ObservedRange` is still there for exactly the benchmark reason, and choosing it warns on every run. What would make it the *default* is a caller for whom declared buckets are not available and the comparison to published results matters more than the endpoints |
| Defending against the minimality attack | Wong et al. is a real result about exactly the table this crate emits, and "we know about it and did nothing" is an uncomfortable sentence | It is a different algorithm rather than a flag — the m-invariance family — and adopting one would replace Mondrian rather than harden it. Naming the exposure is worth more than a partial defence that a caller would read as a complete one | A caller publishing to an adversary who is known to know the algorithm, which is the condition the attack needs. That is a real threat model and not a hypothetical one; it is simply not the one this crate was built for |

## The tooling

| The idea | Its attraction | The evidence against | What brings it back |
| --- | --- | --- | --- |
| Removing the incremental core from the batch path, which builds an empty dependency database on every invocation | The diagnosis is correct — there is no reuse between invocations — and a borrowed figure from a comparable project reported a 52% improvement from exactly this change | The borrowed figure does not transfer, and there are two structural blocks besides — see below | A profile where compilation stops being microseconds. Half of it is already measured against — see below |
| A subprocess as the embedding surface: a product spawns the binary and reads JSON off its stdout | The cheapest possible integration — no linking, no version skew in the build, no wasm toolchain — and it works on day one for any host that can start a process | It makes the *binary* the API, and the binary is the one host that cannot be embedded where the product actually runs — measured 2026-08-16, see below | A host that cannot run wasm at all, or a corpus whose run genuinely needs facilities `wasm32` does not have — a disk to spill to being the concrete one. Neither is a reason to keep a second copy of a capability the browser already performs; both are reasons for the command line to remain a client |
| A linked Rust type as the contract between fossil and a host: a small, wasm-clean crate holding the wire structs | Genuinely one source of truth, checked by the compiler on both sides, and one lightweight dependency for the host | The crate accumulates unrelated contracts and build machinery belonging to the consumer, and two of its three contracts are consumed from a language that never links it — see below | A host in the same workspace, or one that wants the compiler to enforce the contract at *its* build time rather than at its deserialize time — a real thing to want, and a different argument from the one that put three unrelated contracts in one crate |
| Foldering the crates into `core/`, `extensions/` and `corpus/` | Two dozen sibling directories show nothing, and the grouping the site draws in its dependency diagram would become the grouping on disk | A folder cannot hold a boundary. Every candidate for `core/` is already separated by something real — a cycle, a `cfg`, an orphan rule — so the directory would restate an edge that exists; and `fossil-base`, the one crate whose *contents* are wrong, would be filed rather than fixed. `extensions/` fails the same way: `fossil-shex` sits outside the descriptors because of a cycle, and a folder does not dissolve a cycle. The only grouping that is real today is *compiles to wasm32 or does not*, and six `compile_error!` already enforce it without a directory | A grouping that is not already implied by an edge — one a reader could not derive from `cargo metadata` |
| Lifting `fossil-base`'s `test_support` feature into a crate of its own, the way the locator went | The same rule that moved the locator, applied to the other thing in `base` that is not substrate — and it takes a feature and 339 lines out with it | It cannot compile. A helper crate that implements `System` must depend on `fossil-base`, and `fossil-base`'s own unit tests must depend on the helper — a dev cycle Cargo allows and `#[cfg(test)]` breaks, because the crate under test is a **second copy** of `fossil-base` whose types do not unify with the one the helper linked. Measured on a two-crate spike; the accordion has rustc's words. Sixteen of thirty-two unit tests would have to leave `src/`, and `fossil-base` would shed no dependency for it | `test_support` ceasing to name `fossil-base`'s own types — if what it hands out were only `fossil-graph-schema` values, the helper would not depend on `fossil-base` and there would be no cycle to break |
| Keeping the one generic MCP tool — `dispatch_verb { dataset, operation }` — and typing the envelope better | One tool, one handler, one place to add a verb, and the wire form is already the `{ verb, params }` envelope every other binding speaks | The cost is paid by the caller and it is measured: the envelope schema is **6,604 bytes** and has to be read to make *any* call, against **308** for `path` and **1,536** for the largest of the six. Every call is assembled by picking a discriminant and then rebuilding params underneath it, and six descriptions arrive as one paragraph whatever the question was. It also made "a binding MAY hide `execute_sql`" undeliverable, because a tool cannot be half-registered | A protocol where a client can filter *inside* a tool's schema. The envelope is not the problem — six tools still serialise the same envelope underneath — the problem is that one tool is one unit of selection |
| Six tools each taking `dataset` as an argument, so the server stays stateless | It keeps the existing spawn contract intact, one server can serve several corpora, and nothing has to be configured at startup | It puts back most of what the single tool was wrong about: a field in six schemas that no verb has, which the model must reconstruct identically six times, and which is the largest thing in five of them. A tool's input schema being exactly its verb's `Params` is the entire content of the change | A server that genuinely serves several corpora to one caller — at which point the dataset is a *selector* and not a payload, and the answer is a name resolved against server configuration, not a blob in every call |
| Building the six tools with `rmcp`'s `#[tool]` macro, one function per verb | It is the SDK's own route, the routing is generated; six small handler functions read well | The macro derives against `schemars` 1.x while the verb surface pins 0.8, so each of the six would need a mirror `Params` deriving the other version — six second copies of the wire contract, in the one crate whose job is to not have one. Building the tools from `Verb::params_schema()` crosses the boundary as `serde_json::Value`, which is the only crossing there is, and let the direct `schemars` dependency go entirely | The two versions converging, or `rmcp` accepting a pre-built schema through the macro. Neither changes the shape of the answer: the schema still has to come off the verb |
| Defaulting `--allow-raw-sql` on, to preserve what the generic tool did | The generic tool granted raw SQL because it had no way not to, so leaving it on is the smaller behaviour change | The tool names changed in the same breath, so no caller survives this untouched anyway and the "smaller change" buys nothing. Five verbs cost a function of the answer; this one costs a function of whatever was typed, and a default is what a deployment gets when nobody decided | Nothing. A deployment that wants the hatch says so, and saying so is one flag |
| An unmaintained language-server framework, rather than the low-level protocol library | The obvious choice by search ranking and by API pleasantness | Roughly three years without maintenance, and all three reference implementations in this space use the low-level library instead | Maintenance resuming — and until then the ban is explicit rather than tacit, so reintroducing it takes a decision rather than an import |
| An editor client that consumes semantic tokens | Exactly the missing piece, and two candidates advertise the area | Obtained by probing the packages rather than reading their prose: of twenty-seven exports and seventeen prototype methods in the leading candidate, none matches semantic tokens; the other candidate's semantic-sounding strings are initialisation options passed through to the server, not consumers of a response. The generic request escape hatch does exist and does return the payload | A client that consumes the response rather than forwarding an option — and the transferable part is the technique: probe a package by its exports and its prototype before adopting it |

<Accordions>
<Accordion title="Lifting `fossil-base`'s `test_support` feature into a crate of its own">
Cargo permits a dev-dependency cycle, and half of it works: an **integration** test in `tests/`
links the plain rlib, so it sees the same `fossil-base` the helper crate saw. A **unit** test does
not. `#[cfg(test)]` compiles a second `fossil-base`, and rustc says so exactly:

```text
note: there are multiple different versions of crate `base` in the dependency graph
   |
15 |     use crate::System;
   |         ------------- `System` imported here doesn't correspond to the right version of crate `base`
```

Measured 2026-08-26 on a two-crate spike outside the workspace, reduced to one trait and one impl.
It is not a quirk of the reduction: every `SourceFile`, `Provider`, `System` and Salsa input that
`test_support` hands out is a `fossil-base` type, so every one of them crosses that seam.

The bill, then: sixteen of `fossil-base`'s thirty-two unit tests move out of `src/` into `tests/`
and lose their module's private scope; `test_support`'s own three go with the module; 112 call sites
in 58 files across eight crates change import path; nine manifests change a dev-dependency line.

Against which `fossil-base` sheds 339 lines, one feature — and **no dependency**. Its two path
dependencies are both held by production code: `fossil-graph-schema` by `shape_documents.rs`,
`providers.rs` and `diagnostic.rs`, `fossil-descriptors-input` by `system.rs`. No arrow moves on the
architecture diagram either, because that page reads `[dependencies]` and this is a dev edge.

The rule being applied here indicts what a `base` decides **about a program**. The locator decided
where a written path points, which is a decision about a program, so it left. `test_support` decides
nothing about one, and its own header already said so before this was measured: *"This is not
compiler logic … a format that exists nowhere else and that no program will ever be written in."*
It is a reference implementation of a seam `fossil-base` itself defines, behind a feature no shipped
binary carries.
</Accordion>
<Accordion title="Removing the incremental core from the batch path">
The borrowed 52% does not transfer, and measuring locally says why: that project is a library whose
entire work is compilation, so its percentage of compilation *is* its percentage of the process.
Here compilation is two thousandths of a command dominated by process start-up and opening a
database connection. The ceiling on the saving is under four percent of that two thousandths,
falling to under half a percent as the program grows — and the same measurement found the real cost,
quadratic behaviour in one lowering step, entirely unrelated.

Two structural blocks came with it: the memoised core is the type through which the whole internal
API passes, so replacing it is a rewrite of thousands of signatures; and the browser artifact
reaches it through the executor regardless of whether the database is built.

What would bring it back is a file with hundreds of mappings, or a check called in a loop inside a
long-lived process. The first is measured and points the wrong way. What is **not** measured is the
cost in bytes of the browser artifact, which would be a different argument from the one about time.
</Accordion>
<Accordion title="A subprocess as the embedding surface">
Measured on 2026-08-16: the product this surface was built for spawns no fossil binary anywhere, and
both of its images declare that they contain none — `run`, `refs`, `providers` and `check` all
execute in the browser. The verbs and their wire types outlived their only consumer, and while they
lived a second implementation of each grew beside them, which is how the serializer divergence got
in.

The subprocess is not wrong as a *transport*; it is wrong as the definition of what fossil offers.
</Accordion>
<Accordion title="A linked Rust type as the contract between fossil and a host">
The crate accumulates contracts that have nothing to do with each other — the run result, the
provider registry and the typed lineage arrived in one crate named for the first of them — and it
accumulates build machinery belonging to the consumer, which is how an optional schema-derive
feature whose own comment read "Host-only" came to live in a compiler crate.

Measured: of the three contracts, only the run result is referenced from the host's Rust at all; the
other two are consumed from TypeScript through the wasm package, so the linked crate carries two
contracts for a language that never links it. A linked type also pins the host to a tag — dropping
the feature means the host cannot bump past its pinned tag until it stops asking for it.
</Accordion>
</Accordions>
