## An expression is a function of one row

Everything a property, an identity or a predicate may say is a pure function of the single row in
scope. That is the whole of the design, and every other property on this page follows from it: an
expression terminates by construction, it has no state to carry between rows, and it compiles to
exactly one SQL expression.

<Callout title="Deliberately absent">
There are no programs. No recursion, no loops, no user-defined functions — the last of those is a
ruling and not an omission (`grammar.bnf, § NOT IN MVP`): polymorphism lives in the library, and the
user declares no functions.
</Callout>

## The forms, and the program that spells each

`HirExpr` has twelve variants (`crates/fossil-hir/src/lower.rs:252`) — the nine forms below, which
between them cover eleven, plus the bare-name column reference the surface is retiring. They are not
a wish-list: each is spelled by a program in `apps/docs/programs/`, compiled by the production path
rather than transcribed here.

| form | what it is for | spelled by |
| --- | --- | --- |
| interpolated string | the identity slot, and any text composed from a row | `shop`, region `identity` |
| qualified column reference | `User.email` — a column, named by the row it belongs to | `shop`, region `properties` |
| string, integer, float and boolean literals | a constant property | `expressions`, region `literals` |
| call | the value library, reached as `str.trim(x)` or as `x.trim()` | `expressions`, region `two-paths` |
| edge constructor | `Person(User.email)` — the `Person` whose identity is built from this email | `shop`, region `edge` |
| arithmetic | `Row.gross - Row.discount`, left-associative | `arithmetic` |
| comparison, `and`, `or` | a filter's predicate, and the condition of a conditional | `disjunction` |
| unary minus and `not` | negation in either position | `negation` |
| ternary | the conditional, both branches one type, no coercion | `ternary` |

The access operator is the dot and there is only one of it (`grammar.bnf, PostfixExpr`): what is on
the left decides what the members are — a namespace gives its functions, a type its fields, a value
its type's operations, a relation its verbs.

### One catalogue row, two ways to reach it

`str.lower(str.trim(x))` and `x.trim().lower()` are the same row read twice, not two ideas — the way
`s.len()` is `str::len(&s)` in Rust. The cost was accepted knowingly when the rule was taken: the
corpus contains both spellings, on purpose, so that the equivalence is demonstrated rather than
asserted.

<Program src="expressions/expressions.fossil" region="two-paths" title="expressions.fossil" />

The catalogue is 51 rows: thirteen relation verbs, three source constructors, and **35 functions an
expression may call**. Twenty-three of the 35 render on the DataFusion backend. The twelve that do
not are listed in `crates/fossil-df/src/stdlib.rs:85` with the cause beside each — five because
DataFusion has no way to raise from an expression, four because an aggregate is not a scalar call at
all, two because the function lives in an optional package this crate does not register, and one
because DataFusion ships no JSON extraction. A test renders every row's template and compares what
fails against that list, so a function becoming reachable — or stopping — is a diff there and not a
surprise in someone's program.

## The drop is loud, and that is the guarantee

This is the failure mode the whole project exists to prevent: the compiler declaring success and
writing a corpus with a property missing, no diagnostic at any stage. It happened. The lowering read
a handful of node kinds and dropped the rest, and the checker raised nothing because the HIR never
saw the expression.

The fallback arm is a diagnostic now — it quotes the source text, points at it, and names the node
kind the parser built. And what can still reach it has shrunk to one thing: every `*_EXPR` kind the
parser produces has an arm, so nothing a **well-formed parse** yields falls through, and what arrives
at the fallback is the parser's own `ERROR` node. In practice that is a retired spelling, which is
the commonest way to reach it while the surface is still being replaced.

`an_unlowerable_expression_is_a_diagnostic_and_not_a_silent_drop`
(`crates/fossil-hir/src/lower.rs:2840`) pins it, and it has outlived two fixtures: it was written
against `doble = .id * 2`, and both halves of why that was unlowerable have gone. Arithmetic has an
operator and lowers like every other binary expression
(`crates/fossil-hir/src/lower.rs:2885`); the leading `.` is not a form the parser reads. The test
survives because the guarantee it pins is the drop being **loud**, not the fixture being unlowerable.

<Callout title="Two claims a reader should not merge">
A call type-checks against the catalogue and writes its column —
`crates/fossil-df/tests/expressions.rs:42` asserts the values, not the plan. That a call *runs* is
not the same as every catalogued function running: see the twelve above.
</Callout>

## What leaves

**Anything the HIR does not need leaves the grammar.** A token that never reaches the HIR is a
promise the language does not keep, and the grammar used to make several. Four are gone as of
2026-08-08 — **partial application** (`f(_, x)`; `_` is now an ordinary identifier), **arrows**
(`->`), **type annotations on values** (`f :: String -> Iri`) and **`@export`**, which named an
export in a language with no module system to export to. Removing them was checked the only way it
can be: the workspace tests, and `fossil run examples/hello.fossil` writing a byte-identical corpus.

Seven more went on 2026-08-11, and the list is now short. **`$VAR`** and the **triple term**
(`<< s p o >>`, the pre-1.2 spelling — see [RDF 1.2](/docs/characteristics/rdf12)) left first.
Then: the **`in g`** named-graph clause, which the corpus has nowhere to put; the **`&` shape
intersection**, which was not merely unread but *lossy* — a header declaring two shapes type-checked
and emitted the first alone, because the lowering took one IRI and dropped
the rest with no diagnostic; the **annotation block** and the **record
literal** in value position, which went together because they were the two readings of one `{`;
`use` with its path, selective import and alias, which stay dead until there is a module system for
a name to come from; and `T_COLON`, which the grammar
declared as a terminal and the lexer never emitted — the ternary's `:` is the same `SHAPE_SEP`
the mapping header takes.

Two of the thirteen were not dead surface but **holes**, and both were fixed rather than deleted.
`PAREN_EXPR` had no arm, so `(Row.a and Row.b)` was refused by the fallback in a language that
already lowers `and` and `or` — grouping is not a form, so the arm unwraps to the expression inside.
`UNARY_EXPR` was the one that stayed open longest, because `not …` parsed with no `HirExpr` variant
to lower it to; adding one was a decision about the HIR rather than a missing arm, and it was taken.
`grammar.bnf, UnaryExpr` is the production, and `negation` is the program.

**`|>` left with them, and it is the one deletion a reader is most likely to have been told
otherwise.** `a |> f()` was a second spelling of `a.f()`, and with member resolution by receiver
type the pipeline operator had nothing left the dot could not do. It is not a token, there is no
pipeline node in the HIR, and the parser refuses the operator by name. The leading dot went the same
way: `.edad` named a column of an anonymous row, and the row has a name now, so a reference is
qualified — `User.edad`. Both are tombstones in `grammar.bnf`, which describes the language rather
than the parser's tolerance.

## What this does not settle

- **The bare name.** A property may still write `id` where it means `User.id`, and the lowering
  builds the anonymous-row form for it. That is two spellings for one idea, which this house does
  not keep; the sequence ends by deleting the variant, and until it does the surface in this tree is
  mid-move rather than finished.
- **The twelve functions the DataFusion backend cannot render.** Two of them —
  `anon.hash` and `str.split` — are one `SessionContext` registration away and nothing else; the
  other ten each need a decision, and four of them (`math.sum`, `avg`, `min`, `max`) are not scalar
  calls at all but [a pipeline with a group-by](/docs/characteristics/pipeline).
- **Where the value library is written down.** The catalogue is Rust today and is meant to become a
  file the compiler reads, so that adding a row stops touching the compiler at all. Nothing loads a
  file yet, and that is deliberate: what the catalogue owes a loader is a shape it can fill, not a
  parser it has to agree with.
