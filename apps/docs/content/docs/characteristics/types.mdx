## Why this is the core and not a feature

Fossil is RML with a type system. RML validates the graph **after** producing it, when the error
already costs a full regeneration over a source that may have millions of rows. Everything fossil
offers over RML is the part that happens before that.

So the type system is not a component. It is the thesis.

## Job one — the source

The descriptor says which fields exist and which primitive each carries. A `User.nombre_completo`
that is not in the source is an error in the editor, not a `NULL` in the corpus.

And this is where the expensive work is, which is easy to get backwards: **the programs are small and
the sources are large.** A fossil script is tens of lines; the CSV it points at is not. Going to the
source and inferring its schema is the only part of a compile that costs real time.

That is why it happens **before the compiler exists**, and since `fbd1102` it is not the compiler
doing it. `fossil-introspect` is the native host's half: `extract_source_refs`
(`crates/fossil-introspect/src/lib.rs:97`) scrapes the `io.` bindings out of the program text, and
`crates/fossil-introspect/src/lib.rs:267` runs `DESCRIBE SELECT * FROM <reader>(...)` — the reader
the constructor names, `read_csv_auto` / `read_json_auto` / `read_parquet` — and fills the host's
descriptor cache. `fossil-cli` calls it and then compiles, which is the order the browser has always
used. That is also why the cache is deliberately outside the query system: it is a function of the
world, not of the program text.

<Callout title="The cache exists since 2026-08-07, and its token is deliberately not a hash">
It was the least-built thing in the tree: the field that drove invalidation was `String::new()` at
every production site, its fallback hashed the *resulting columns* rather than the source, the key
was the binding name rather than the URI, and registering a descriptor panicked by default. All four
are closed.

The freshness token is **mtime + size from one `stat`** — not a content hash, because a hash reads
the whole source to decide whether to read the source, which is the one way a cache over large
sources can cost more than it saves. Its failure modes are stated rather than hidden: "changed when
it didn't" costs one redundant DESCRIBE and no wrong answer; "unchanged when it did" needs mtime
*and* size both preserved. A host with a strong `ETag` writes that instead, and one that cannot
cheaply tell writes `""`, which reads as *never fresh*.
</Callout>

## Job two — the shape is a contract

The output shape is the **target type**, and the checker proves that no mapping can violate it: a
property the shape does not declare, a broken cardinality, an incompatible primitive, an IRI of one
type where another is expected.

This is design principle D9 — *invisible types, total guarantees; if it compiles, it runs* — made
true.

**Three of those four are checked today, and what closed them was the document becoming an input.**
`resolve_target_shape` (`crates/fossil-hir/src/shapes.rs:535`) reads the document the program names
through the file registry and the tracked `shape_document`, and `typecheck_mapping` calls it
(`crates/fossil-hir/src/check.rs:128`). A key the shape does not declare is refused by
`resolve_predicate` with a did-you-mean over the ones it does
(`crates/fossil-hir/src/check.rs:480`); a value whose type the
constraint will not admit is refused by `compatible` (`crates/fossil-hir/src/check.rs:908`); and a
predicate the shape requires that the body never writes is refused by `check_required_properties`
(`crates/fossil-hir/src/check.rs:599`).
`apps/docs/programs/errors/wrong-type` is the third of the four spelled as a program, and
`editing_the_document_rechecks_the_program_and_the_diagnostic_changes`
(`crates/fossil-engine/src/documents.rs`) drives it through the production path: the shape declares
`xsd:integer`, the column is a string, the diagnostic names `Integer` as what was expected, and
editing the document to say `xsd:string` makes it go away.

<Callout title="The accept-all literal is still in the tree, and it is not on this path">
`OutputDescriptorKind::ACCEPT_ALL_DEFAULT` at `crates/fossil-engine/src/lib.rs:268` is the **run's**
fallback, not the checker's: one descriptor per program, resolved for the executor, and reached only
when a program names no shape document *and* carries no `io.rdf` `schema =` argument. Since a bare
property key resolves only against a predicate a shape declares, a program that reaches it writes no
property at all — the checker has already refused it. All twenty-three programs in
`apps/docs/programs/` name a document through a `type { … } := io.…("…")` binding, so nothing in the
conformance set reaches that line. The comment above it names a pure-`io.rdf` exception; that program
is gone, and the exception with it.
</Callout>

**What is not checked is the upper bound.** `compatible` took an `occurs` parameter and lost it
(`crates/fossil-hir/src/check.rs:922`), and the property loop says in its own comment why it does not
read `constraint.occurs` (`crates/fossil-hir/src/check.rs:451`), so the only cardinality the checker observes is a required
property that is absent. Nothing in the language constructs a multi-valued expression, so a
`maxCount 1` property has nothing to reject yet — the gap is real and is not currently reachable from
a program.

**Which schema language the shape is written in is settled, and it is neither.** A ShEx decoder and a
SHACL decoder lower into one format-neutral vocabulary and the checker reads that and nothing else;
the argument is on [the shapes page](/docs/design/shapes), and the variant that used to be called
`Shacl` is called `Lowered` for exactly that reason — it never meant SHACL, it meant the decode
already happened (`crates/fossil-descriptors-output/src/kind.rs:48`). The one asymmetry that survives
is about RDF 1.2 rather than about investment: SHACL 1.2 Core carries `sh:TripleTerm` as a node kind
and a reifier-shape constraint component, so it can describe an
[RDF 1.2](/docs/characteristics/rdf12) output, and ShEx has no working group and no mention of any of
it. That is a reason a document might be SHACL. It is not a reason the compiler should prefer one.

## Job three — sensitivity is a type

This one falls out of the other two, and it is what makes the type system pay for itself.

If the shape is a contract, the shape can declare that a property is sensitive. And then a raw value
is **not assignable to it**. A function from the `anon.*` family does not return the type of its
input; it returns a **pseudonym**, deterministic and keyed so that joins survive anonymisation, and
the pseudonym is the only thing that fits there.

<Callout title="What this buys">
Anonymisation stops being a function you can forget to call and becomes something the compiler will
not let you skip. That is *if it compiles, it runs* applied to privacy, and no mapping language
offers it.
</Callout>

The material is in the tree and, since `call` landed, reachable: `crates/fossil-hir/src/stdlib.rs`
catalogues `anon.hash` and `anon.redact` alongside the cleaning functions. What is missing is not the
plumbing but the type — see [the expression cliff](/docs/characteristics/expressions) for what a call
now does.

`anon.hmac` was catalogued beside them and is **deleted from the language**, with the reason kept at
the deletion site: HMAC needs a key schedule, DuckDB has `sha256` and no HMAC, and the only honest
renderings left were a native UDF (gone with `Udf`) or a function called `hmac` that is not one. The
keyed pseudonym that survives joins across a corpus is therefore an unbuilt capability rather than a
catalogued one, and it is the thing sensitivity-as-a-type will need before it means anything.

## The lattice, and the boundary it used to cross as text

Nine xsd-aligned primitives in one enum — `String`, `Integer`, `Float`, `Bool`, `Date`, `DateTime`,
`Time`, `GYear`, `AnyUri` (`crates/fossil-graph-schema/src/lib.rs:124`). It lives in the leaf crate
the schema, the checker and the descriptors all depend on, so a column crosses the provider boundary
carrying the enum itself (`crates/fossil-descriptors-input/src/inferred.rs:23`):

```rust
pub struct InferredColumn {
    pub name: SmolStr,
    pub primitive: Primitive,
}
```

**Until 2026-08-07 that field was a `SmolStr`,** and the lattice of the type system travelled across
its most important boundary as text with the invariant written in a comment. The cause was on the
record and it was not carelessness: it was made a string **on purpose**, to avoid a dependency
cycle against `fossil_hir::Primitive`. A dependency direction had untyped the core of the type
system, and it cost seven implementations of one table — two of them inside the same crate, one of
which existed only to assert that it agreed with another.

What is left is one function per direction, both on the lattice itself:
`Primitive::from_xsd_iri` (`crates/fossil-graph-schema/src/lib.rs:165`), which takes the full IRI,
the `xsd:` prefixed form and the bare local name; and `Primitive::to_xsd_iri`
(`crates/fossil-graph-schema/src/lib.rs:189`). Beside them stand two mappings that are not
duplicates but vocabularies a materializer owns: `primitive_to_graphar`
(`crates/fossil-hir/src/shapes.rs:498`) and `duckdb_type_to_fossil_primitive`, which went to the
host with the `DESCRIBE` (`crates/fossil-introspect/src/lib.rs:56`).

The `D-INFERRED-UNKNOWN-DATATYPE` diagnostic went with the string. A host that sends a type fossil
does not carry is now rejected where its JSON arrives, naming the value — not coerced to `String`
and reported three crates later as a complaint about a column.

<Callout title="Deliberately absent">
No user type annotations — types come from descriptors. No global inference: the check is
bidirectional and local to a mapping. There IS subtyping, and it is five rules wide — reflexivity,
lifting to `Optional`, covariance of `Optional` and of `Seq`, and `Integer <: Float`, all of them in
[the typing rules](/docs/book/typing).
`compatible` runs them on every property. This callout said "no subtyping" until 2026-08-08, which
described an intention rather than the checker. And the introspection of job one is **never** a query in the
incremental system; its cache is ours and its invalidation policy is explicit.
</Callout>

## What this does not settle

- **How sensitivity is declared in the shape.** SHACL has no constraint component for it, so it is a
  choice between our own annotation and an existing vocabulary.
- **Which freshness token the descriptor cache uses** — mtime, ETag, or a content hash.
- **What types a `join` condition.** The `on` predicate is checked for the existence of every column
  it names and for nothing else, so an `Integer` key equated with a `String` one compiles. It is not
  a hole in job two: it is on the source side of the checker, upstream of any shape, and it belongs
  to [the mapping algebra](/docs/design/algebra) rather than to the contract — see what a compile
  does not promise on [the typing page](/docs/design/types).
