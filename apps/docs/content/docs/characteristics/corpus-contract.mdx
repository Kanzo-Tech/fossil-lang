## Why a corpus needs a contract at all

A corpus is bytes on disk that outlive the process that wrote them, and it is read by code that was
not compiled against the code that wrote it. Dense ids, the Morton order, the CSR/CSC pair, the chunk
addressing — every one of those is arithmetic that a reader has to re-derive, and re-derivation is
where formats go wrong.

The decision about *how* that arithmetic ships was taken on the evidence of nine formats: Arrow,
Parquet, Iceberg, Delta, MVT, PMTiles, Zarr, GraphAr, and H3 against S2.

## The destination: four obligations, none optional

<Callout title="Decided, not built">
All four are `decisions/0045-dos-nucleos-un-monorepo.md`, the fourth of the decisions recorded in
its 2026-08-05 review. One of them has a first half on disk; the rest are a plan, and the section
below this one says exactly which.
</Callout>

### 1. The arithmetic publishes as Iceberg publishes it, not as PMTiles does

Iceberg specifies its bucket transform as Murmur3 x86 32-bit with seed 0 — the formula, the widths,
the sign — **and a table of vectors** by type, of which `34 → 2017239379` is one. Searching for that
constant finds it in the tests of independent implementations that copied it. PMTiles dispatches its
Hilbert curve with a link to Wikipedia, and every port re-derives it.

So `tile = dense_id >> 12` gets written with the width of the shift, the width of the integer, the
sign, and a table of vectors at the boundaries: 0, 4,095, 4,096, 2³¹−1, 2³¹, 2⁵³. **The vectors are
the deliverable**, because the vectors are what gets copied. They ship inside the corpus as Parquet,
so every layer reads them with what it already has.

### 2. 64-bit ids are `BigInt` at the TypeScript boundary, and `number` is a lint error

This is not precaution. `node-s2` was a **binding** — not a port, not a reimplementation — and it
returned wrong cell ids anyway, because JavaScript's `number` carries 53 bits and a cell id carries
64. **A binding does not protect a language boundary that cannot hold the value.**

H3 settled it by decree, typing `H3Index` as a string before anyone could get it wrong. We settle it
the same way: `BigInt` at the boundary, `number` forbidden for an id by lint rule. `>>` means three
different things across our three layers, and in JavaScript it coerces to 32 bits. What goes to the
GPU stays a typed array; what *identifies* does not.

### 3. Our TypeScript reader calls the same compiled Rust

Not a reimplementation. That is the H3 model, and it costs nothing here because the writer is already
Rust. H3 wins its comparison with S2 not because bindings are magic but because it has **one oracle
and almost nobody reimplements it** — zero divergence incidents across its ecosystem. S2 has four
oracles in a chain (`rust-s2` is a port of the Go one, `s2js` is "compatible with" the Go one: ports
of a port) and no shared vectors, with concrete divergences open for years.

Third parties — measured, they exist — get the specification and the vectors, which is the half a
wasm module cannot give them.

### 4. Conformance is round-trip, and it blocks the merge

Write with the writer; read with the wasm reader *and* with the TypeScript/DuckDB path; diff the
three. Arrow demands two implementations and integration tests **before** a format change lands,
which is why its gaps are enumerated `skip` lines rather than wrong answers. GraphAr ships a shared
corpus with no round trip, and through that gap its fourth implementation landed having re-derived
the path arithmetic differently from the other three *and* from the corpus on disk — green CI on both
sides, because its tests asserted hand-written strings instead of resolving against the artefact.

## What is true today

**One quarter of the fourth obligation exists**, and it is the half GraphAr specifically lacks.

`crates/fossil-engine/tests/conformance.rs` — `the_corpus_keeps_the_promises_it_makes_to_a_stranger`
— compiles a small mapping, runs it, and then opens the produced tree with **plain SQL over a fresh
DuckDB connection**. It never touches `fossil-graph`, `fossil-df` or any other reader of ours. That
is the entire point: a test that reads back through the writer's own types proves the types are
self-consistent and nothing else. It cannot see a promise the format makes to somebody who is not us.

Six invariants, each expressed as a count of violations:

| # | the promise |
| --- | --- |
| 1 | `dense_id` is a gapless `0..n` with no repeats — a tile is a range of dense ids, so a gap is an addressable empty tile or an unaddressable vertex |
| 2 | each adjacency file is ordered by the key its name claims — `by_source` is CSR, `by_target` is CSC |
| 3 | the two orientations carry the same edge set; they are one relation stored twice and nothing else in the writer says so |
| 4 | every endpoint addresses a vertex that exists — the corruption renumbering could introduce and no row count would reveal |
| 5 | `RunStatus` agrees with what was written, because a corpus disagreeing with its own status is undetectable from either side alone |
| 6 | the staged single-file vertex Parquet is gone, not left behind as a stale second copy a reader would glob up |

It gates merges in the ordinary way: `cargo test --workspace` runs on every pull request.

<Callout title="Checked for vacuity, and mutation-tested">
Every assertion is a count of violations, so **an empty corpus satisfies all six at once** — which is
exactly how a conformance suite comes to pass vacuously and stop being evidence. The fixture's row
counts are asserted first for that reason. And inverting the ordering predicate reports 299
violations over 300 rows, which is how the ordering check is known to measure the ordering rather
than pass by construction.
</Callout>

## The three-quarters that are not there

Said plainly, because the register matters more here than anywhere else on this site:

- **No test vector is published.** Not for `morton2`, not for chunk addressing. This is deliberate
  rather than pending: the same ADR put the Morton quantisation in motion (it may widen if flattened
  ids are adopted) and is retiring the chunk for a 4,096-row tile. **Vectors for an arithmetic that
  is about to change would be precisely wrong rather than honestly absent.**
- **`BigInt` at the TypeScript boundary is decided and not enforced.** There is no lint rule.
- **There is no second reader in this repository.** The validator is one writer read by one
  independent engine — not the three-way round trip obligation 4 asks for, because two of the three
  readers live in another repository. The cross-implementation half arrives with the tile reader.

<Callout type="warn" title="Two things that would invalidate the destination, and one clock">
A **second writer** — anyone producing our corpus without being our Rust — inverts the priority: the
specification becomes the contract and the library becomes one implementation among others. A single
writer is what makes the library-shaped half safe. Two writers is what turned Parquet into what it
is, with a reference implementation normative by accident and `created_by` parsed against tables of
known-bad versions.

And the clock runs one way. **If the corpus reaches third parties before the vectors do, the option
is gone.** Parquet's problem is thirteen years of files that can no longer be withdrawn. Nothing is
published today, which is what makes this cheap exactly once.
</Callout>
