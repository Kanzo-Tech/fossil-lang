## The question this answers

A source almost never arrives with the shape a mapping needs. Filtering, joining, grouping — that
work has to live somewhere, and there are three somewheres: outside fossil entirely, borrowed from
the engine through the source binding, or in the language.

**It lives in the language.** `|>` composes sources, and our checker types the result end to end,
which is the thing neither of the other two options gives.

## But the plan is DataFusion's

This is what makes the choice affordable, and it is easy to state backwards. **We do not need a
planner. We need a checker.**

The typed pipeline lowers to a DataFusion `LogicalPlan`, which already has predicate pushdown, join
reordering and a cost model. We supply what DataFusion does not have — the types of the mapping — and
borrow what it does.

Two consequences, and they have to be read together or the second reads as an amputation:

- **The fourteen MIR operators stay.** They are the pipeline's vocabulary, not an aspiration. This
  reverses the reading that the operator set was over-designed: it was never reached, which is a
  different problem with a different fix.
- **The ten rewrite rules go.**

<Callout title="Removing the rewrite rules is not giving up on optimisation">
It is giving up on optimising **twice**. `rewrite()` was not incomplete — it was competing with an
optimizer that sits underneath it, and losing by definition. What we can do that DataFusion cannot is
type the mapping; what it does better than we will is choose a plan.
</Callout>

## What is true today

**The ten rules are gone.** `rewrite()` ran on every compile and always returned its input, because
all ten matched operators the lowering never emits; `rewrite.rs` and the `eval.rs` that existed only
to drive R7–R10 left together, and `fossil run examples/hello.fossil` writes a byte-identical corpus
before and after. The lowering still emits four of fourteen operators: `Source`, `EmitVertex`,
`EmitEdge`, `Sink`.

**And the source pipeline is the other half, which closed the same day.** `adultos := users |>
where(.edad >= 18)` is a **relation**, not a value, and it needed three things that did not exist: a
source binding that is not an `io.*` call, `Op::Filter` reachable from source, and types for
`where`/`select`/`join`. All three are there. The opening question — whether `join` is in the first
version — is answered: **it is**, as an inner equi-join whose key is named once (ADR-0054).

The lowering now emits seven of fourteen: `Source`, `Filter`, `Project`, `Join`, `EmitVertex`,
`EmitEdge`, `Sink`. The checker gained its first two-input rule with them — `fila(izq) ⊎ fila(der)`
with the key identified and any other shared name refused — because a join is where an operator set
stops being a list and starts being an algebra.

There is one more mismatch worth recording because it is the shape of how the enum grew: the module
header of `crates/fossil-mir/src/op.rs:1` says *"the complete 11-operator typed set"*, the enum has
fourteen variants, and the list the header itself enumerates has twelve names. Three numbers, none
of them agreeing, in one file.

<Callout title="Deliberately absent">
**No planner of ours.** No cost model, no statistics, no join reordering. If any of that is ever
needed it arrives through DataFusion or it does not arrive.

**No operator the pipeline cannot express.** The enum stops growing speculatively; the gap between
fourteen, twelve and eleven above is what growing speculatively looks like from the inside.
</Callout>

## What this does not settle

- **How two keys with different names are joined.** `on = .k` is `USING (k)`: the column has to be
  called the same on both sides, so `pedidos.persona_id` against `personas.id` — the ordinary shape
  of a foreign key — cannot be written in v1. The extension is `on = .a == .b`, and it is declared
  rather than built because it first has to say which row each `.` names, and that is a qualified
  reference the language does not have.
- **The three join flavours that are not `Inner`.** They stay defined and unreachable. An outer join
  manufactures NULL, and [the shape](/docs/characteristics/types) has no way to declare a nullable
  property yet, so the one that arrives will arrive with that story and not before.
- **How a pipeline's type is reported in the editor.** A source binding today has a schema from a
  descriptor; a pipeline has a schema derived from one, and hover has to say something useful about
  the derived one.
