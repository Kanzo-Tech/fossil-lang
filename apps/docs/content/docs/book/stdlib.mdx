The catalogue, organised by **what is on the left of the dot**. That is how you look one up when you
are mid-line: you have a value, you want to know what you can do to it.

**Every table on this page is generated, and the prose between them is written.** The rows come out
of the catalogue the checker itself resolves a call against — `crates/fossil-hir/src/stdlib.rs` for
the functions, `catalogue.bnf` for the readers — through `cargo xtask catalogue`, which writes
`apps/docs/content/generated/stdlib.mdx`, which each section below pulls in. That division is the
whole point of the page: a sentence here can be wrong, and a row cannot be, because a row is not
written down twice.

<Callout title="What the hand-written tables cost">
They carried 58 distinct rows. Fifty-one of them existed. `seq.filter` had been renamed `where`,

nowhere in the repository but here — the page was their only existence. All 58 rendered
identically, so nothing about the page told you which seven to distrust.

## How to read this page

A **member of a type** is reachable two ways — through the value or through the type — and they are
the same function:

| through the value | through the type |
| --- | --- |
| `Contact.email.trim()` | `str.trim(Contact.email)` |
| `Adults.count()` | `seq.count(Adults)` |

A **member of a namespace** has only the one spelling, because a namespace is not a value:

| | |
| --- | --- |
| `parse.integer(Row.qty)` | and there is no `Row.qty.integer()` |
| `io.csv("data/users.csv")` | and there is nothing for `io` to be on the right of |

That is why the first column of a table below is sometimes a bare member and sometimes a dotted
name: it is the receiver that decides, and the table prints whichever spelling the row actually has.

In a signature, the first parameter is the receiver — `(text: String, start: Integer) -> String` is
what you call as `s.slice(start = 3)`. **Every parameter carries its name, and the name is
load-bearing**: it is what a named argument writes to reach that position (`grammar.bnf, NamedArg`),
so `str.replace(x, needle = "a", replacement = "b")` is a call and `from =` / `to =` is an error.

`Relation` is the receiver's own relation, with whatever rows it carries, and `Predicate` is a
condition over one of those rows. Neither is written more precisely than that because neither can
be: both depend on the receiver. Everywhere else the type is a scalar one, and where you expected a
polymorphic signature the catalogue is giving the scalar approximation it has today — see
[functions](/docs/book/functions).

The third column is **how the row compiles**: either a SQL expression with `%N` naming its
zero-based argument, or the operator of the algebra the row names. It is on the page because it is a
field of the row, read by the compiler and not restated for the reader.

## A relation

Everything here takes a relation and gives back a relation, so they chain.

<include>../../generated/stdlib.mdx#seq</include>

`where` filters. `select` narrows to the named fields. `join` takes an equality between qualified
references, or several joined by `and`, and does not flatten the rows — both are in scope after it.
`group_by` is consumed by `aggregate` and by nothing else.

`select` names one parameter because its columns are **names and not values**: the lowering reads
them off the syntax. The signature says what the verb takes of the algebra, which is the relation.

`seq` is the receiver, so `Adults.count()` and `seq.count(Adults)` are one row. There is no `filter`
— it is spelled `where`, so that the catalogue spells what the surface spells, and an IDE offering
the members of a relation cannot offer a word the language does not have.

Three of the thirteen reach the surface today: `where`, `select` and `join` are the ones
`crates/fossil-hir/src/lower.rs` lowers. The other ten are rows the checker knows and the lowering
does not yet handle; what the table gives them is that the day one is implemented, its arguments are
checked by the same code that checks `str.trim`'s.

## A string

The operations of `str`. Reachable through the value or through the type.

<include>../../generated/stdlib.mdx#str</include>

`slug` lowercases, replaces anything that is not a letter or a digit with `-`, and collapses runs of
them — the shape you want in an IRI. Its template is the one measured against the two Rust slug
implementations the tree used to carry, and `crates/fossil-hir/src/stdlib.rs` records which one it
reproduces exactly and which one it cannot reproduce at all.

`slice` counts from zero and takes a `start`. There is no `end` parameter and this page claimed one.

`concat` takes exactly two strings. The template notation has no variadic form, and there is no row
that needs one.

There is no `normalize_unicode`. `DuckDB` ships `nfc_normalize`, which is NFC and nothing else, so a
row advertising a `form` argument would have been a function that lies about three of the four
values it accepts; it was deleted from the language rather than quietly narrowed.

## A number

<include>../../generated/stdlib.mdx#math</include>

`math.sum`, `math.avg`, `math.min` and `math.max` are the four that go inside `aggregate`. Nothing
in the rows says so — the catalogue has no field for it, and the table above is the catalogue.

`math.round` takes no `digits` argument, and this page claimed one.

## `core` — the two that belong nowhere else

<include>../../generated/stdlib.mdx#core</include>

`core.lang("Bonjour", tag = "fr")` is a language-tagged literal. There is no `dir` argument and this
page claimed one.

A column the source declares as nullable is a `T?`, and a shape that requires a value will not take
one. `require` is how you say the value is there. Its signature reads `(value: String) -> String`
rather than `forall T. T? -> T` for the reason given above — the catalogue's types are scalar today
— and its lowering is the one template on the whole page that reads its argument twice.

## `validate` — text that has to look like something

Each one is meant to return its input unchanged when the input is well formed.

<include>../../generated/stdlib.mdx#validate</include>

Four of the five have exactly that shape — `CASE WHEN … THEN %0 ELSE error(…) END`, so the answer is
the value or an error and never a null, and a `NULL` input passes through untouched. Each of those
four templates was measured against the Rust function it replaced, and
`crates/fossil-hir/src/stdlib.rs` carries the hand corpus and the fuzz counts row by row.

`validate.regex` does not have that shape. It lowers to a bare `regexp_matches`, which answers
whether the pattern matched rather than giving the input back, so the row's declared return type and
its lowering disagree. That is a defect in the row; it is stated here because the third column is
the first thing on this page that made it visible.

## `anon` — text you do not want to publish

<include>../../generated/stdlib.mdx#anon</include>

`anon.hash` with a salt is the usual way to build an identity out of something you must not put in
an IRI, and `salt` is a parameter rather than a convenience: a hash of an email with no salt is a
rainbow-table lookup. There is no `algo` argument and this page claimed one — the row lowers to
`sha256`, and a choice of digest is a thing to add when something needs it, not a parameter to
describe first.

## `io` — the readers

These take nothing on the left, because they are what makes the thing.

<include>../../generated/stdlib.mdx#io</include>

This table is a different shape from the others because the datum is different. An `io.` row is a
name, the extensions it accepts and what it does with them — it carries no signature, because what a
call to it needs to know is that the name is a source and not a scalar expression. The rows live in
`catalogue.bnf`, which is also where each one's argument is written.

The first four read rows: one name, giving both a row type and a relation — see
[naming what you read](/docs/book/what-you-read). The last two read types and bind the output
contract — see [naming what you produce](/docs/book/what-you-produce).

`io.rdf` and `io.shacl` both accept `.ttl`, and that is not a conflict: the name decides.
`io.rdf("g.ttl")` reads rows out of a graph and `io.shacl("s.ttl")` reads types out of a shapes
graph. `io.shex` deliberately does not claim `.ttl`, which is the same rule read the other way —
`io.shex("catalogue.ttl")` is an error naming both the constructor and the extension.

There is no `io.sql` and no `io.http`. This page listed both, and nothing else in the repository ever
has.

The list is a list, not a grammar. A format that arrives later is a row in `catalogue.bnf` and
nothing else changes — including this page, which will show it without being edited.
