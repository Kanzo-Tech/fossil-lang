---
title: 'Reference: the command line'
description: Check a program, write a corpus, declare a memory budget, pass a credential, and ask a program what it reads.
---

`fossil` is one binary and it takes four subcommands — `check`, `run`, `refs` and `providers`. Every
one of them takes `--verbose` to raise the log level.

## `fossil check`

```bash
fossil check shop.fossil
```

Reads the program, the shape document it names and the sources it binds, and reports every
disagreement. Exits zero and prints `ok — no errors in shop.fossil` when there are none. It touches
no data beyond what it needs to know the columns, and writes no file.

This is the one to put in a pre-commit hook and in CI. It is also what your editor runs — see
[in your editor](/docs/book/editor).

## `fossil run`

```bash
fossil run shop.fossil --dest file:///tmp/shop
```

```
wrote 2 vertex type(s), 1 edge type(s) to file:///tmp/shop
```

Checks the program, then writes the corpus. There is no step in between and no artifact of fossil's
own to keep — the destination is the output.

| flag | |
| --- | --- |
| `--dest <url>` | where the corpus goes. Required. `file:///path`, `s3://bucket/prefix`, and the rest. |
| `--memory-gib <gib>` | the memory budget for the run. Fractions allowed. |
| `--creds-stdin` | read a JSON credentials payload from standard input. |
| `--output-json` | print the run's result as JSON instead of the summary line. |
| `--policy <path>` | the privacy policy this release is verified against. An error if the program binds one. |

### `--memory-gib`

```bash
fossil run shop.fossil --dest s3://corpus/shop --memory-gib 4
```

One number, and it bounds the whole run. Past it, work spills to disk rather than growing, so a
corpus larger than the machine takes longer instead of failing. Leave it off and the run is
unbounded, which is the right choice when you know the data fits and the wrong one when you are
guessing.

### `--creds-stdin`

```bash
cat creds.json | fossil run shop.fossil --dest s3://corpus/shop --creds-stdin
```

A secret on a command line is visible to every process on the host, and a secret in the environment
is inherited by every child. So credentials ride standard input, and there is no flag that takes one
as a value. The payload is JSON, keyed by the destination or source it belongs to; omit the flag for
local paths and public URLs.

### `--policy`, and the line a program writes instead

```bash
fossil run shop.fossil --dest file:///tmp/shop --policy people.jsonld
```

The document states a bound — a `k`, a set of quasi-identifiers, a suppression allowance — and the
run **refuses** rather than writing a corpus that misses it. Nothing partial is left behind: the
verification happens while the release is still a value.

A program can name its own instead, and this is the form to reach for:

```
policy := "people.jsonld"
```

Same document, same refusal, and the reference resolves the way every other one does — beside the
program, or through an `@conn` alias, or as a URL. What it buys is that nobody has to remember it.
A bound that lives in a flag lives in whatever invoked the run; a bound that lives in the program is
reviewed with the program.

**Giving both is an error.** They are not two spellings of one thing: the binding is how a producer
carries the obligation, `--policy` is how a recipient imposes one on a program they did not write.
Where they disagree there is no answer to prefer, so the run says so and stops.

Name neither and the corpus is sealed `privacy: undeclared`, which the summary line says out loud.
That is a claim on the artifact — *no bound was checked* — and not a claim that the data is public.

## `fossil refs`

```bash
fossil refs shop.fossil
```

```
Data	-	data/users.csv
Data	-	data/orders.csv
```

Lists the **data** a program reads — one line per distinct source path or URL, with the `@conn` alias
it hangs off or `-` for a direct path. It parses and stops: no data is opened, no credential is
needed. `refs` walks the source bindings, so what reaches the list is:

| the binding | on the list |
| --- | --- |
| `io.csv("data/users.csv")` and its siblings | yes, with the role `Data` |
| `type { … } := io.shex("shop.shex")` | no — a type binding is not a source binding |
| `policy := "people.jsonld"` | no — the policy is not read by the compiler, so it is not in the def-map `refs` walks |
| a `schema =` argument to a source constructor | yes, with the role `Schema` |

This is what to run when you want to know what data a program will touch before you let it touch
anything. `--output-json` gives the same list as JSON.

## `fossil providers`

```bash
fossil providers
```

Lists the readers under `io` — the source formats this binary can bind — with what each one accepts.
`--output-json` for the machine-readable form.

## Exit codes

| | |
| --- | --- |
| `0` | nothing was wrong |
| non-zero | at least one error diagnostic. The diagnostics are on standard error, the summary on standard output |

Which is what makes `fossil check` composable: put it in a pipeline and the pipeline stops.
