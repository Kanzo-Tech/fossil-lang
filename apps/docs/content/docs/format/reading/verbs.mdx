---
title: The six verbs
description: A closed enum over an already-written corpus. schema, read, expand, path, aggregate, execute_sql — and the camera is not among them, because it is addressed rather than queried.
---

Beside the corpus there is a read surface: **six verbs**, a closed set, with a JSON schema each and
SQL generation behind them. `crates/fossil-graph` is the whole of it, and the whole of it knows
nothing about the language, touches no filesystem, and declares exactly two ports — `ManifestSource`,
which fetches a manifest file by relative path, and `DuckExecutor`, which runs a query. "Knows
nothing about the language" is a build failure rather than a sentence: `apps/docs/content.test.ts`
reads the crate's `Cargo.toml` and requires its internal dependencies to be exactly
`["fossil-sinks"]`, so the graph core growing a second root turns the tree red — and so does the
last one disappearing, because that needs the claim rewritten too.

The verbs are a convenience over the corpus, not the contract. **The contract is the corpus.** A
browser, a notebook and a service are equal citizens because they read the same files, and a caller
that would rather write SQL is not doing anything second-class.

## The set

| verb | what it answers |
| --- | --- |
| `schema` | the manifest, and per-field statistics on request |
| `read` | rows of one vertex type, filtered, ordered and capped |
| `expand` | the neighbourhood of a set of vertices |
| `path` | the route between two vertices |
| `aggregate` | a bounded, constant-memory grouping |
| `execute_sql` | the escape hatch |

The wire form is identical for every transport — an MCP tool call, an HTTP body, a CLI subcommand:

```json
{ "verb": "read", "params": { "vertex_type": "Person", "where": "subject = '…'" } }
```

Adding a verb means a variant, a `Params`/`Result` pair and a snapshot test. Removing one is a
breaking change to every binding, which is the point of the set being closed rather than a registry.

## What each one takes

**`schema`** — optionally a `vertex_type` and a `field`. Without them it answers the type list with
counts and field names; with them it answers per-field statistics: datatype, distinct count, a role,
samples. What used to separate the cheap introspection calls from the expensive one is a parameter
now, not four verbs.

**`read`** — a `vertex_type`, an optional `where` predicate over that type's columns, an optional
order and a limit. It absorbed two verbs that were the same query with different defaults: reading
one vertex is `where: "subject = '…'"`, and a top-k is an order plus a limit. Rows come back as
opaque JSON objects, with `subject` riding along as the identity and the layout columns left out —
those are the tiles' business.

<Callout type="warn" title="`where` carries the authority of `execute_sql`">
`where` is SQL. A binding that gates the escape hatch behind a permission **must** gate this field
with the same permission: the two reach the same engine with the same reach. A surface that hides
`execute_sql` and leaves `where` open has not gated anything.
</Callout>

**`expand`** — a set of subject IRIs, a depth, an optional edge-name filter and a mode. `Into` is
the subgraph induced on the given set — only edges with both ends inside; `All` walks outward from
the frontier. Results carry a hop count from the origin set.

**`path`** — two endpoints and a hop cap. An empty result means no path within the cap, which is a
different statement from no path.

**`aggregate`** — a type, a `group_by`, an aggregation, an optional measure, an optional bin count
and a limit. Binning is grouping, so a histogram is `bins` on this verb rather than a verb beside
it.

**`execute_sql`** — SQL and a row cap; the result carries its column descriptors and whether it was
truncated. Text-to-SQL lives here. Bindings may hide it behind a permission flag, and one does.

## What is not a verb

**The camera.** Level-of-detail is not a filter — it reads a *different relation*, and a `WHERE`
cannot change which table it reads. A tile at aggregation level 3 holds super-nodes that do not
exist at level 0. So the camera computes a level and a set of tiles and asks for bytes, with no SQL
and no database on that path, and [Addressing](/docs/format/conventions/addressing) is where that lives.

When a filter has to change the picture, the algebra returns **ids** and the canvas applies them as
a mask over the tiles it already holds. One mechanism, not a second renderer.

**Selection.** It was a verb once and it always belonged to the client.

**Summarising a cluster, or answering with communities.** Both are a `read` over an aggregation
level.

<Callout title="A shape that is right, and a speed argument that is not available">
`expand{into}` is justified in the literature by the membership mask that Kùzu and Neo4j push down
inside the scan. Measured here, **DuckDB does not accept that class of pruning** — a range join
against the id set costs more than not pruning at all. The verb is a shape a caller wants; the
performance story behind it is not a story this engine tells.
</Callout>

## Eleven verbs left, and only four were deleted

The surface was seventeen. The reduction is mostly absorption rather than removal, and the
distinction matters to anyone who had a use for one of them:

- four became a parameter of `schema`;
- `histogram` became a parameter of `aggregate`; `top_k` and `get_vertex` became `read`;
- four never had an implementation, three of those were never verbs;
- `viewport` and `materialize_graph` went with nowhere to go, because the camera is addressed.
